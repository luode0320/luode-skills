# 修复验证模板

结论：{修复是否有效，一句话}；影响：{受影响的用户、角色或业务环节}；范围：{本次会验证的修复场景}；非范围：{明确不验证的场景}；变化：{修复后用户或业务可感知的变化}；完成标准：{可放行或驳回的可观察条件}；术语说明：无技术术语需要解释，或 {术语：它在本次问题中的作用}；验证状态：{当前验证进展、覆盖范围和依据}。

本模板不新建文档，只在已存在的 Bug 主文档末尾追加一节 `## 修复验证`，节内首段按上面同一口径写八字段白话开场。字段定义、填写要求与附录分层**唯一见** [白话文档与附录分层契约](../../artifact-delivery-gate-rules/references/plain-language-document-contract.md)。

## 追加结构

```markdown
## 修复验证

结论：{修复是否有效，一句话}；影响：{受影响的用户、角色或业务环节}；范围：{本次会验证的修复场景}；非范围：{明确不验证的场景}；变化：{修复后用户或业务可感知的变化}；完成标准：{可放行或驳回的可观察条件}；术语说明：无技术术语需要解释，或 {术语：它在本次问题中的作用}；验证状态：{当前验证进展、覆盖范围和依据}。
```

本阶段各字段写什么：

| 字段 | 本阶段写什么 |
|---|---|
| 结论 | 修复是否有效，一句话 |
| 影响 | 受影响的用户、角色或业务环节 |
| 范围 | 本次会验证的修复场景 |
| 非范围 | 明确不验证的场景 |
| 变化 | 修复后用户或业务可感知的变化 |
| 完成标准 | 可放行或驳回的可观察条件 |
| 术语说明 | 无技术术语时写「无技术术语需要解释」 |
| 验证状态 | 当前验证进展、覆盖范围和依据 |

## 本阶段必需内容

1. 缺陷名称与原始现象。
2. 修复目标。
3. 当前 Bug 主文档与关联测试目录。
4. 验证环境与样本。
5. 验证步骤。
6. 当前结论：通过 / 驳回 / 待补测。
7. 副作用与未覆盖项。
8. 必要后续动作（仅验证未通过、待补测、需回流修复或用户明确要求建议时填写；验证闭环且无必需动作时不写）。

上述内容写入本阶段追加的 `## 修复验证` 节及其文末附录，**不改写文档原有的 H1 开场段和既有附录**。

## 任务阻断收口

- 仅真实阻断时使用本节。
- 当关闭 Bug 所必需的验证无法继续且无替代验证，或修复后出现必须回改的问题时，按 `artifact-delivery-gate-rules/references/task-blocker-closure-contract.md` 完整填写 `BLK-*`、任务状态、阻断阶段、阻断依据与证据、已尝试与停止边界、影响、最多三步解决计划、恢复后重入点和去重键。
- 每一步解决计划必须明确责任方、前置条件、完成判据和 Bug 重验入口；同根因已有 `BLK-*` 时引用已有记录。
- `limited`、`not_applicable`、普通待补测和 P2/P3 风险不使用本节。

## 执行附录

- local 验证环境、样本、逐步操作、执行命令、观察结果、失败预期、清理和回滚。
- 受限验证的人工补验方式、执行人、时间和通过标准。

## 追踪附录

- Bug、修复任务、实施计划完成条件、测试和风格证据的双向追踪；来源、稳定标识、`TEST`/`STYLE` 证据定位和结论变更。
