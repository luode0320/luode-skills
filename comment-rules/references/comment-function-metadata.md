# 函数头元信息

- 每个新增或修改的函数、方法都必须补齐函数头注释，不允许只补方法体内注释。
- 元信息顺序固定为：`[参数]`、`[返回]`、`最近修改时间`。
- 当无参数或无返回时，仍按固定顺序保留对应行并写 `无`。
- `最近修改时间` 必须作为函数、方法注释块最后一行，格式为北京时间：`yyyy-MM-DD HH:mm:ss`。
- `最近修改时间` 行必须包含本次改动的一句话简单说明，要求简短、具体、可定位，如 `2026-09-09 14:20:00 新增, MoonPay 卖币独立接入`；不写“优化一下”“调整逻辑”这类空泛表述。这一行是**唯一**承载改动说明的位置，其余注释位置一律只写作用或目的。
- **`最近修改时间` 全函数只保留一行**：再次修改时覆盖该行，不得并列堆叠多行历史。需要追溯完整演进时看 `git log`，那才是历史的载体；函数头堆成变更日志会越读越长，且与当前实现无关的旧条目永远没人删。
- **函数头只描述当前实现**：改动的来龙去脉写进 `最近修改时间` 那一行的一句话简单说明里即可，不得在函数头另起段落叙述"原先怎样、为什么改、对比了什么"。判定方法：把函数头里每一句话对照当前代码，凡是只有"知道历史的人"才需要的句子，删。
- 即使函数、方法本体逻辑非常短，也不能省略函数头元信息。
- **签名固定的测试入口函数免写 `[参数]`/`[返回]`**：`func TestXxx(t *testing.T)`、`func BenchmarkXxx(b *testing.B)`、`func TestMain(m *testing.M)` 这类由测试框架规定签名、无返回值的函数，写 `[参数] t: 测试上下文` / `[返回] 无` 属于零信息噪声，正是本规则要反对的内容。它们的函数头只写：**这个用例验证什么、判据在防什么、有无副作用**（会写库/建单/发消息的必须写明）。被测辅助函数不属于此例外，仍按常规补齐。
- 函数、方法在本轮发生签名、流程、分支、返回值、关键调用任一变化时，必须更新 `最近修改时间`；纯格式化改动可不更新。

## 函数注释核对清单模板

最终收口前必须至少输出以下结构：

```text
函数注释核对清单：
- [通过/缺失] 文件: <path> | 函数: <name> | [参数]: 是/否 | [返回]: 是/否 | 最近修改时间: 是/否 | 一句话说明: 是/否
- [通过/缺失] 文件: <path> | 函数: <name> | [参数]: 是/否 | [返回]: 是/否 | 最近修改时间: 是/否 | 一句话说明: 是/否
```

若本轮不涉及函数/方法，必须输出：

```text
函数注释核对清单：
- 本轮函数位点: 0 个（仅常量/字段/SQL/配置变更）
```

## 补丁注释核对清单模板

当本轮在原有方法中新增或修改补丁逻辑时，最终收口前必须补充：

```text
补丁注释核对清单：
- [通过/缺失] 文件: <path> | 函数: <name> | 位点: <if/for/switch/return 等入口描述> | 作用/目的说明: 是/否
- [通过/缺失] 文件: <path> | 函数: <name> | 位点: <if/for/switch/return 等入口描述> | 作用/目的说明: 是/否
```

若本轮无补丁逻辑位点，必须输出：

```text
补丁注释核对清单：
- 本轮补丁位点: 0 个（无新增补丁分支/兜底/兼容逻辑）
```
