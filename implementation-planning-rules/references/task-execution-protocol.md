# 任务执行协议（状态标记 / 检查点 / 偏差 / 回滚 / 规模）

> 归属 owner：`implementation-planning-rules`。本文件是最小任务与实施周期的**执行期状态管理协议**，不产生独立自动触发入口。吸收来源：`conductor`（Google Conductor 的 Claude Code 移植版，Apache-2.0，市场 `codebuddy-plugins-official/external_plugins/conductor`，含 context-driven-development / track-management / workflow-patterns 三 skill）。与本地规则关系：`tdd-workflow.md` 管"单任务内红→绿→重构的测试节奏"，本文件管"任务/阶段的状态标记、检查点、偏差标注、语义回滚与规模量化"，二者互补不重复；`minimum-task-execution-contract.md` 的单任务内部状态机（Planned→InProgress→StyleReviewing→Accepted）与 ROLLBACK-* 字段完全保留，本文件的清单标记不替代状态机。

## 适用场景

- 实施计划已落盘，进入周期内最小任务逐个执行阶段，需要在 plan 文档内维护可追溯的执行状态。
- 任务清单需要显式区分"跳过 / 阻塞"而非仅"待办 / 完成"两种状态。
- 阶段完成时需要对产物做验证并留下可回滚的检查点记录。
- 实现与计划出现偏差时，需要在任务完成处就地标注偏差与理由。
- 需要按"实施周期 / 阶段 / 最小任务"粒度做 git 语义回滚。
- 任务拆分需要量化规模参照（多少任务算过大、多少算过小）。

## 任务状态标记协议

计划文档（实施总览 / 实施周期 / 任务卡）内的任务清单统一使用五态标记，禁止混用其他符号：

| 标记 | 含义 | 使用场景 |
| --- | --- | --- |
| `[ ]` | 待办 | 任务未开始 |
| `[~]` | 进行中 | 当前正在执行，同一时刻至多一个 `[~]` |
| `[x]` | 完成 | 已完成，**必须附带 commit SHA**（见下节） |
| `[-]` | 跳过 | 有意不执行，必须附理由（如"遗留迁移：不需要"） |
| `[!]` | 阻塞 | 等待依赖，必须附阻塞原因（如"等待 API key"） |

示例：

```markdown
- [x] **TASK-1.1** 搭建数据库 schema `abc1234`
- [~] **TASK-1.2** 实现用户模型
- [ ] **TASK-1.3** 补校验逻辑
- [!] **TASK-1.4** 集成鉴权服务（阻塞：等待 API key）
- [-] **TASK-1.5** 遗留迁移（跳过：不需要）
```

规则：

- 状态切换即时性：执行到哪一步就立即改标记，不允许批量后补。
- 阻塞不空转：任务 `[!]` 时检查同阶段其他任务能否先推进；阻塞原因与预期解除路径必须写明。
- 跳过不留坑：`[-]` 必须有理由，且与 `AC-*` 完成条件对照确认不构成验收缺口。
- 标记一致性校验（阶段收口时）：清单 `[x]` 的任务必须能在 git 历史中找到对应 SHA；`[!]`/`[-]` 的比例异常（如全部跳过）需复核计划质量。

## commit SHA 追踪

每个 `[x]` 完成的任务在计划文档内就地记录提交 SHA，作为可追溯性与语义回滚的锚点：

- 格式：`- [x] **TASK-1.1** <描述> \`<sha>\``
- 提交信息必须引用对应 `TASK-*` / `AC-*` 标识，保证"计划→提交→代码"双向可查。
- 阶段检查点额外在检查点表记录该阶段收口 SHA（见下节）。

## 阶段检查点机制（本地适配版）

> 外部 conductor 原版含"等待用户审批后才进入下一阶段"步骤。**本地上不吸收人工审批**：本地为零决策执行模型（强模型冻结决策、执行模型自动闭环），阶段放行按本地既有闸门（`artifact-delivery-gate-rules`、`skill-execution-compliance-gate-rules` 等）执行，不在阶段间引入额外人工等待。若任务本身已标记需要人工确认（如 `WAITING_DECISION` 类状态），仍按对应 Owner 规则处理。

每个阶段完成时执行检查点协议：

1. **验证**：跑该阶段全部验证点——真实测试命令、断言、覆盖率与 `AC-*` 对照；验证点必须来自实施计划，不临时新增。
2. **记录**：在计划文档的检查点表登记阶段收口 SHA（`git rev-parse HEAD` 或最后提交 SHA）、日期与状态。
3. **放行**：验证通过即进入下一阶段；验证失败按 `error-handling-rules` / `execution-failure-learning-rules` 处理，不得携带失败跨阶段。
4. **检查点用途**：语义回滚的恢复点、阶段评审的 diff 边界（`git diff <前阶段SHA>..<本阶段SHA>`）。

检查点表模板：

```markdown
| 阶段 | 检查点 SHA | 日期 | 状态 |
| --- | --- | --- | --- |
| 阶段 1 | def5678 | 2026-08-23 | verified |
| 阶段 2 |  |  | pending |
```

## 偏差标注格式

实现与计划出现偏差时，在任务完成处就地标注，禁止静默偏离：

```markdown
- [x] **TASK-2.1** 实现校验 `abc1234`
  - DEVIATION: 改用库替代手写逻辑
  - Reason: 边界情况处理更完备
  - Impact: 新增依赖 email-validator
```

偏差四类型与处理：

| 类型 | 场景 | 处理 |
| --- | --- | --- |
| 范围新增 | 实现中发现规格外需求 | 记入需求主文档为新需求；计划补任务；标注新增理由 |
| 范围缩减 | 功能被判定不必要 | 任务标 `[-]` 附理由；更新范围说明；保留决策依据 |
| 技术偏差 | 实现路径与计划不同 | 就地 DEVIATION 标注；变更依赖时同步技术栈记录 |
| 需求变更 | 需求理解在执行中变化 | 走 `requirement-change-rules` 专项；同步 `AC-*` 后重验证 |

分层边界：执行期偏差就地标注（本文件）；需求层面变更回写主文档（`requirement-change-rules`）。本文件不接管需求变更裁决。

## 按工作单元语义回滚

借助计划文档内的 SHA 锚点，git 回滚可按"实施周期 / 阶段 / 最小任务"粒度定位，而非只按时间或文件：

- **任务级**：`git revert <task-sha>`（对应单个 `[x]` 记录的 SHA）。
- **阶段级**：`git revert <前阶段检查点SHA>..<本阶段SHA>` 组合提交，回滚到阶段检查点。
- **周期级**：回滚整个实施周期的提交区间。
- 回滚后必须同步计划文档状态标记（`[x]`→`[ ]` 或标注回滚），保持清单与 git 状态一致。
- 本地 git 操作边界与安全要求（提交授权、回退检查）以 `git-collaboration-rules` 为唯一事实 Owner，本文件只提供"按计划单元定位"的映射，不改变 git 红线。

## 任务规模量化指南

实施计划的任务拆分参照以下规模区间（与本地"单任务 ≤5 文件"文件粒度互补，双重超界优先拆小）：

| 指标 | 合适 | 过大（触发拆分） | 过小（触发合并） |
| --- | --- | --- | --- |
| 阶段数 | 2-4 | >5 | 1 且任务 ≤2 |
| 任务数 | 8-20 | >25 | <几小时工作量 |
| 交付形态 | 单一可测试闭环 | 多个无关功能混入 | 无独立验证价值 |

过大处理：拆成多个独立周期/任务，边界清晰后再排顺序；过小处理：并入相关任务或作为子任务，不单独开周期。

## 实施前上下文校验

进入实施周期前先做一次轻量上下文校验（不替代 `pre-implementation-code-exploration.md` 的代码库探索，两者并行）：

1. 读当前上下文工件（`PROJECT_CURRENT.md` / 项目记忆四件套 / 需求主文档）。
2. 标注其中与本周期相关的过时信息（状态、依赖、范围、决策）。
3. 先提议更新再推进；上下文与计划冲突时按来源优先级（当前项目代码 > 最近对话 > 已有文档 > 旧记忆）裁决。
4. 校验结论记入阶段检查点表备注，避免"上下文已过时仍按旧计划执行"。

## git notes 可选增强（轻量）

完成任务提交时，可用 `git notes add -m "<摘要>"` 附加决策理由与文件清单（不污染提交信息正文）。可选，不强制；与本地"提交信息引用 AC-* / 测试文件"的要求兼容。git notes 未启用或团队不使用时跳过，不影响本协议其他条款。

## 与相邻文件的边界

- `tdd-workflow.md`：单任务内红→绿→重构节奏；本文件不重复 TDD 步骤。
- `minimum-task-execution-contract.md`：单任务内部状态机 + ROLLBACK-* 字段；本文件的清单标记/SHA 追踪是其外部可视化的配套约定，不改变其字段与状态机。
- `requirement-change-rules`：需求层面变更裁决；本文件只处理执行期偏差的就地标注。
- `git-collaboration-rules`：git 操作与授权边界唯一 Owner；本文件只提供按计划单元的 SHA 定位映射。
- `task-granularity-and-order.md`：依赖图 + 垂直切片拆分方法论；本文件补充量化规模参照，不改变拆分原则。
