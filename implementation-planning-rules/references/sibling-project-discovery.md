# 同级项目发现约定

## 目标

补齐“需要参考其他项目时，去哪里找那个项目”这一环。本文件只负责**定位**外部项目；定位完成后的登记字段、版本冻结和验证回指由同目录 [cross-session-plan-execution-contract.md](cross-session-plan-execution-contract.md) 的 `EXT-*` 外部项目代码引用契约承接，两者不互相替代。

## 工作区布局前提

多个项目并列存放在同一个父目录下（例如父目录 `D:/luode/` 下并列多个项目仓库）。父目录本身不是仓库、不是工作区根，也不承载业务代码，只作为兄弟项目的枚举范围。

当前项目根的父目录一层即为默认的兄弟项目搜索范围；不假设兄弟项目之间存在依赖、同构或统一技术栈。

## 发现顺序（硬约定，逐级停止）

按顺序判断，命中即停，不得跳级也不得叠加执行：

| 顺序 | 条件 | 动作 |
| --- | --- | --- |
| 1 | 用户已给出目标项目的绝对路径 | 直接使用该路径，不做任何扫描 |
| 2 | `PROJECT_MEMORY.md` 已有该项目的**已验证**兄弟项目条目 | 直接命中记忆中的绝对路径，不重新扫描父目录 |
| 3 | 前两级均未命中 | 只列出当前项目根的**父目录一层**目录名（不递归进入子目录），按项目名匹配 |
| 4 | 父目录一层无匹配 | **停下向用户确认**，不再自行扩大搜索 |

第 4 级的硬禁止：

- 禁止递归向上（祖父目录及以上）或向下（兄弟项目内部）做全盘搜索。
- 禁止凭项目名猜测路径，也禁止用“大概在这个位置”的推断路径继续执行。
- 禁止拿同名公共开源仓库、社区镜像或搜索结果顶替本地兄弟项目。
- 禁止把“找不到”静默处理成“该项目不存在”或“改用当前项目实现”。

## 候选项目识别

父目录一层按名称匹配到的目录，必须同时满足以下任一项才算合格候选：

- 具备仓库标志：存在 `.git/`。
- 具备项目标志文件：存在 `go.mod`、`package.json`、`pom.xml`、`build.gradle`、`Cargo.toml`、`pyproject.toml`、`project.godot` 等语言/框架级项目声明文件。

不满足上述任一项的目录（临时目录、归档目录、报表输出目录、压缩包解压残留等）不得作为候选。

匹配到多个候选时，必须列出全部候选及其判定依据，按名称相似度排序交用户裁决；不得自行选定其中一个继续执行。

## 只读边界

### 免确认

- 列举当前项目根的父目录一层目录名。
- 兄弟项目内的只读动作：读取 README、配置、代码、文档，以及 `git log`、`git show`、`git status` 等只读盘点命令。

### 默认只读 + 会话级写入授权（最高优先级，强制）

**默认口径：当前会话只能修改与本会话绑定的当前项目；兄弟项目的代码和文件默认只读。**

当任务确需写入兄弟项目时，走「会话级跨项目写入授权」通道：

- 授权请求必须写明：目标项目名称 + 绝对路径、授权范围（目标文件 / 符号 / 模块，或整个项目）、操作类型（文件写入、构建测试、依赖安装、Git 写操作）、目标项目当前分支与 commit（版本冻结）、改动意图、验证方式、回滚方案。
- 用户在当前轮显式确认后，生成会话级授权记录 `WRT-*`，本会话内对该兄弟项目 + 授权范围 + 操作类型持续有效。
- 授权记录留痕于当前项目 `PROJECT_CURRENT.md` 或在会话内明确声明；缺少目标绝对路径、授权范围或操作类型任一项时不得授权、不得写入。

授权生效后，在授权范围内允许对兄弟项目执行：文件写入 / 创建 / 删除 / 重命名、命令执行 / 构建 / 测试 / 依赖安装、Git 提交 / 推送。

授权失效条件：会话结束、用户撤销、目标项目或范围超出授权、版本冻结值漂移；失效后回到默认只读，须重新申请。

授权不覆盖的独立红线（仍按各章执行）：`local` 本地连接调试测试红线、凭据不回显、个人文件安全与删除保护。

违反本条视为最高级别流程违规。

### 未获授权时的唯一出口

未取得授权、或授权已失效时，确实需要修改兄弟项目，当前会话只允许产出**改动计划**，不允许落地：

- 输出目标项目绝对路径、目标文件/符号、改动意图、建议改法和验证方式，必要时给出 patch 文本或代码片段供人工采用。
- 明确交接给“绑定该项目的会话”执行：由用户在该项目目录下新开会话，按计划实施。
- 计划本身写入当前项目的文档产物或直接回复用户，不得写入兄弟项目目录。
- 不得以“已经写好了计划，顺手落地更省事”为由跨项目落盘。

### 不继承环境授权

读取兄弟项目不等于获得它的运行环境授权。本地连接红线仍以**当前项目**的 `local` 配置为准；不得使用兄弟项目的配置去连接数据库、缓存、消息队列或上下游服务，也不得启动兄弟项目的服务来补证据。

### 凭据边界

兄弟项目中的 API key、token、密码、私钥、连接串原值不得回显到日志、测试证据、执行记录或面向用户的回复中。

## 与 `EXT-*` 的衔接

发现结果必须转写为 `EXT-*` 表格的字段，不能停留在“已经找到了”的口头结论：

- **外部项目地址**：写盘符加完整绝对路径并统一使用 `/` 分隔，例如 `D:/luode/other-project`；WSL 项目写 `/home/<user>/<project>`。仅写项目名、相对路径或“父目录下那个项目”不合格。
- **版本 / 提交**：按既有契约补齐 commit / tag / 分支加时间，或写明 `未固定 + 原因 + 复核命令`。
- **项目根相对路径、文件 / 符号、引用用途、许可证 / 复制边界、可达性与验证**：全部按 `cross-session-plan-execution-contract.md` 的字段要求填写。

发现过程本身不构成登记；缺任一 `EXT-*` 字段时，涉及该引用的任务和正式计划均不放行。

## 记忆回写

经过真实读取验证的兄弟项目，按 `project-memory-rules` 的写入规则回写 `PROJECT_MEMORY.md`，供下次直接命中发现顺序第 2 级：记录父目录绝对路径，以及“项目名 → 绝对路径 → 用途”的兄弟项目清单。

未真实读取验证的路径不写；被证明无关或已失效的项目路径标记为废弃，避免后续重复误查。
