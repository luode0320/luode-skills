# 跨会话计划独立执行契约

## 目标

正式计划必须能够脱离当前会话、当前模型和上一轮上下文，直接交给新会话执行。计划正文不能依赖“思考中已经说明”“见上文”“当前工作目录默认正确”或执行者自行补齐的默认值。

## 计划级自包含字段

正式计划必须冻结以下事实；无法确认时只能写 `N/A + 原因 + 证据`，如果该事实会影响执行则必须转为受限 / 阻断计划：

- 主项目身份：项目名称、可识别根目录地址、仓库类型、代码基线（提交号；无提交号时写可验证的文件指纹）。
- 执行入口：新会话拿到计划后的第一步、当前应执行的 `CYCLE-*` / `TASK-*`、恢复前必须读取的文件和必须核验的中断点。
- 环境契约：操作系统、运行时版本、依赖安装入口、允许的 `local` 配置来源、服务启动入口和禁止使用的环境。
- 决策冻结：技术方案、目录/文件/符号、输入输出、异常边界、权限/兼容边界、测试样本、断言、清理、回滚、停止条件和最大推进边界。
- 追踪闭环：每一项 `SRC`、`DEC`、`REQ/RULE`、`AC`、`CYCLE`、`TASK`、文件/符号、`TEST`、`EVIDENCE` 都能双向回指。

上述信息必须出现在计划正文或末尾执行/追踪附录中，不能只存在于当前对话、悬浮窗 projection、模型隐含推理或未引用的旁路文档中。悬浮窗只用于进度观察，不能替代正式计划源。

## 外部项目代码引用契约

只要任务需要读取、复制、对照、调用或修改其他项目的代码，计划必须建立“外部项目代码引用清单”，每个引用使用唯一 `EXT-*` 标识，并同时填写：

| 字段 | 要求 |
| --- | --- |
| 外部项目名称 | 写完整项目名，不得只写“另一个项目”或“旧项目” |
| 外部项目地址 | 至少提供一个可复现地址：本机项目根绝对路径、仓库 URL 或两者；仅写项目名、相对路径或当前会话可见路径不合格。只知道项目名、不知道路径时，按 [sibling-project-discovery.md](sibling-project-discovery.md) 的发现顺序定位后再填写 |
| 版本 / 提交 | 写 commit、tag、分支加时间，或明确 `未固定 + 原因 + 复核命令`；不得让执行者自行选择版本 |
| 项目根与代码路径 | 写从外部项目根计算的相对路径，禁止把当前项目相对路径冒充外部路径 |
| 文件 / 符号 | 精确到文件、包/模块、类/函数/字段或配置键 |
| 引用用途 | 说明复制、对照、调用、迁移或兼容的具体目的 |
| 许可证 / 复制边界 | 写许可证来源和允许的复制范围；未知时阻断复制行为 |
| 可达性与验证 | 写新会话如何检查地址、版本、文件和符号，以及失败时的停止条件 |

地址不得包含 token、密码、私钥、连接串或其它敏感值。Windows 本机路径使用盘符加完整绝对路径并统一使用 `/`，例如 `F:/other-project`；跨平台计划同时给出仓库 URL 或明确的路径映射。仓库 URL 必须指向实际仓库或官方镜像，不得写搜索页、泛化组织首页或不可定位的短链接。

每个 `EXT-*` 必须在追踪附录回指使用它的 `TASK-*`，并由对应 `TEST-*` 或 `EVIDENCE-*` 验证；缺地址、版本、代码落点、用途或验证任一项，涉及该引用的任务和正式计划均不放行。没有外部项目代码引用时必须写：`外部项目代码引用：N/A + 原因 + 证据（本计划只读取当前项目代码，已对当前项目根目录完成检索）`。

## 新会话交接检查

新会话接手计划时，必须按以下顺序执行：

1. 读取计划正文、执行附录和追踪附录，确认主项目地址、基线、当前周期和当前任务。
2. 按主项目地址进入正确工作树，核对基线与计划中的目录树；地址、版本或文件指纹不一致时停止。
3. 若存在 `EXT-*`，逐项检查外部项目地址、版本、代码路径和符号；任何一项不可达或不一致时停止，不得自行寻找替代项目。
4. 读取计划列出的 local 环境和依赖入口，运行计划指定的前置检查，确认断言、清理和回滚动作可执行。
5. 只从当前周期的第一个未完成 `TASK-*` 进入实现；先核验 `in_progress` 中断点，再按“实现 -> 真实测试 -> 6-review”闭环。

新会话无法完成上述检查时，状态必须为 `受限` 或 `阻断`，不得把缺失信息写成假设并继续执行。
