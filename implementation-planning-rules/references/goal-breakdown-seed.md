# 目标拆解种子（goal-breakdown-seed）

> 归属 owner：`implementation-planning-rules`。本文件为「来源对象仍是模糊大目标、尚未达到条件闸门收敛」时的轻量拆解入口；方法论吸收自外部 skill `dw-goal-breakdown`（v1.0.0，Dream，MIT，SkillHub）。倒推法方法本体（澄清目标与 deadline → 拆 3 层动作 → 标出首个最小可行步）的单一权威在 `../../long-run-loop-rules/references/goal-breakdown-before-loop.md`，本文件只定义工程域的使用时机与衔接，不重复方法步骤。

## 触发场景

用户问"这件事怎么做 / 怎么实现 / 先给计划 / 先出方案"，但来源对象仍是模糊大目标（如"把技能体系做得更好""半年内转行做开发"）——尚未满足本 skill 正式触发的条件闸门（来源边界与前置验收未收敛）时，先做轻量拆解，不直接套正式实施文档模板。

## 产物与衔接（工程域专属）

- **产物形态**：目标可衡量化 + deadline + 3 层动作（周→日，长周期先补月）+ 首个最小可行步（默认 10 分钟内可启动）。具体步骤按 `../../long-run-loop-rules/references/goal-breakdown-before-loop.md` 的倒推法执行。
- **种子性质**：拆解产物是**种子**，不是正式实施文档；来源对象经拆解收敛边界后，仍须走本 skill 正式流程（实施总览 → 实施周期 → 最小任务闭环）。
- **最小步下沉**：首个最小可行步自然成为第一个最小任务的首步——任何实施计划的第一个任务都必须能在短时间（默认 10 分钟）内启动，防止"大目标激动一下就忘了"。
- **域路由**：用户表达 goal 意图（如"建个 goal 跑这个目标"）时转 `long-run-loop-rules` 主流程（其 before-loop 负责 goal objective 输入）；本文件只服务工程计划入口。
- **边界**：不代替 `requirement-splitting-rules` 的业务切片；不代编工期与负责人。

## 示例

用户"我想半年内转行做开发" → 可衡量化：6 个月内完成入门课 + 2 个可展示项目；拆解：季度学基础 / 月做项目 / 周刷题；首个最小可行步：今天选一门入门课（10 分钟）。
