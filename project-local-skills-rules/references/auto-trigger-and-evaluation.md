# 自动触发与价值评估细则

> 吸收自外部 skill-autosave（触发条件/价值评估），裁剪为「聚焦项目写操作」的项目级形态。

## 触发前提（缺一不可）

1. **本轮涉及项目仓库写操作**：代码 / 文档 / 配置 / 测试文件有新增或修改（不改变可执行行为的纯读任务不触发）。
2. **满足以下任一沉淀条件**：
   - 使用了 **5+ 次 tool call** 的非平凡任务（多次检索、多步实现、跨文件改动）。
   - 遇到错误后找到了正确解法（含绕过的坑、环境陷阱、API 变更适配）。
   - 用户纠正了方法，学到了新做法（约定、命名、流程、取舍）。
   - 发现了可复用的多步骤 workflow（下次遇到同类任务可直接复用）。

## 价值评估门槛（不沉淀的情况）

- 一次性简单任务（1-3 步即完成、无新知识）。
- 用户明确说不需要沉淀。
- 纯聊天 / 闲聊 / 仅提问无产出。
- 无项目写操作（只读盘点、检索、咨询）。
- 经验已被现有 skill 覆盖（查重后无增量，见 `dedup-and-update.md`）。

## 四类典型沉淀场景样例

| 场景 prompt（示例） | 判定 | 理由 |
|---|---|---|
| 「刚修完订单状态机 bug，是 goroutine 泄漏，排查了很久」 | 命中（自动通道） | 踩坑 + 解法 + 项目写操作 |
| 「帮我把这个项目的数据库查询规范沉淀成 skill」 | 命中（主动通道） | 用户点名 |
| 「给这个接口加个重试参数」 | 评估后可不沉淀 | 单次小改、无新知识 |
| 「查一下这个依赖的版本」 | 不沉淀 | 无写操作、纯检索 |

## 收口检查时机

- 任务收口（最终回复前）对照本表走一遍；命中则按主流程「查重 → 创建/更新 → 登记」执行。
- 不命中则无需动作，不必为形式化而沉淀。
