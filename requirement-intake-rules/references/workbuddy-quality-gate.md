# 需求 100 分质量门

> 本参考吸收 WorkBuddy 官方 `requirements-pilot` 的质量评分思想，但不复制整套流程。质量门只作为需求接入的达标线，不改变实施规划的零决策计划。

## 评分维度与满分

| 维度 | 满分 | 判分要点 |
| --- | ---: | --- |
| 功能清晰 | 30 | 输入、输出、用户交互、成功标准是否明确 |
| 技术具体 | 25 | 集成点、技术约束、性能要求是否具体 |
| 实现完整 | 25 | 边界、错误处理、数据校验是否完整 |
| 业务上下文 | 20 | 用户价值、优先级、范围是否清楚 |
| 合计 | 100 | 达到 90 分才允许移交实施规划 |

## 门禁行为

- 低于 90 分：进入澄清与补缺口，一次只推进一个真实关键缺口。
- 达到 90 分：形成需求主文档质量摘要，允许移交 `implementation-planning-rules`。
- 无法补齐时进入 `gap-routing`，禁止 Agent 猜测或把未确认方向写成已确认结论。

## 与现有需求流程的整合

- 质量门不替代 `requirement-intake-rules` 的初始侦察、缺口路由、边界、拆分和变更专项。
- 质量评分结果记录在需求主文档，不单独创建“评分报告”文档。
- 90 分门禁不替代实施规划的 `AC-*` 完成条件，两者是先后两道门。
