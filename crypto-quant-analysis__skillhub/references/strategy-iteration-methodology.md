# 策略迭代方法论

> 本文件吸收了 `wm-backtest`（winmale 量化回测平台 skill）的策略迭代与结果归因方法论精华，适配到 Python 加密货币回测语境。

## 核心思想

**历史回测 = 用过去数据验证逻辑与参数，做成败归因，小步迭代。**
复盘最专业的数据源是**执行历史（ledger/持仓明细）+ 执行过程日志（trace/因子暴露）**，不是只看总收益。结论不构成投资建议。

## 迭代闭环

```text
基线 → 假设（只改一类）→ 预览 → 回测 → 拉执行历史 + 过程日志
  → 成败归因 → 1～3 条改法 → 再跑
```

| 环节 | 做什么 | 输出 |
|------|--------|------|
| 基线 | 当前策略的完整指标（收益/夏普/回撤/胜率） | 基线报告 |
| 假设 | 选一个变量或逻辑改动，陈述预期 | 可证伪的假设（If X then Y） |
| 预览 | 确认参数/时间窗口/标的范围 | 确认后的回测配置 |
| 回测 | 执行历史模拟 | 策略绩效指标 |
| 拉执行历史+日志 | 读取持仓明细、交易记录、因子暴露 | 执行痕迹 |
| 归因 | 分析赚/亏的根本原因 | 归因分析 |
| 改法 | 1～3 条可再跑改进方向 | 下一轮假设 |

## 一次只改一类

**这是最关键的纪律。** 同时改多个变量（如既改入场条件又改止损参数）会导致无法归因——赚了不知道是哪个改对了，亏了不知道是哪个改错了。

正确做法：
- 每轮只改一个参数或一段逻辑
- 陈述预期："如果我把 RSI 入场阈值从 30 改为 25，预期会减少假信号但可能错过部分反弹"
- 跑完复盘验证该假设是否成立
- 成立则保留，不成立则回退，进入下一轮

## 结果分层解读

不要只看总收益。分层拉取数据：

| 层级 | 数据 | 回答什么问题 |
|------|------|------------|
| **L0 摘要** | 总收益率、年化收益、夏普比率、最大回撤、胜率、交易次数 | 策略整体表现如何？ |
| **L1 执行历史** | 持仓明细（ledger）、权益曲线（equity）、持仓快照（holdings） | 什么时候赚/亏的？哪个标的贡献最大？ |
| **L2 过程日志** | 因子暴露（factors）、交易日志（trace） | 规则是否按预期触发？哪些因子主导了收益？ |

### 实际做法

1. 先看 L0 摘要——判断策略是否值得进一步分析
2. 如果收益为正但夏普偏低 → 看 L1 权益曲线，找大幅回撤时段
3. 如果回撤集中在某标的 → 看 L2 因子暴露，查该标的的入场/出场决策
4. 如果规则未触发 → 回看该标的是否满足条件，调整逻辑

## 关键分支必须打点

策略执行过程中，关键决策点必须有日志输出，否则无法证明规则是否真的触发了。

在 Python 回测脚本中，建议在以下位置添加结构化日志：

```python
# 收盘时记录
log_entry = {
    "step": "selector",        # 阶段：selector/trading/risk
    "code": "XS_TRACE",        # 事件类型
    "symbol": symbol,
    "reason": "pe_filter",     # 具体原因
    "detail": {"pe": pe_value, "threshold": 15}
}
trace_log.append(log_entry)
```

**必须打点的关键分支：**

| 阶段 | 需要打点的位置 | 示例 |
|------|--------------|------|
| 选股（selector） | 每个标的入选/剔除原因 | `"symbol": "BTC", "reason": "pe_gt_15", "action": "reject"` |
| 交易（trading） | 每个入场/出场决策 | `"symbol": "ETH", "action": "buy", "weight": 0.25` |
| 风控（risk） | 每次风控裁剪/否决 | `"symbol": "SOL", "action": "risk_reject", "reason": "drawdown_exceed"` |

**原则**：归因依赖日志。仅 return 指标不记录中间决策过程，就无法回答"为什么这个策略在某个时段表现差"。

## 归因分析框架

### 归因四问

1. **收益来自哪里？** 是少数标的贡献了大部分收益（集中度风险），还是分散持有？
2. **回撤发生在什么时候？** 回撤与市场整体下跌同步（系统性），还是独立于市场的策略缺陷？
3. **规则是否按预期触发？** 入场信号是否在正确时机出现？出场规则是否过早/过晚触发？
4. **参数敏感度如何？** 稍微改变参数，结果是否大幅变化？如果是，策略不稳定。

### 归因模板

```
## 回测归因分析

### 总览
- 总收益: XX%
- 夏普比率: X.XX
- 最大回撤: -XX%
- 交易次数: XX

### 收益分解
- 收益 Top 3 标的: XXX (+XX%) / XXX (+XX%) / XXX (+XX%)
- 亏损 Top 3 标的: XXX (-XX%) / XXX (-XX%) / XXX (-XX%)
- 集中度: Top 3 占总收益 XX%

### 时间序列分析
- 最大回撤区间: YYYY-MM-DD ~ YYYY-MM-DD
- 回撤期间市场状态: 下跌/震荡/上涨
- 回撤原因: [系统性/策略缺陷/特定标的]

### 规则触发分析
- 入场信号触发次数: XX (预期触发 XX)
- 出场信号触发次数: XX (预期触发 XX)
- 风控触发次数: XX

### 参数敏感度
- 关键参数 X 在 ±10% 范围内: 收益变化 XX%
- 稳定性判断: [稳定/敏感/不稳定]

### 下一轮改法（1～3 条）
1. [改法一] 预期效果: ...
2. [改法二] 预期效果: ...
3. [改法三] 预期效果: ...
```

## 自然语言→回测工作流

从用户描述到回测执行的完整闭环：

```
用户说: "PE<15 买入、浮盈10%卖，近3年"
  → 自动识别: 选股条件(PE<15) + 交易规则(浮盈10%止盈) + 时间窗口(近3年)
  → 预览给用户确认: "我理解的是: 沪深300成分股中PE<15的买入，持仓浮盈10%卖出，近3年。对吗？"
  → 用户确认后执行回测
  → 输出: 收益/夏普/回撤 + 归因分析 + 指出偏差 + 1～3条改法建议
```

**关键规则**：
- 未确认前禁止直接发起回测（避免误操作）
- 回测结果必须附带解读（用户不是看数字，而是看结论）
- 偏差必须明确指出（数据偏差/逻辑偏差/参数偏差）
- 下一轮改法必须有具体方向和预期效果描述
