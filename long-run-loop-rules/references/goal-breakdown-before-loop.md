# 目标拆解前置（goal-breakdown-before-loop）

> 归属 owner：`long-run-loop-rules`。本文件为「显式 goal 意图触发但目标模糊」时的拆解前置步骤；吸收自外部 skill `dw-goal-breakdown`（v1.0.0，作者 Dream，MIT，SkillHub）。拆解产物是 goal objective 的输入，不是循环执行本身。

## 触发场景

路径 B（显式 goal 意图）命中后，若目标仍为模糊大目标——无法直接写出完成标记、无法直接判定"完成"边界（如"我想半年内转行做开发""把技能体系做得更好"），必须先走本前置，不得跳过拆解直接创建 goal 或进入循环。

## 倒推法三步（强制顺序）

1. **澄清目标与 deadline**：把目标改写成可衡量结果（做什么、做到什么程度、何时完成）；用户未给 deadline 时先询问，不得代编。
2. **倒推拆 3 层动作**：从 deadline 倒推，逐层拆为 周动作 → 日动作（目标跨年/半年时先补月层，即 月→周→日）。每层动作必须可执行、可验证，禁止空泛占位词。
3. **标出首个最小可行步**：给出今天就能启动的最小动作，默认必须 10 分钟内可启动；该动作是拆解产物中唯一"现在就能做"的入口。

## 输出与主流程衔接

- 拆解产物（目标 + deadline + 3 层动作 + 首个最小可行步）写入 goal objective 后，按 SKILL.md 主流程继续（解析完成标记 → 进入循环）。
- 首个最小可行步作为第一轮 worker 的启动任务；若目标极简（已可直接写完成标记），本前置可省略。
- 示例（来自外部源，改写为本地口径）：用户"我想半年内转行做开发" → 目标可衡量化：6 个月内完成入门课 + 2 个可展示项目；拆解：季度学基础 / 月做项目 / 周刷题；首个最小可行步：今天选一门入门课（10 分钟内可完成）。

## 边界

- 本前置只负责"目标 → 可执行拆解"，不负责工程级实施计划（转交 `implementation-planning-rules`）、不负责需求业务切片（转交 `requirement-splitting-rules`）。
- 不代编 deadline、不承诺工期、不凭空指定负责人。
