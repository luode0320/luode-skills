#### Vyper 审查原则
> 精准优先于召回：只报告可能导致资金损失、会计错误或可达路径上的安全漏洞的问题。Vyper 语法和语义在 0.4 版本有重大变化——0.3.x 使用 `@nonreentrant("key")` 和普通方法语法调用外部合约，0.4.x 使用裸 `@nonreentrant` 并需要 `extcall`/`staticcall` 关键字——因此在应用任何版本特定规则前请读取 `# pragma version`。不要引入 Solidity 惯用模式：Vyper 没有继承、没有内联汇编、没有递归、没有无界循环，算术默认检查。

#### 正确性
- 重入保护的正确使用
- 整数运算安全（Vyper 默认检查但仍需注意）
- 状态变量的访问控制
- 外部调用的返回值处理

#### 安全
- 未受保护的函数（缺少 `@payable`、`@nonreentrant` 等修饰符）
- 时间戳/区块号依赖的潜在操纵
- 不安全的接口实现
