#### 明显的拼写或拼写错误
- 变量名、函数名、组件名或 Props 属性名中的拼写错误
- 日志或错误消息中包含影响可读性的拼写错误的字符串

#### 死代码
- 永远不会执行的代码块（例如条件始终为 false 的分支、return 语句后的代码）
- 已声明但从未读取或引用的变量
- 大块被注释掉的代码（没有明显的保留意图）

#### 代码质量检查
- **重复代码**：检查可提取的公共逻辑
- **代码注释**：复杂业务逻辑应有清晰解释性注释（避免注释显而易见的代码）
- **硬编码**：禁止业务相关的硬编码字符串，特别是 URL 路径和业务数值；简单的 UI 文本可放宽
- **变量声明**：严格禁止使用 `var`；使用 `let` 或 `const`
- **相等比较**：禁止使用 `==` 和 `!=`；使用严格相等 `===` 和 `!==`
- **TypeScript 类型**：避免使用 `any` 类型；如必须使用请提供注释说明原因
- **空值检查**：访问值或解构时执行空值检查以避免空指针异常
- **三元表达式**：不允许嵌套三元表达式

#### React 最佳实践
- **Hooks 使用**：验证是否遵守 Hooks 规则（仅在顶层调用，仅在 React 函数中调用）
- **状态管理**：确保状态放置在适当的层级；避免不必要的状态提升
- **副作用处理**：验证 useEffect 正确处理依赖和清理函数
- **性能优化**：验证是否正确使用 React.memo、useMemo、useCallback（基于性能分析；避免过度优化）
- **渲染副作用**：严格禁止在 React 组件渲染方法中产生副作用（如 API 调用、DOM 操作）
- **内联样式**：避免使用内联 `style` 属性，动态样式除外
- **内部组件**：禁止在组件内部声明新组件；使用渲染方法代替（如 `renderItem` 而非 `<Item/>`）

#### 异步处理标准
- **错误处理**：异步函数必须包含适当的错误处理及用户友好的错误消息
- **优先使用 async/await**：优先使用 async/await 而非 Promises；禁止回调地狱
- **循环中的异步**：区分独立异步操作（使用 `Promise.all` 并行处理）和依赖异步操作（使用顺序执行）；性能优先时选用 `Promise.all`

#### 代码安全检查
- **XSS 防护**：验证用户输入是否被正确转义
- **innerHTML 安全**：禁止使用 innerHTML 直接插入用户输入；使用 textContent 或应用 XSS 防护
- **代码注入防护**：严格禁止使用 eval()、Function() 构造函数以及字符串参数形式的 setTimeout/setInterval
- **危险方法**：禁止使用 document.write()，因其会导致页面回流和安全问题
- **敏感信息**：检查是否暴露了 API Key 或敏感数据
- **原型链安全**：禁止修改原生对象原型（如 Array.prototype、Object.prototype）
