#### 明显的拼写或拼写错误
- 类型名、函数名、变量名、枚举变体、trait 名或模块名在声明处的拼写错误；不要在调用点报告拼写错误
- 日志消息、panic 消息、错误消息或公共诊断中包含影响可读性的拼写错误的字符串

#### 所有权和生命周期正确性
- 不正确地返回引用、借用的值逃出其有效作用域、或使 API 不安全或不可用的生命周期关系
- 为解决借用问题而引入的过多或不必要的 `clone()` 调用，当借用、迭代器、`Cow` 或所有权转移会更清晰且更廉价时
- 使用内部可变性（`RefCell`、`Cell`、`Mutex`）来绕过所有权，但没有真正的共享可变性需求
- 使用 `Rc<RefCell<T>>` 或 `Arc<Mutex<T>>` 导致的引用循环，应使用 `Weak` 来打破所有权循环

#### 错误处理和 Panic
- 在生产/库路径中使用 `unwrap()`、`expect()`、`panic!`、`todo!` 或 `unimplemented!`，而该失败是可恢复的或可以用 `Result` 传播的
- 错误过早地转为字符串或未被携带上下文就被丢弃；优先保留原始错误并在边界处添加可操作上下文
- `Result` 或 `Option` 值被忽略、吞掉或映射为误导性的默认值
- 公共 API 在普通无效输入上 panic 而不是返回类型化错误，除非 panic 记录了明确的编程不变量

#### Unsafe 代码边界
- 比必要的范围更广的 `unsafe` 块，或隐藏了多个不相关的不变量
- `unsafe` 块、`unsafe fn`、`unsafe impl Send` 或 `unsafe impl Sync` 缺少或过时的安全理由
- 原始指针解引用没有清晰的合法性、对齐、初始化、别名和生命周期保证
- FFI 边界未验证空指针、缓冲区长度、所有权转移、字符串编码或分配器兼容性
- 在没有使操作合理的文档化不变量的情况下使用 `static mut`、未检查的 `transmute`、`MaybeUninit`、`mem::zeroed` 或手动 drop 逻辑

#### 并发和共享状态
- 持有 `Mutex`、`RwLock` 或 `RefCell` 守卫时间过长，特别是在调用用户代码或可能阻塞的操作时
- 在 `.await` 间持有同步锁，或在异步任务中直接使用阻塞 I/O、sleep 或 CPU 密集型工作
- 关于共享状态、缓存初始化、文件创建或原子操作的检查-执行竞态
- 原子操作的 ordering 对于所保护的数据来说太弱，或过强的 ordering 隐藏了预期的同步契约
- 未证明所有包含的状态在文档化不变量下是线程安全的 unsafe `Send` 或 `Sync` 实现

#### 异步和取消安全性
- 生成的任务的 `JoinHandle` 被丢弃，但失败、取消或关闭仍需被观察
- 对于部分写入、锁获取、事务或资源清理不具有取消安全性的 Future
- 在请求/工作者路径中使用同步文件系统、网络或进程 API，可能阻塞运行时
- 没有 backoff、超时、取消传播或有界尝试的重试循环

#### 集合、迭代器和性能
- 在热路径上避免不必要的分配，如重复的 `String` 构造、`format!`、`collect()` 或 `to_vec()`，当借用或流式处理足够时
- 优先使用迭代器适配器和标准库集合 API，当它们使所有权和复杂度更清晰时；避免掩盖错误处理或副作用的密集迭代器链
- 当预期大小已知且增长成本显著时，确保 hash map、vector 和 string 预先分配
- 当 `HashMap`、`HashSet`、排序或索引策略可以显著降低复杂度时，避免嵌套循环中的 O(n²) 查找

#### 类型和 API 设计
- 使用枚举、newtype 和类型化 ID 来建模领域状态，而非布尔值、字符串或原始整数，当无效状态本可以被表示时
- 设计可复用 API 时优先使用标准转换和借用 trait（`From`、`TryFrom`、`AsRef`、`Borrow`、`IntoIterator`）
- 公共 struct、enum、trait 和错误应具有有用的名称、可见性、trait derive 和适合 crate 边界的文档
- 当 slice、迭代器、trait 或更窄的抽象可以保留灵活性时，避免在公共 API 中暴露具体的集合或同步类型

#### 宏和元编程
仅在 diff 实际定义 `macro_rules!` 或过程宏时标记；不要在普通宏调用上报告。
- `$x:expr` 片段在展开中被多次插值，因此调用方的表达式——以及任何副作用——会运行多次；在展开内将其绑定到一次 `let`
- 导出的或公共使用的宏引用了没有 `$crate::` 的项，因此当从另一个 crate 调用宏时，名称解析会失败或绑定错误的项
- 令牌树（`$t:tt`）片段在没有括号的情况下重新发射，其中运算符优先级可以静默地改变预期含义；这仅适用于令牌级（`tt`）插值，因为 `:expr` 片段和整个展开各自被解析为一个完整的表达式
- 过程宏在格式错误的输入上 `unwrap()`、`expect()` 或 `panic!`，而不是用有用的 span 发出 `syn::Error` / `compile_error!`
- 破坏的宏卫生假设：生成的标识符依赖调用作用域的名称，或同一模块中多次调用宏时碰撞的项

#### 安全敏感代码
- 在使用前验证路径、URL、命令、SQL 和序列化输入；不要用未检查的字符串拼接构建 shell 命令或 SQL
- 不要记录密码、令牌、凭据、私钥或个人身份信息
- 检查整数转换、字节切片和长度算术是否存在溢出、截断和 UTF-8 边界错误
- 加密、随机、认证和授权代码必须使用经过仔细审查的 crate 和显式错误处理；标记临时实现
