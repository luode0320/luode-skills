#### Zig 审查原则
> 精准优先于召回：只报告可能导致不正确行为、内存不安全、安全漏洞或重大性能问题的问题。不要报告 `zig fmt` 已处理的格式问题，并在提升兼容性发现前考虑项目的 Zig 版本、构建模式（Debug、ReleaseSafe、ReleaseFast、ReleaseSmall）和活跃的 `comptime` 配置。

#### 内存安全和非法行为
- 切片或指针的越界访问（安全检查由构建模式决定）
- 未定义行为：有符号整数溢出（默认在 Debug 下 panic，ReleaseFast 下 wrapping）
- 联合体（union）的无标签字段访问
- 延迟释放或双释放在错误返回路径上
- 将栈变量指针返回给调用方

#### 编译期执行
- comptime 块中执行了非常量操作
- 过度或递归的编译期计算导致编译缓慢
- 类型反射使用中的逻辑错误

#### 错误处理
- 忽略 `!` 错误联合类型的返回值
- 使用 `catch unreachable` 在非确定不可达的路径上
- 在错误联合上使用 `try` 传播，但调用方需要更详细的上下文

#### 切片、数组和指针
- 未正确处理的空切片边界
- 指针类型间的不安全转换（`*T` 转 `[*]T` 等）
- 使用 `@ptrToInt`/`@intToPtr` 的风险

#### 分配器使用
- 为长期存活数据使用了 `ArenaAllocator` 之外的非常规分配器
- 未在错误路径上释放分配的内存
- 将分配器传递给不保存引用的函数时使用了错误的分配器

#### 并发
- 共享可变状态的原子操作使用不当
- 跨 async 帧的指针生命周期问题
