#### 明显的拼写或拼写错误
- 变量名、方法名或类名在声明处的拼写错误（使用 `code_search` 搜索类似标识符的命名约定来确认）
- 日志消息或异常消息中包含影响可读性的拼写错误的字符串
- 不要在引用处报告拼写错误，因为这些通常由声明决定

#### 死代码
- 永远无法到达的代码块（如条件始终为 false 的分支、return 语句后的代码）
- 已声明但从未读取或引用的变量
- 大块被注释掉的代码（没有明显的保留意图）

#### 逻辑错误检测
- 错误的 if 条件逻辑（使用 `file_read` 检查周围上下文并确认预期逻辑）
- 边界条件处理错误（特别注意索引和数组长度检查）
- 布尔逻辑运算符的误用（优先级和短路求值问题）
- 明显的无限循环或没有终止条件的递归
- 在不该退出的地方使用了 return/break/continue
- switch case 中缺少 break 语句导致非预期的贯穿
- 有意的贯穿但缺乏解释性注释
- 可能导致 NPE 的代码模式（使用 `file_read` 和 `code_search` 检查数据源调用链来确认风险）
- 逻辑表达式中缺少括号可能导致执行顺序与意图不符

#### 严重性能问题
- 循环内的数据库查询（使用 `code_search` 确认方法调用是否涉及数据库操作）
- N+1 查询问题（建议批量查询优化）
- 大数据集处理无分页（使用 `file_read` 了解数据规模和处理上下文）
- 嵌套循环中低效的算法实现（O(n²) 或更高复杂度但存在更优方案）

#### 线程安全问题检测
仅在以下情况下标记线程安全问题：
- **竞态条件**：存在"检查-执行"模式，其中间状态可能被另一线程修改
- **非原子复合操作**：需要原子性但缺乏同步机制的多步操作
- **不安全的懒初始化**：单例模式或缓存实现中的双重检查锁定缺陷
- **对非线程安全集合的并发写入**：在多线程环境中修改 ArrayList 或 HashMap 等非线程安全集合

不在以下情况下报告：
- **方法内的局部变量**：这些本质上是线程安全的，每个线程拥有自己的副本
- **单线程上下文使用**：没有多线程调用的证据（使用 `code_search` 搜索相关调用上下文确认）
- **只读操作**：即使使用非线程安全的数据结构，如果只执行读操作
- **不可变对象**：指向不可变对象的 final 字段引用
- **已存在适当的同步**：代码已使用 synchronized、Lock、原子类或其他正确的同步机制
- **设计为单线程使用的组件**：如 Builder 模式的构建阶段、临时数据传输对象等
