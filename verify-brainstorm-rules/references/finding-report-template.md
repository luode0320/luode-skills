# 问题清单模板与落盘规则

> 归属 owner：`verify-brainstorm-rules`。用途：统一发散结果的呈现结构与落盘位置。

## 1. 落盘位置

- **优先复用同一轮测试主文档**：本轮已有 `doc/5-tests/` 测试主文档时，把下面的结构作为独立小节追加进去（遵循 `../artifact-storage-rules/references/update-policy.md` 的同一轮复用策略）。
- **无同一轮主文档时**：在 `doc/5-tests/` 新建扁平 md，命名遵循 `../artifact-storage-rules/references/path-map.yaml` 的 `test_doc` 约定 `{datetime}_{中文主题}.md`，主题体现"验证发散"。
- 不新建子目录、不建 `evidence/` 目录；证据（命令输出、日志片段、截图引用）内联进正文，截图按 `doc/data/images/` 规则引用。
- 全文必须先以白话说明结论、影响与范围，技术细节与证据进入附录（遵循 `../artifact-delivery-gate-rules/references/plain-language-document-contract.md`）。

## 3. 填写硬要求

- **每条 P0/P1 必须有触发路径**；写不出触发路径的降为 P2 并标"未证实"。
- **位置必须精确到文件行号或符号**；只写"某模块"不算位置。
- **禁止风格意见**：命名、格式、注释密度等归 `code-style-consistency-rules`，不进本清单。
- **禁止"整体看没问题"**：无问题只能以维度级"无问题 + 依据"表达。
- **建议与裁决分离**：`建议优先级` 是本 skill 的建议，用户裁决结论另起一节记录（可后续追加）。
- **文档体积可控**：待观察区压缩为一行一条，不展开描述。

## 4. 精简示例（问题条目）

```markdown
#### P1-2 新增分页参数未做上界限制

- **位置**：handler/order_list.go:87
- **维度**：边界与空值
- **来源**：改动点
- **触发路径**：请求传 page_size=1000000 时，服务端不校验直接透传为 LIMIT，单次拉取全表。
- **影响**：大表下响应超时与数据库连接占用升高，可被用于放大请求成本。
- **依据**：第 87 行直接使用入参赋值 LIMIT，无上界判断；全仓库检索未见该参数校验。
- **建议方向**：在入口处对 page_size 设置区间校验并给出统一默认值。
- **建议优先级**：下一轮修
```
