# 调试窗口使用与回收纪律

## 适用场景

- 本地联调观察：前端 DevTools console、IDE 调试窗口、调试器输出面板。
- 临时打印观察量，不落入正式日志。

## 使用纪律

1. **只打印本次观察所需变量**：不打印无关对象、不整包打印。
2. **带唯一前缀标识**：沿用 `[DEBUG-xxxx]` 随机短标识（与 bug 域临时调试日志一致），打印内容可被一次 grep 回收。
3. **可溯源**：打印必须带来源（组件名 / 函数名），能区分是谁打的。
4. **走本地通道**：调试窗口输出只用于本地观察，不写入正式日志文件，不混入业务日志。

## 回收纪律

1. 定位完成立即删除临时打印。
2. 提交前全仓库检查：
   ```bash
   grep -rn "console\.log\|[DEBUG-" <本轮改动文件>
   ```
   命中必须逐一处理（删除或转正式日志）。
3. 若观察点确需长期保留，删除调试打印，按正式日志规则重新设计（转 `logging-trace-rules`）。

## 禁止事项

- 调试打印进生产（生产 console.log 禁令属写侧职责，归 `logging-trace-rules`）。
- 把调试窗口当长期观测工具。
- 把 token、密码等敏感数据打进调试窗口。
- 调试输出残留提交。

## 与正式日志的关系

- 调试窗口是本地临时通道，正式观测走框架日志；二者不互相替代。
- 需要长期观测时，用框架日志 + 级别切换（见 `log-level-switching.md`），不用调试窗口。
