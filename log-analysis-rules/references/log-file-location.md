# 日志文件位置约定与当日文件定位

## 适用场景

- 需要知道"日志在哪、今天的日志是哪个文件"。
- 多服务、多实例、多容器场景下区分各自日志。

## 核心约定

1. **路径来自配置，不来自记忆**：日志目录与文件名由项目日志配置声明（`logging-trace-rules` 的配置化要求）。第一步是读配置找 `filePath` / 日志目录字段，禁止凭经验猜路径。
2. **统一落点**：无特殊约定时默认 `<项目根>/logs/`；配置声明了其它路径时以配置为准，两者不一致时以配置为准并记录差异。
3. **按服务隔离**：多服务项目按服务名建子目录（如 `logs/<service-name>/`）；单服务项目可直接在 `logs/` 根下。
4. **当日文件**：按轮转规则定位当日文件，常见格式 `app-YYYY-MM-DD.log`（按日轮转）或 `app.log` + 归档（按大小轮转）。当日文件未生成时，查最近一次轮转的归档文件。
5. **远端日志**：SSH 到目标机器后按同一路径约定定位；有日志平台时优先用平台检索（按服务名 + 时间窗），平台不可用时回落本地文件。

## 操作步骤

1. 读日志配置，取出日志目录与文件名模板。
2. `ls <日志目录>` 确认文件存在性与最近修改时间。
3. 定位当日文件：`ls -lt <日志目录> | head` 取最近写入的文件。
4. 多服务时先确认目标服务名与实例（端口 / 容器 ID），再进对应子目录。

## 禁止事项

- 未确认配置前猜测日志路径。
- 把临时文件、调试输出文件写入正式日志目录。
- 把其它项目的日志目录当作当前项目日志目录读取（跨项目只读边界仍有效）。
