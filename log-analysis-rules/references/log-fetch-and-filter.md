# 日志取证过滤：时间窗、关键词、错误堆栈

## 适用场景

- 从日志文件中取"与问题相关的最小证据集"，避免大海捞针。

## 核心过滤方法

1. **关键词过滤**：request-id、错误码、业务键（订单号、用户 ID）。
2. **时间窗过滤**：以问题发生时间为锚，先宽窗（±5 分钟）确认边界，再收窄（±1 分钟内）；窗口外命中视为噪声。
3. **级别过滤**：只取不低于目标级别的行（如 ERROR 及以上先看，WARN 补充，DEBUG 仅在切级别后）。
4. **堆栈上下文**：定位到 ERROR/WARN 行号后，取堆栈上下文：
   ```bash
   grep -n -A 20 -B 5 "错误关键词" <日志文件>
   ```
5. **多文件合并**：跨服务日志按时间戳排序合并，统一时间格式后再排序。

## 输出规范

- 每条证据必须带：文件路径、行号、时间戳、原始行内容（不改写）。
- 证据片段回贴 bug 主文档 / 测试主文档时，注明来源文件与过滤条件，保证可复现。

## 常见坑

- 日志截断（如错误信息截 80 字符）：看到截断标记时要回源头取完整堆栈。
- 多行堆栈被误截：用 `-A` 取足上下文，别只取首行。
- 脱敏字段：取证片段含 token、密码等敏感字段时按脱敏规则处理后再回贴。
- 时间格式不统一：跨服务合并前先统一时间戳格式（建议 ISO-8601）。

## 禁止事项

- 无过滤条件直接全文扫描。
- 凭记忆改写日志原文。
- 把调试窗口瞬时输出当作日志文件证据引用。
