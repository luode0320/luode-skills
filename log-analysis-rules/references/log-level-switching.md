# 日志级别切换与恢复纪律

## 适用场景

- 当前日志级别看不到关键分支、状态变化或错误详情，需要临时切到 DEBUG 观察。
- 观察完成后需要把级别恢复原状。

## 核心约定

1. **切换前记录事实**：切换时间、当前级别、目标级别、预计恢复时间、恢复动作（改回配置或重启服务）。
2. **切换方式按项目能力选择**（从低侵入到高侵入）：
   - 运行时热更（框架支持时，如日志级别动态刷新接口）；
   - 改配置文件 + 重启服务；
   - 临时环境变量覆盖。
   优先级：热更 > 配置重启 > 环境变量。禁止为了切级别改动业务代码逻辑。
3. **恢复纪律**：取证完成后立即恢复原级别；恢复后验证日志级别已回落（如 `grep -i "level=debug"` 不再命中，或配置回读为原值）。
4. **与临时调试日志的关系**：级别切换针对框架日志整体；`[DEBUG-xxxx]` 临时调试日志针对代码埋点，二者互补。级别切换能解决时优先用级别切换，不要动代码。

## 操作步骤

1. 确认当前级别：读配置或运行时接口。
2. 选择切换方式并执行，记录切换事实。
3. 验证 DEBUG 已生效（能观察到目标日志）。
4. 取证完成后恢复原级别，验证恢复。
5. 若切级别未生效（框架不支持），记录阻断，改用临时调试日志方案（转 `bug-intake-rules` 的 runtime-diagnostics）。

## 禁止事项

- 长期保持 DEBUG 不恢复。
- DEBUG 输出写入正式审计或落库。
- 为切级别修改业务代码逻辑。
- 忘记记录切换事实导致恢复无据。
