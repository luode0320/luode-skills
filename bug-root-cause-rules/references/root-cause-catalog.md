# 常见根因类别清单（Root Cause Catalog）

> 归属 owner：`bug-root-cause-rules`。本文件吸收自 awesome-ai-agent-skills 的 `调试`（debugging，v1.0.0，2026-08-22 吸收）。作为「假设生成」阶段的候选池：先扫一遍类别清单避免漏项，再按 `hypothesis-ranking.md` 的 3-5 个排序假设纪律收敛。
>
> 症状层入口：先用 `symptom-rootcause-map.md` 按五类症状映射根因方向，再进入本文件的代码层类别候选池；两文件为同一链路的上下游。

## 用途

静态定位卡住或证据不足时，用类别清单做「可能是什么」的系统化穷举——把零散经验变成可勾选的候选池，防止只盯着第一眼可疑代码。

## 常见根因类别（先扫一遍再定假设）

1. **输入假设错误**：null、空串、越界、类型不符、格式不匹配（最常见，先查）。
2. **并发共享可变状态**：多协程/多线程读写同一可变容器（缓存、计数器、集合）无同步；典型症状是「只在负载下偶发」。
3. **陈旧缓存 / 记忆化值**：缓存未失效、memoized 值未随依赖更新、TTL 过长。
4. **运算符优先级错误**：`and`/`or`、位运算、三元表达式、链式比较的隐式优先级与直觉不符。
5. **异步缺失 await**：async 调用未等待、Promise 未落定即使用结果、回调时序假设错误。
6. **依赖版本不兼容**：升级后 API 变更、传递依赖冲突、锁文件漂移。
7. **无界内存容器**：模块级数组/Map/缓存只增不减（内存泄漏的常见形态，症状是随时间线性增长直到 OOM）。

## 边界场景（外部原因优先排除）

按顺序排查，避免在应用代码里死磕：

1. **第三方库 bug**：根因在依赖而非应用代码时，先查该库 changelog 与 issue tracker，再决定升级、workaround 或 pin 已知良好版本；推荐修复路径前必须先确认版本事实。
2. **编译器 / runtime bug**：极少数情况下缺陷在语言运行时自身。先穷尽应用层解释，确认无应用层原因后再建议在不同 runtime 版本上测试验证。
3. **数据损坏状态**：涉及半写入记录、坏数据时，诊断必须数据与代码一起看——向用户索取样本数据或数据库状态，与代码路径分析关联后再下结论。

## 区分根因与症状（强制）

报错本身通常是症状，不是根因：

- 空指针异常是症状，根因可能是三个函数调用之前的缺失校验。
- 显式记录「症状」与「根因候选」两栏，禁止把症状描述直接当根因结论写回 Bug 主文档。
- 判定根因成立前，按 `root-cause-evidence.md` 证据条件复核。
