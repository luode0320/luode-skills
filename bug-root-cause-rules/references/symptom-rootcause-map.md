# 症状分类与根因方向映射（Symptom → Root Cause Map）

> 归属 owner：`bug-root-cause-rules`。本文件吸收自 `qa-test-skills` 的 `qa-bug-root-cause-analysis`（v1.7.0，Kokxi/qa-test-skills，2026-08-23 吸收）。作为静态定位的「症状层入口」：先从现象归类症状，再映射根因方向，然后进入 `root-cause-catalog.md` 的代码层类别候选池与 `hypothesis-ranking.md` 的排序假设。
>
> 与 `root-cause-catalog.md` 的分工：本文是「看到什么现象 → 往哪个方向查」的粗粒度入口；catalog 是「代码层可能是什么」的细粒度候选池；两文件为同一链路的上下游，代码层细节不在本文件重复展开。

## 用途

静态定位第一步先做症状分类，避免带着模糊现象直接扎进代码。五类症状（返回错误 / 数据不对 / 性能退化 / 没反应 / 偶发问题），每类映射到四个根因方向层。

## 症状 1：返回错误（HTTP 4xx/5xx、业务错误码、错误信息）

```text
根因方向：
├─ 代码层：逻辑错误（条件判断）/ 空指针（对象未初始化）/ 数组越界 / 类型转换
├─ 数据层：数据缺失 / 数据错误（格式/值）/ 数据冲突（唯一性约束）/ 数据过期
├─ 配置层：配置缺失 / 配置错误 / 环境差异 / 配置变更
└─ 依赖层：依赖不可用 / 依赖超时 / 依赖返回错误 / 依赖版本不兼容
```

## 症状 2：数据不对（缺失 / 错误 / 不一致 / 格式异常）

```text
根因方向：
├─ 写入问题：写入失败 / 写入丢失（事务未提交）/ 写入延迟（异步未完成）/ 写入重复（重复提交）
├─ 读取问题：缓存不一致 / 读取过滤（查询条件）/ 读取延迟（读从库）/ 读到旧缓存
├─ 同步问题：同步延迟 / 同步失败 / 同步冲突（并发）/ 同步丢失
└─ 转换问题：格式转换 / 编码不一致 / 精度丢失（浮点）/ 时区错误
```

## 症状 3：性能退化（响应变慢 / 吞吐下降 / 资源占用高）

```text
根因方向：
├─ 数据库：慢查询 / 索引缺失 / 锁等待 / 连接池耗尽 / 数据量增长
├─ 代码：算法复杂度 / 循环嵌套 / 内存泄漏 / 线程阻塞 / 频繁 GC
├─ 缓存：缓存穿透 / 缓存雪崩 / 缓存击穿（热点 key）/ 缓存容量不足
└─ 资源：CPU 瓶颈 / 内存不足 / IO 瓶颈 / 网络瓶颈
```

## 症状 4：没反应（点击无响应 / 操作无效 / 界面卡住）

```text
根因方向：
├─ 前端：JS 报错 / 事件绑定 / 状态异常 / 请求未发出 / 渲染异常
├─ 网络：请求丢失（丢包）/ 请求超时 / 连接断开 / DNS 解析失败
├─ 后端：请求未接收 / 处理阻塞 / 响应丢失 / 服务不可用
└─ 中间件：Nginx 配置 / 网关路由 / MQ 阻塞 / 触发限流
```

## 症状 5：偶发问题（时有时无 / 特定条件出现 / 难以复现）

```text
根因方向：
├─ 并发：竞态条件 / 死锁 / 线程安全（共享资源）/ 资源泄露
├─ 环境：环境差异 / 配置差异 / 依赖状态 / 硬件差异
├─ 数据：数据状态（特定状态触发）/ 数据量（阈值触发）/ 数据顺序 / 数据时效
└─ 时序：时序依赖（操作顺序）/ 定时任务 / 缓存过期 / 会话超时
```

## 现象速查表（现象 → 症状分类 → 大概率方向 → 优先排查）

| 现象 | 症状分类 | 大概率方向 | 优先排查 |
|------|---------|-----------|---------|
| 报 500 错误 | 返回错误 | 后端异常/数据异常 | 日志 ERROR + 入参数据 |
| 返回空数据 | 返回错误 | 查询条件/权限过滤 | SQL 日志 + 权限配置 |
| 页面白屏 | 返回错误 | 前端解析/接口数据格式 | F12 看接口响应 |
| 金额不对 | 数据不对 | 计算逻辑/精度问题 | 核对计算公式 |
| 状态不更新 | 数据不对 | 状态机/回调处理 | 检查状态流转日志 |
| 账单对不上 | 数据不对 | 数据一致性/事务问题 | 核对多个数据源 |
| 页面越来越慢 | 性能退化 | 慢查询/数据累积 | 慢 SQL 日志 |
| 高峰期就挂 | 性能退化 | 并发/资源不足 | 压测复现 + 监控 |
| 点按钮没反应 | 没反应 | 前端事件绑定/接口不通 | F12 看请求是否发出 |
| 加载中不动 | 没反应 | 后端处理卡住/死锁 | 线程堆栈 + DB 锁查询 |
| 偶尔支付失败 | 偶发问题 | 并发冲突/超时 | 并行多次复现 |
| 特定时间出问题 | 偶发问题 | 定时任务/缓存过期 | 核对定时任务时间 + 缓存策略 |
| 只有某用户出问题 | 偶发问题 | 数据隔离/权限 | 对比正常/异常用户数据 |

## 排查顺序（缩小范围纪律）

按顺序排除，先外部后内部：

1. 先排除外部因素（依赖服务状态 / 环境差异）。
2. 再排除配置因素（配置缺失 / 配置变更 / 环境差异）。
3. 再排查数据因素（数据缺失 / 错误 / 特定状态）。
4. 最后排查代码因素（逻辑 / 并发 / 时序）。

与 `root-cause-catalog.md`「边界场景（外部原因优先排除）」同口径；本处为完整顺序，catalog 展开第三方库 / runtime / 数据损坏的细查方式。

## 根因分层（纵向追问纪律）

根因结论至少区分三个层级，禁止停在最表层：

- **直接原因**：立即导致故障的那一步（如空指针报错处）。
- **间接原因**：使直接原因得以发生的条件（如上游未校验入参就调用）。
- **系统原因**：流程 / 设计 / 测试层面的结构性缺口（如缺少契约测试、缺输入校验约定）。

同一症状先横向产出多个候选假设（`hypothesis-ranking.md`），再对每个候选纵向追问到系统层；修复建议落在间接或系统层，直接原因只是触发点。

## 注意事项

- 分析涉及生产日志 / 样本数据时先脱敏（订单号、支付金额、证件号、手机号等），不粘贴真实生产数据；索要样本数据的口径见 `root-cause-catalog.md` 边界场景。
- 本文只负责症状分类与方向映射，不代替 `static-analysis-path.md` 的调用链收窄与 `root-cause-evidence.md` 的证据判定。
