# 修复建议模板

结论：{推荐的修复结果，一句话}；影响：{受影响的用户、角色或业务环节}；范围：{本次会修复的内容}；非范围：{明确不修复的内容}；变化：{修复后用户或业务可感知的变化}；完成标准：{修复达到何种可观察结果}；术语说明：无技术术语需要解释，或 {术语：它在本次问题中的作用}；验证状态：{根因确认、测试或审查进展和依据}。

本模板不新建文档，只在已存在的 Bug 主文档末尾追加一节 `## 修复建议`，节内首段按上面同一口径写八字段白话开场。字段定义、填写要求与附录分层**唯一见** [白话文档与附录分层契约](../../artifact-delivery-gate-rules/references/plain-language-document-contract.md)。

## 追加结构

```markdown
## 修复建议

结论：{推荐的修复结果，一句话}；影响：{受影响的用户、角色或业务环节}；范围：{本次会修复的内容}；非范围：{明确不修复的内容}；变化：{修复后用户或业务可感知的变化}；完成标准：{修复达到何种可观察结果}；术语说明：无技术术语需要解释，或 {术语：它在本次问题中的作用}；验证状态：{根因确认、测试或审查进展和依据}。
```

本阶段各字段写什么：

| 字段 | 本阶段写什么 |
|---|---|
| 结论 | 推荐的修复结果，一句话 |
| 影响 | 受影响的用户、角色或业务环节 |
| 范围 | 本次会修复的内容 |
| 非范围 | 明确不修复的内容 |
| 变化 | 修复后用户或业务可感知的变化 |
| 完成标准 | 修复达到何种可观察结果 |
| 术语说明 | 无技术术语时写「无技术术语需要解释」 |
| 验证状态 | 根因确认、测试或审查进展和依据 |
