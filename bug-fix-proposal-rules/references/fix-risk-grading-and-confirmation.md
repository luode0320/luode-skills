# Bug 修复风险分级与确认

> 本参考吸收 WorkBuddy 官方 `requirements-pilot` 的“风险高必须先确认、风险低可直接执行”思想，并合并本地 `bug-fix-proposal-rules` 的 `regression-risk` 条件路由。

## 风险等级判定

| 风险等级 | 判定条件 | 是否必须确认 |
| --- | --- | --- |
| 高 | 公共方法、共享模块、对外接口、数据库、缓存、兼容性、异常语义、历史能力变化 | 必须确认 |
| 中 | 改动影响面有限，但可能影响既有调用方或验证路径 | 建议确认；证据不足时按高处理 |
| 低 | 本地单点修复，不改公共契约，不改变历史行为 | 可直接编码 |

## 确认与执行规则

- 高风险修复：先给出主方案、备选方案、影响面、风险点、验证方式和确认建议，写入同一份 Bug 主文档，等待用户确认后再编码。
- 低风险修复：可直接编码，但必须保留分级依据与验证方式。
- 证据不足：不得凭猜测把风险定为低，先补齐影响面证据，再决定是否直接编码。
- 分级结论必须写入当前 Bug 主文档，并继续沿用到修复、回归与验证阶段。
