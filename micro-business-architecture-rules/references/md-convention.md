# 微业务 Markdown 规范

## 文档职责

微业务的说明文档只帮助定位业务域、版本目录和跨域边界；实际目录以 `package-structure-rules` 为准。文档落在业务代码目录，不替代 `doc/` 研发产物。

| 文档 | 落点 | 职责 |
|---|---|---|
| 业务域 README | `<source-root>/<domain>/README.md` | 说明本域职责、版本目录结构与跨域边界。 |
| 全局业务索引 | `<source-root>/README.md` | 列出业务域、职责、状态和 README 链接。 |

不再维护根 `contract/README.md` 或公共接口契约清单。跨域共享结构的权威入口是根 `common/`。

## 业务域 README 必填字段

| 字段 | 内容要求 |
|---|---|
| 业务职责 | 说明本域负责的核心能力。 |
| 边界 | 分别说明本域负责与不负责的事项。 |
| 目录结构 | 按 `package-structure-rules` 列出本域实际子目录（域级通用目录 + 各版本目录 router/<v?>/、controller/<v?>/、entity/<v?>/、service/<v?>/）。 |
| 版本目录 | 列出 `v1/`、`v2/`… 各版本的业务差异与演进说明。 |
| 依赖的其他业务 | 本域是否依赖其他业务域；业务域之间禁止直连，共享结构仅走根 `common/` 与 `global/`；无依赖时写 `无`。 |
| 私有数据入口 | 指向本域 `v*/entity/`、`v*/service/` 等私有实现，明确其他业务不得引用。 |
| 关键链路 | 描述入口、本域处理与响应。 |

## 全局业务索引

业务索引只有一张表：业务域清单。

```markdown
| 业务域 | 一句话职责 | 状态 | README |
|---|---|---|---|
| orders | 订单业务 | 活跃 | [orders](./orders/README.md) |
| users | 用户资料业务 | 活跃 | [users](./users/README.md) |
```

## 维护规则

- 新增业务域时必须建立该域 README，并更新全局业务索引。
- 新增版本目录时，必须更新目标域 README 的版本目录说明。
- 文档不得把目标业务的实体、服务、私有常量或异常类型写成跨域可引用能力。
