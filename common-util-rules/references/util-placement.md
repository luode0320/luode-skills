# 公共工具调用边界与目录转交

## 用途

本文件帮助 `common-util-rules` 判断公共工具是否应复用、是否需要公共调用边界、纯转换函数该落在哪，以及是否应转交目录 Owner；不再保存具体目录、二级子目录或依赖方向细则。

## 公共资格与调用边界

- 与当前业务流程强绑定、需要大量业务上下文参数化的逻辑，留在业务层。
- 已有同语义工具、常量、公共组件或统一协程封装时，优先复用既有实现，不新增第二套入口。
- 需要公共化时，先说明复用范围、输入输出语义、调用边界和不得继续扩张的边界。
- 命中“最近修改时间超过 7 天且多处复用”的通用代码时，优先新增兼容入口，不直接修改旧行为。
- 可脱离项目独立复制的工具包与 SDK 由 Catalog 定位到根 `utils/<package>/`；根 `utils/` 自身禁止文件，且不得依赖项目其他包。
- 需要引用项目其他包、但不承载业务流程的高关联工具函数由 Catalog 定位到独立后端根 `common/util/<function>.<ext>`；该目录禁止子目录。

## 纯转换工具函数的落点（点名判据）

「纯转换函数」指同时满足以下全部条件的函数，它就是根 `utils/<pkg>/` 的典型居民：

- 确定性：相同输入必得相同输出。
- 无副作用：不改外部状态、不写库、不发消息。
- 无 IO / 无网络 / 无时钟 / 无随机：不读文件、不请求远端、不依赖当前时间或全局可变状态。
- 无项目依赖：不引用项目其他包（配置、错误、日志包装、领域常量均不得依赖）。

落点裁决：

- 满足全部条件 → 必进根 `utils/<pkg>/`，按技术主题归包（如 `utils/time/`、`utils/convert/`、`utils/decimal/`），**不得**落在业务域，也不应放进 `common/util/`。
- 一旦需要引用项目其他包 → 降级到独立后端根 `common/util/<函数>.<ext>`（禁止子目录）。
- 只要同时带有业务语义 → 一律不算纯转换函数，留在业务层（见 `util-qualification.md`）。
- 判据冲突时以「能否脱离项目独立复制」为最终裁决。

## 转交 `package-structure-rules` 的条件

- 需要决定根 `utils/`、独立后端 `common/util/`、`common`、`global`、`middleware`、`shared`、`helpers` 等目录落点。
- 需要判断公共根目录是否应拆二级子目录、是否允许新增目录或是否存在根目录堆文件。
- 需要判断公共层能否依赖业务层、跨层依赖方向、模块边界或目录命名。
- 涉及业务源码层、请求结构或数据库层归位时，必须查询 `package-structure-rules` Catalog；本 Skill 只判断是否具备公共复用资格。

## 输出要求

- 本 Owner 输出公共资格、复用检索、调用边界和冻结策略结论。
- 目录类结论只写“已转交 / 应转交 `package-structure-rules`”，不得在本文件内复制目录细则。
