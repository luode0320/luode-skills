# 性能测试方法论 — test-performance

> 归属 owner：`apifox`。本模块提供性能测试的方法论与 apifox 落地方式。吸收来源：API测试自动化专家版（PerformanceTester / performance_guide.md）方法论，转换为 apifox 可执行方式。与 `modules/test-automation.md` 的关系：后者负责 runner/定时任务/CI 执行机制，本模块负责"测什么类型、看什么指标、怎么设计性能用例"。

## 何时加载

- 用户要求"性能测试""负载测试""压力测试""并发测试"
- 接口响应慢、需要量化性能基线
- 上线前需要性能门禁
- 回归时需要监控响应时间退化

## 红线提醒

apifox 不做 JMeter 级压测。性能测试在 apifox 中的落地方式为**重复执行 + 多迭代 + 响应时间断言 + 定时回归**，禁止引入本地压测脚本替代（`test-strategy-rules` 接口测试执行通道红线）。

## 性能测试四类型（方法论）

| 类型 | 目标 | 方式 | 适用场景 |
|------|------|------|----------|
| **负载测试** | 验证正常负载下性能达标 | 正常并发、稳定流量 | 常规性能门禁 |
| **压力测试** | 找系统拐点 | 并发逐步增加，观察错误率/响应时间突变 | 容量规划 |
| **峰值测试** | 验证突发流量下的稳定性 | 正常负载 ↔ 突发高负载交替 | 活动/促销场景 |
| **延迟测试** | 精确测量单请求延迟 | 低并发精确测量 | 核心接口延迟基线 |

## 性能指标（统一口径）

| 指标 | 定义 | 健康参考 |
|------|------|----------|
| P50 | 50% 请求的响应时间 | 业务约定（如 ≤200ms） |
| P90 | 90% 请求的响应时间 | 业务约定 |
| P95 | 95% 请求的响应时间 | ≤500ms 常见阈值 |
| P99 | 99% 请求的响应时间 | 业务约定（如 ≤1s） |
| 吞吐量 | 每秒请求数 req/s | ≥业务约定 |
| 错误率 | 失败请求占比 | ≤1% 常见阈值 |

> 具体阈值以业务/团队约定为准，不要编造通用标准。

## 性能基线校验

| 校验项 | 通过条件 |
|--------|----------|
| 平均响应时间 | ≤ 基线（如 200ms） |
| P99 响应时间 | ≤ 基线（如 1s） |
| 错误率 | ≤ 基线（如 1%） |
| 吞吐量 | ≥ 基线（如 100 req/s） |

任一项不达标 → 记录性能风险，不判定"性能通过"。

## apifox 落地映射（强制）

### 1. 用例设计

- 关键接口的重复执行/多迭代：`test-case run` 或 `apifox run --test-case <caseId>` 多次执行，或 `test-suite` 内多次迭代（`--iteration` 参数以 CLI help 为准）
- 响应时间断言：自定义脚本断言响应时长（如 `pm.response.responseTime` 阈值）
- 回归：`test-suite` 定时执行（`scheduled-task`），对响应时间做退化敏感监控

### 2. 执行方式

- 单次验证：手动跑 N 次取指标
- 长期监控：`modules/test-automation.md` 的定时任务 + 报告

### 3. 环境红线

- 性能用例 environment 只允许 local（`test-strategy-rules` 红线），禁止对 test/prod 压测
- 压测前确认 local 服务已启动且端口可访问

## 最佳实践

1. **测试前预热**：先跑少量请求避免冷启动影响
2. **渐进加压**：从小并发逐步增加，记录每档的错误率/响应时间，找到拐点
3. **持续监控**：长时间稳定性测试后检查响应时间分布（如最大响应 > 平均×5 提示间歇性问题）
4. **指标记录**：性能结果记录到测试主文档（`doc/5-tests/`），保留多次对比历史

## 常见恢复

| 现象 | 处理 |
|------|------|
| 响应时间超标 | 先确认是环境问题（local 资源）还是实现问题，记录基线对比 |
| 迭代参数不确定 | `apifox run --help` 以 CLI 输出为准 |
| 压测影响其他测试 | 错峰执行，控制迭代量，结束后确认无遗留进程 |
| 需要 JMeter 级压测 | 记录为待补测风险（`test-strategy-rules` 风险分层），不引入本地压测脚本 |
