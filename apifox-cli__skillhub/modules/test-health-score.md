# API 健康评分方法论 — test-health-score

> 归属 owner：`apifox`。本模块提供 API 健康度的五层评分方法论与 apifox 落地方式，用于上线门禁/定期巡检的健康评估。吸收来源：API测试自动化专家版（HealthScorer / health_report.md）方法论。数据缺口处理：安全/稳定性等维度 apifox 可能无数据源时**按 0 计并明示**，不编造分数。

## 何时加载

- 用户要求"健康评分""健康报告""API 健康度"
- 上线前门禁的健康评估部分
- 定期巡检项目 API 整体健康度
- 多次测试后需要横向对比

## 五层评分算法（总分 100）

| 维度 | 权重 | 评分标准 | 健康阈值 |
|------|------|----------|----------|
| **功能层** | 30 | 通过率 = passed/total | ≥90% 健康 |
| **性能层** | 20 | P95 响应时间 | ≤500ms 健康（业务约定） |
| **安全层** | 20 | 安全检查通过率 | ≥95% 健康 |
| **稳定性层** | 15 | 错误恢复/重试成功率 | ≥80% 健康 |
| **契约层** | 15 | Schema 验证通过率 | ≥95% 健康 |

各层得分按子项通过率加权累加，总分 = 五层之和（功能 0-30 + 性能 0-20 + 安全 0-20 + 稳定 0-15 + 契约 0-15）。

## 健康度等级

| 总分 | 等级 | 建议 |
|------|------|------|
| 90-100 | 优秀 🟢 | 保持现状，定期复查 |
| 80-89 | 良好 🟡 | 关注薄弱维度 |
| 60-79 | 一般 🟠 | 优先修复 P0 问题 |
| 40-59 | 较差 🔴 | 立即修复，暂停上线 |
| 0-39 | 危险 ⚫ | 紧急修复 |

## apifox 落地映射（强制）

| 评分维度 | apifox 数据来源 |
|----------|-----------------|
| 功能层 | test-suite 运行结果：通过/失败/跳过统计（`modules/test-automation.md` 报告） |
| 性能层 | 响应时间断言 + 多迭代运行结果（`modules/test-performance.md`） |
| 安全层 | 安全相关用例结果（鉴权/越权/输入校验，见 `testing-pitfalls.md` 安全分类）；无数据源则按 0 计并明示 |
| 稳定性层 | 重试/恢复类用例结果（见 `testing-pitfalls.md` Fallback）；无数据源则按 0 计并明示 |
| 契约层 | 契约用例运行结果（`modules/test-contract.md`） |

## 评分示例（功能层）

```
功能层得分 = Σ(子项通过率 × 子项权重) × 30
例如：参数校验 95% × 0.25 + 状态码 100% × 0.25 + 响应字段 90% × 0.25 + 业务逻辑 85% × 0.25 = 92.5% → 27.75/30
```

## 常见恢复

| 现象 | 处理 |
|------|------|
| 安全/稳定维度无数据 | 按 0 计并明示"该维度未测试"，不编造分数 |
| 健康分下降 | 对比各层得分定位下降维度，回查对应模块 |
| 测试总数不足 | 明示样本量，避免小样本高分误导 |
