# API 目录组织 — folder 归类与持续维护

> 覆盖 apifox 接口目录（folder）的**创建、归类、迁移、合并、拆分、归档与定期审计**。已从 SKILL.md 继承：写入标准流程、分支参数规则。

## 何时加载

- 创建接口前需要确定 folder 归属
- 接口堆在「默认模块 / 接口」平铺层、未按业务归类
- 接口需要迁移 / 合并 / 拆分 / 归档到正确 folder
- 项目质量审计（A9/A10）或定期整理时检查接口位置

## 核心原则（强制）

> **接口生成了不是就完事——归类是持续维护工作，不是一次性动作。「生成了就不调整」是反面模式。** 截图反面案例：全部接口堆在「默认模块 → 接口」一层，没有按业务模块（交易所 / 兑换活动 / 币种 / 翻译…）归类。

1. **创建即归类**：每个 endpoint 创建时就必须落在业务 folder 下，不允许停留在「默认模块 / 接口」平铺层（对应硬动作 A11）。
2. **业务模块识别**：按产品模块 / 业务域 / 功能域分组，禁止按 URL 路径机械分组（`/api/v1/xxx` → 建 `api/v1/xxx` 目录是反面模式）。
3. **持续维护**：接口迁移 / 合并 / 拆分 / 归档是常规操作，发现归类异常**立即调整**，不累积。
4. **定期审计**：项目质量审计（A9/A10）、sprint 收口时顺带检查 folder 归类；新增接口后同步检查其归类。

## folder 三级深度（推荐）

- **L1 产品域**：如 `交易所`、`钱包`、`营销活动`
- **L2 业务子域**：如 `币币交易`、`兑换活动`、`币种管理`
- **L3 接口组**：按功能聚合同类接口（同一业务对象的 CRUD / 同一页面的一组接口）
- 超过三级 → 考虑拆分或重新建模；folder 名用业务中文名，不用 URL 前缀 / 技术名
- 单一 folder 接口数 > 20 → 提示拆分；folder 为空 → 提示归档或删除

## 业务模块识别法

- **来源优先级**：产品模块文档 > 接口 summary/tags > 业务域上下文受控推导
- **判定问题**：这个接口服务哪个业务场景？谁调用它？操作 / 返回什么业务对象？
- **反例（禁止）**：按 URL path 展开（`/api/swap/...` → 建 `api/swap` 目录）、按 controller 名机械展开、全部塞进「默认模块」
- 同一业务的读 / 写 / 查询接口尽量归入同一 folder，方便用例与文档导航

## 持续维护工作流

| 场景 | 动作 | 说明 |
|------|------|------|
| 接口归类错误 | 迁移 | `apifox folder` 定位目标 folder，endpoint 归属变更；同步更新相关 test-case 的引用 |
| 多接口同一业务但分散 | 合并 | 归并到同一 folder，删除空 folder |
| 单一 folder 过大 | 拆分 | 按业务子域拆 L2 / L3，迁移相关接口 |
| 接口废弃 / 下线 | 归档 | 移入 `归档` folder 或标记 deprecated，避免污染活动接口导航 |

> 迁移接口后必须回读验证（`endpoint get <id>`），确认 method+path+schema 未丢失、folder 归属已生效；涉及测试用例时按 `test-case.md` 更新流程同步修正。

## 定期审计命令集

```bash
# 1) 列出未归类接口（命中「默认模块」等平铺层 → 待归类清单）
apifox endpoint list --project <projectId> --branch <branch> --output endpoints.json
# 解析 endpoints.json：folder 为默认/根目录/空的接口全部列为待归类

# 2) 检查空 folder / 孤儿 folder
apifox folder list --project <projectId> --branch <branch>

# 3) 检查 folder 深度（超过 3 级 / 超过 20 接口的 folder 提示拆分）
# 4) 与 project-interface-baseline-rules 的接口清单对账：新接口是否都落了 folder
```

**审计结论格式**：待归类接口数 / 空 folder 数 / 超深 folder 数；非零则按「持续维护工作流」逐项修复，修复后复扫归零才算收口。

## 与 tags 的关系

- **folder = 目录归属**（结构维度，决定接口在文档树中的位置）
- **tags = 业务标签**（语义维度，决定导入分组与检索）
- 两者都要：导入时 `import-export.md` Step 5 校验 tags 业务化；导入后 A11 校验 folder 归类；不能只依赖其中一个

## 不可违反规则

1. 创建接口后不落在业务 folder、停在「默认模块 / 接口」平铺层 → 视为归类缺口，必须归位后才能收口
2. 禁止按 URL 路径机械建 folder
3. 接口变更（新增 / 删除 / 迁移）后不同步调整 folder → 视为归类缺口
4. 质量审计时跳过 folder 归类检查 → 视为审计不完整
