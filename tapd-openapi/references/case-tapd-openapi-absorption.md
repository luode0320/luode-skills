# 已完成修复补录经验吸收案例

## 调整目标与边界

只补齐 TAPD 的已完成修复记录和工时登记流程。OpenAPI 拥有实体、状态及工时规则，CLI 拥有运行方式，环境引导拥有凭据真源；不改任务执行器、不新建同类 skill、不重放 TAPD 写请求。

## 同域扫描与裁决

扫描 tapd-openapi、tapd-cli、tapd-env-bootstrap、tapd-task-executor。创建人和凭据规则已覆盖，采用引用；新增补录路由与执行器职责分开。清理主入口的 5 个 Bug 文档失效路径，无兼容副本。新增业务规则仅在 completed-fix-and-timesheet.md 一处，CLI 只链接它。裁决见根目录吸收表，来源事实见 source-notes.md。

## 检验样例

1. 已修复 Bug 登记 1 小时，代码回归通过但尚未验收 HTTP：选择已确认项目和真实创建人，记录修复及提交；已解决，不标已验证/关闭，不自动通知或转派；实际工时写 timesheet，不自动写 effort。
2. 工时 POST 超时，但同实体、同日期、同工作人已有 1 小时：GET 查询并核对四项唯一键，确认数值正确则复用；不再 POST 新建。
3. 用户只要求实际 1 小时，workspace_list 为空：按已配置项目 ID 查项目信息并结合上下文定位；只写 timespent，不照抄本次曾双填的 effort；项目仍有歧义时仅询问项目。

上述样例用于独立子代理的流程 dry-run，不产生 TAPD 写入。文档及字段校验、WSL 脚本冒烟与真实 TAPD 先前回读是不同证据，不能把 dry-run 宣称为再次完成 API 写入验收。
