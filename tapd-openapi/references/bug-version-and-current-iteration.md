# Bug 版本与当前迭代

本文件是 TAPD Bug 默认版本填写的唯一规则来源。适用于新建或补录 Bug，以及用户要求给已有 Bug 填写“当前版本”。默认使用该 Bug 所属项目的当前迭代；它是动态查询结果，不是某个固定版本号。

## 每次写入前实时查询

1. 先确定本次 `workspace_id`。已有 Bug 用 `/bugs` 回读其归属；新建 Bug 沿用已确认的项目。不能使用配置列表第一项、上一个 Bug 的项目或其它项目的当前迭代。
2. 用户已明确指定版本或迭代时优先按其指定值处理，但仍实时查询对应项目以校验 ID、归属和候选值。修改已有 Bug 的其它字段时不自动覆盖其非空版本或迭代；本规则不授权批量修订历史记录。
3. 在本次操作中重新 GET `/iterations?workspace_id=<本次项目>&limit=200&page=1`，逐页读取直到返回不足一页；同时 GET `/bugs/get_fields_info?workspace_id=<本次项目>`，读取 `iteration_id.options` 与所需 `version_*.options`。本次操作内可复用这批响应完成选择和写入；下一次创建、补录或版本修改必须重新查询，不能用记忆、上次任务的响应或上次会话的版本号作默认值。
4. 按用户已确认时区的业务日期核对迭代开始/结束日期；无法确定用户时区时先询问，不退回宿主本地日期。当前标识的可核验来源是 `/bugs/get_fields_info` 返回的 `iteration_id.options` 候选标签，例如名称后带“（当前迭代）”；迭代日期和状态来自 `/iterations`。接口没有此标识时，按实际状态、日期、迭代说明和用户范围确认唯一候选，不假设另有字段。排除已关闭或未来迭代；只有 `status=open` 或版本号较大不等于当前。日期、标识或状态冲突、必要证据缺失或查询失败时，保留已有值并说明缺口，不猜默认版本写入。
5. 当前候选只有一条且归属、状态和日期一致时，使用其实际 ID 与版本名称。若同时有多个当前迭代，结合该 Bug 已有归属、迭代说明与用户明确范围裁决，并说明选择依据；证据不足以唯一确定时列出名称和周期，询问用户。禁止仅按最高版本、最大 ID、列表第一项、最新创建时间或最新开始日期机械选一条。
6. `scripts/tapd_client_stdlib.py` 的 `mine --iteration current` 是待办查询入口；其日期重叠时取最新开始日期的便捷结果，不可直接作为 Bug 写入裁决。默认版本填写仍执行上述完整查询、分页、时区与歧义检查。

## 字段填写边界

| 字段 | 默认动作 | 必须具备的证据 |
| --- | --- | --- |
| `iteration_id`（所属迭代） | 新建时填写本次确认的当前迭代 ID | 同项目的实际迭代记录；已有值非空则不因更新其它字段而覆盖 |
| `version_report`（发现版本） | 新建时默认填写所选当前迭代对应的版本值 | 版本值存在于该项目字段候选；用户指定或已确认的实际发现版本优先 |
| `version_fix`（合入版本） | 不因当前迭代默认规则而自动填写 | 有实际合入事实且版本候选匹配才填写；用户指定的未来目标可记在描述中，不能当作已合入版本写入此字段 |
| `version_test`（验证版本） | 不因当前迭代默认规则而自动填写 | 有对应版本的实际验证证据；local 报价或代码测试不能冒充发布版本验证 |
| `version_close`（关闭版本） | 不因当前迭代默认规则而自动填写 | 有实际关闭事实；待版本验证状态不能当作已关闭 |

迭代名与版本候选不一致时，使用项目明确给出的映射或询问用户，不自行删除 `V` 前缀、拼接补丁号或新建版本候选。只有实际存在的 `release_id` 关联证据才能填写发布计划，不能把迭代 ID 当发布计划 ID。

## 写入与回读

- 在已确认归属和候选值后，将 `iteration_id`、`version_report` 放入新建 `/bugs` 的载荷，避免先建空版本再等用户提醒。已有 Bug 的版本补填用同一端点及完整 `id`。
- 写入后 GET `/bugs` 按 `workspace_id + id` 回读，逐项确认所属迭代、版本值与预期一致；用户要求的其它字段和工时也按各自规则核对。`status=1` 或 HTTP 200 不代表字段一定生效。
- 最终明确报告填了哪一种版本字段、迭代名称和 ID；本次查到的具体版本只作为本次结果，不写成 Skill 的固定默认值。
- 写入超时或结果不明确时，按 [修复补录与工时登记](completed-fix-and-timesheet.md) 先回读，不盲目重复创建。环境和身份继续复用主 SKILL 与 `tapd-env-bootstrap`，本文件不复制凭据配置。

## 反例与接口入口

反例：因为上一条 Bug 填了某个版本，就直接给新 Bug 填同一个版本；因为多个迭代都开启，就选版本号最大的一条；只写描述里的版本文字而不写实际字段；把本地验证通过填写成发布版本验证完成。

接口说明：[迭代查询](iterations/listiterations.md)、[Bug 字段候选](bugs/get_bug_fields_info.md)、[创建 Bug](bugs/add_bug.md)、[更新 Bug](bugs/update_bug.md)、[查询 Bug](bugs/get_bugs.md)。这些文档说明 API 参数，默认值策略统一由本文负责。
