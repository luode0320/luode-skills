# 自然行文与去 AI 味规则

> 归属 owner：`artifact-delivery-gate-rules`。本文件把 [白话文档与附录分层契约](plain-language-document-contract.md) 第 2 节"白话开场"的模糊要求（"短句和常用中文"）落成可执行的识别与改写规则：认识 AI 味、去掉它、保留作者声音。吸收来源：BuiltinMarket「自然改写」(write v1.0.1，SkillHub 生态) 的 write-zh.md 中文 AI 味模式库、翻译腔套路、专家腔清单、用词替换表与标点规则；humanizer-zh 的 AI 写作特征清单。本文件是"怎么写像人话"的单一权威，白话契约不再重复展开。

## 0. 编辑哲学（先读，优先级最高）

1. **过度编辑 = 失败，与不编辑同等**。句子已经自然、清楚、稳定就留它。大部分润色是减法（删重复、删总结腔、删重述结论），不是逐词替换。
2. **作者的声音赢**。保留作者已有的口语词、节奏和立场。规则与作者的刻意选择冲突时，作者赢。规则是默认值，不是法律。
3. **禁用词表和替换表是例子，不是查找替换**。上下文里读着自然的"禁用词"就保留。认味，不认串。
4. **偏好更少、更强的编辑**。三处关键修改胜过三十个机械替换。
5. **规则不许只增不减**。学到新教训时并进已有原则，不追加新禁用词。这份文件不单调增长。

## 1. 保语义 > 去 AI 味（最高优先级）

先确认事实、逻辑、因果不变，再做改写。为"更口语"改坏原意 = 失败改写。技术事实、版本、环境、依赖、出处、复现条件、风险边界不得为删 AI 味而删除；缺信息不编，可保留问题或收敛语气。

## 2. 高频 AI 味模式（按频率优先检查）

**① 段末收尾总结句**（最高频）：一段刚解释完某机制，结尾再重述一遍。识别信号："到这里"、"这说明"、"这本身就是"、"可以看出"开头，或段落最后一句比其他句短且抽象。**直接删**。
> NO: "这不只是设计选项，是资源约束的结果。"（紧接在已解释具体代价之后）
> OK: 说完就停，事实本身已说明一切。

**② 升华句**：把具体工程观察上升到普适人生道理。直接给具体建议，不升华。
> NO: "很多东西都是这样，当初成立的假设，过一段时间回头看可能已经不成立了。"
> OK: 直接给具体建议。

**③ 对比句式**：AI 最爱结构。"不是…而是…"、"X 本身没有价值，真正有用的是 Y"、"X 已经不是瓶颈，Y 才是"。直接说结论，不用对比框架铺垫。
> OK: "代码生成不卡人了，真正费力气的是评审" 比 "代码生成不再是瓶颈，评审才是" 自然得多。

**④ bold 小标题模式**：`**xxx**。content` 改 `**xxx**，content`，让 bold 变成承重词不是独立小标题。例外：bold 本身是完整句子（"能跑不代表安全"）时保留句号。连续 3 行以上对称 bold 起句仍是模板节奏，从第 4 个起改行内嵌入式粗体。

**⑤ 章节引介过渡句**：章节开头/结尾写"上面这些模式解决的是…，下面再看…"——只在宣告结构、没有信息量，直接删。例外保留：内容说明（告诉读者这节为什么值得看）、模式切换信号（原则→案例）、行动指引（给读者具体下一步）。

**⑥ 空泛形容词预判**："更干净："、"逻辑很清晰："，形容词抢先下判断，冒号才引出事实。删掉形容词只留事实。想保留形容词，多半是后面内容没讲清楚。

**⑦ 工整并列总结**：每节结尾必有一句"三层缺一不可"型总结。口语化或删掉。
> NO: "三层缺一不可，只靠 A 没用，只靠 B 不够。"
> OK: "用下来感觉，少任何一层都会出问题。"

**⑧ 段内重复**：同一段把同一意思用不同措辞说两遍。说一遍够了。
**⑨ 重复核心观点**：同一道理在不同节出现 2-3 次。说一次，后面引用或跳过。
**⑩ 讲解腔起手**："真拆开看"、"这背后是同一个变化"、"真正关键的问题是"。删掉直接说。
**⑪ 训人感起手**："先问问是不是 X"、"你得先明白"→"可以先看 X"、"先确认 X"。
**⑫ 系统性定义开头**：教科书格式"X 是对 Y 的系统性评估，包括…"。从问题或场景出发，不从定义出发。
**⑬ 瓶颈转移句**："瓶颈从 X 转移到了 Y"。直接说新情况，不用"瓶颈"这个词。
**⑭ 优先级结论句**："安全边界要比任何功能都先做好"→说清楚为什么："能跑 shell 就能删库，安全得先来"。
**⑮ 收尾答疑**：文末"应该能给你这些问题答疑"→删或改"读完这篇，这几个问题应该能有些答案"。
**⑯ 挑战与未来展望模板段**："尽管面临挑战，X 凭借 Y 仍将持续蓬勃发展"→直接说具体挑战和应对。
**⑰ 同义词循环**：同一对象用 3 种以上同义词替换。选一个称呼用到底。
**⑱ 虚假范围**："从 X 到 Y"里 X、Y 不同尺度（"从架构设计到团队文化"）。直接列真正涵盖的两三件具体事。
**⑲ 知识截止免责声明残留**："根据可用信息"、"现成资料中没有广泛记录"。要么查清直接写，要么删掉。模糊免责声明本身就是 AI 痕迹。
**⑳ 数据后 AI 营销腔**："token 节省 37%"→"token 从 15 万降到 2000，中间 19+ 次来回推理也省掉了"。

## 3. 翻译腔 4 套路（主动排查）

**① 思考过程用物理动作动词**：接住、击穿、锋利、不崩、不爆、打穿、扛住（骨架是英文 catch/pierce/sharp）。换成日常中文："你这几条我都收到了"、"这个假设不成立"。

**② 形容词预判+冒号**："更干净："、"逻辑很清晰："。删形容词留事实（与 2⑥ 同）。

**③ 抽象名词做主语，形容词当结论**："X 的 Y 比 Z 更 W"骨架。让人、动作、具体对象做主语，事实自己说话。
> NO: "工程上的现实比这些数字难看。"
> OK: "这些数字只反映了采用面；真往下看各家怎么接，早就对不齐了。"

**④ 有稳定中文对译的英文词直接混入**：context→上下文、state→状态、cache→缓存、claim→断言、runtime→运行时、contract→契约。术语在中文圈未收敛的（prompt、embedding、tokenizer）保留英文合理。

## 4. 专家腔（润色易把作者改得比原文更像专家）

1. **不补实作细节**：原文只说"串口通信难"，不要补"ACK 丢了、超时重传、翻日志定位"这类原文没有的排障故事。硬件型号、协议字段、波特率、故障原因、排查顺序，原文或用户没给就不补。技术文的人味来自真实细节，不来自编一个更像工程师的 Debug 故事。
2. **元叙事 in 正文**："写到这里"、"更稳的写法是"、"我把 X 单独拿出来讲"→直接陈述或换"一圈下来"。
3. **二人称读者预测**："你会自然地问"、"你会发现"→去"你"做主语："翻论文时会先看 X"。
4. **段首 announce 引子**："X 也是容易被低估的部分："→直接进 X。
5. **章节编号一/二/三前缀**：`## 一、X` 像教材目录，去前缀留描述/判断。参考文献、操作步骤、明确有顺序的列表可保留 1./2./3.。
6. **同对比框架反复使用**：同一文章 2+ 次"X 只是表层，更有用的是 Y"。留一个正典实例，其余变骨架。
7. **"X 在于 Y"名词化公式**："价值在于 Y"、"区别在于 W"→动词化："最大的好处是 Y"。
8. **第一人称 anchor 边界**：实作经历、踩坑过程可保留"我"；技术判断、结论段让事实做主语。第一人称是经历证据，不是审稿姿态。
9. **学习路径不改入门教程**：原文是边做边学的过程，不要改成"入门不用一上来""先把 X 跑通"的课程框架，除非用户明确要教程。
10. **轻口气不修成老派说教**："我跑过/我看到/我还没答案"的探索口气，不要润成"我来告诉你该怎么做"。

## 5. 用词去正式化 + 高频替换

| NO（少用） | OK（推荐） |
|------------|------------|
| 非常 / 极其 | 很 |
| 值得注意的是 | 直接说结论 |
| 综上所述 | 直接收尾 |
| 例如 | 比如 |
| 购买 / 使用 | 买 / 用 |
| 系统梳理 | 从...一路讲到... |
| 核心结论是 | 最后会看到 |
| 聚焦（空泛目标词） | 重点写什么 / 主要看什么 |
| 硬约束（工程黑话） | 约束 |
| 当然，但 / 这话不算错，但（让步腔） | 直接说结论 |
| 事半功倍 / 少走弯路（成语腔） | 直接陈述 |
| 不可或缺 / 奇妙之处（空泛形容） | 直接说具体现象 |
| 最好的 / 最适合 / 直接搞定（营销词） | 我自己这么用 / 装好就能用 |
| 本文旨在 | 直接进内容 |
| emoji（任何场合） | 不用 |

口语词（太太太、居然、谁能想到、于是乎、哈哈）不是禁用，但默认不要主动加；"好比"只在比喻真的有帮助时偶尔用。不要为了"像人说话"硬塞口语词——过度去口语化和过度口语化一样糟糕。保留作者已用的口语词，只约束"不主动添加"。

## 6. 句式与节奏

- 不用"首先...其次...最后"，用"一方面...另一方面..."（操作步骤除外）。
- 四五个句号连发、每句很短 = 打电报。合成长句或用逗号连。
- 单独成段的一两句话，多半是上一段的收尾或下一段的引子，直接并进去。
- 三个承重点关系很紧，写成一段自然段，不强行拆列表。
- 段内超 400 字或 3+ 独立概念：概念切换处加空行拆分。
- 术语注解不扎堆：多个术语同时首次出现时把注解融入行文或分散到后文。

## 7. 引号、括号、分号

- **引号不是强调键**。不要因为"感觉重要"就套引号。引号只用于：直接引述、系统输出、错误消息。
- **括号**：括号内容超 10 个字，多半该进正文；同段 2+ 处括号，至少 1 处改写进正文。可保留：术语首次英文原词、简短数值范围、代码参数。
- **分号不是懒人句号**：两个"感觉有关系"的句子用句号断开。可保留：对仗句、列表项分隔、中文枚举（一是…；二是…）。分号后接转折词是典型错误，直接断句。

## 8. 标题设计

- **标题要有判断，不只是名词**。好标题表明立场或结论。"多 Agent 协作"→"多 Agent 协作让幻觉互相放大"。
- **不要做成名词并列**：三个名词用顿号串起来没有观点。
- **去冗余词**："应该如何 X"→"如何 X"；副标题与主标题意思重复时合并成一句。
- **"主题，副标题"的逗号换冒号**："Prompt Caching，降低重复调用成本"→"Prompt Caching：降低重复调用成本"。
- 叙事、经历型长文里疑问句和好奇式短语更抓人，判断式标题适合分析型文章；作者已定的标题形式优先。

## 9. 长文结构（多 `##` 节、带表格和图的文档）

- **跨章节同义清单**：同一张评估/判断/取舍清单在 2+ 节各写一遍。留信息最全的一份，其余删或后文一句话带过。
- **表格旁正文复读**：一节有对比表，正文却一行行复述表里的列。正文只补表给不了的（里程碑、具体例子、判断、为什么）。
- **图旁文字复述**：紧邻图的正文把图已列项再列一遍。删复述留判断。例外：图后必要说明段（读者看不到 alt 才需要）不算复读。
- **删段前先确认信息量**：删除整段前确认没有在别处重复的技术事实、数据或逻辑；不确定时改成提议而不是直接删。
- 判断信号：删掉这段/这句，读者会不会丢失一个别处没有的事实？不会就是复读，删；会就保留。

## 10. 对外发文专项（公开文案适用）

公开文案（release notes、博客、公告）交出去之前额外扫三件事：

1. **身份和敏感信号脱敏**：不出现可反推作者身份的细节（雇主、地点、具体团队背景、简历式表述）。技术决策可以具体，身份信息默认删。
2. **不踩竞品**：介绍自己产品时不主动贬低同类产品。直接说自己做了什么、为什么。
3. **用户感受先于功能清单**：不要开场就列功能。先给一句场景或感受，再进改动细节。

## 11. 标点规则（逐字符由脚本强制）

- **禁止 U+2014 破折号（—）与 U+2013（–）**：破折号是最强的 AI 味指纹。用逗号、句号、冒号、分号或括号断句；复合词内的连字符（-）允许。
- 中文语境用全角标点，CJK 与 Latin 之间留空格，由 `../scripts/check_punctuation.py` 检测（跳过代码块、行内代码、URL、markdown 链接）。
- 引号方向、是否成对需要人工判断，脚本不检测。

## 12. 自检清单（白话开场输出前过一遍）

- [ ] 段末没有"这说明/可以看出/这本身就是"开头的收尾重述句
- [ ] 没有升华句、对比框架、瓶颈转移、挑战展望模板
- [ ] 没有翻译腔（物理动词、形容词预判+冒号、抽象名词主语、未译英文混入）
- [ ] 没有补原文不存在的实作细节或排障故事
- [ ] 用词没有"非常/例如/综上所述/系统梳理"等报告腔
- [ ] 没有破折号，标点门禁脚本 PASS
- [ ] 作者已有的口语词和立场保留，未被改成更正式/更像专家
- [ ] 语义、事实、版本、出处未被为去 AI 味而删除
