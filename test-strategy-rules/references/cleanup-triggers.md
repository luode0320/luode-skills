# 测试资产清理触发条件

## 触发条件一：收口时清理（强制）

**时机**：每次测试任务收口前（生成测试结论之前）。

**范围**：
- 本轮测试产生的临时数据（fixture JSON、CSV、YAML、生成文件）
- 本轮测试截图（浏览器截图、终端截图等）
- 本轮测试过程产生的临时日志文件
- 本轮测试启动的临时 mock 数据文件

**执行方式**：
1. 在 `test/<skill>/` 下扫描非 `*_test.py`、非 `*_test.go` 的新增文件
2. 与 `test/run_python_tests.py` 的发现列表交叉比对，未被发现的为非测试代码文件
3. 生成清理清单，用户确认后执行
4. `__pycache__` 自动清理，无需确认

**不适用**：纯代码级测试且未产生任何临时数据文件时，写 `N/A + 无临时数据产生`。

## 触发条件二：Skill 退役/合并时清理

**时机**：当 skill 被 `merge_retire` 标记、`SKILL.md` 被删除、或 skill 的 `name` 字段不再在仓库中注册时。

**范围**：
- `test/<skill-name>/` 下的全部文件（含 `__pycache__`）
- 注意：`test/shared/` 下的共享辅助代码不受影响，需单独评估

**执行方式**：
1. 收集仓库中所有已注册 skill 的 `name` 列表（扫描 `**/SKILL.md` 的 `name:` 字段）
2. 与 `test/` 下的子目录名对比
3. 不匹配的目录标记为"遗留资产"，生成清理清单
4. 用户确认后执行，清理前逐条展示路径

**不适用**：当前无 skil 被退役/合并时，写 `N/A + 无退役 skill`。

## 触发条件三：定期清理

**时机**：
- `__pycache__`：每次测试运行后自动清理（无条件）
- 其他资产：按需触发，不设固定周期

**范围**：
- `__pycache__`：`test/` 下所有 `__pycache__/` 目录（含子目录）
- 临时测试数据：仅在收口时处理

**执行方式**：
- `__pycache__`：`scripts/cleanup_pycache.py` 自动运行，递归删除 `test/` 下所有 `__pycache__/` 目录
- 删除前不生成清单、不询问用户

## 触发条件四：存量清理（一次性）

**时机**：新规则生效后的首次扫描。

**范围**：
- `test/` 下所有目录和文件，按六类资产分类逐一标记
- 重点清理：`__pycache__`、无对应 skill 的遗留资产目录、`fixtures/` 中无引用数据

**执行方式**：
1. 运行 `scripts/scan_stale_test_assets.py` 全量扫描
2. 输出清理报告
3. 用户确认后分批执行（每批最多 10 个目录项）

## 触发条件判定矩阵

| 当前场景 | 应触发的条件 | 操作 |
|----------|-------------|------|
| 测试收口前 | 条件一 | 清理临时数据 + __pycache__ |
| skill 被 merge_retire | 条件二 | 标记对应 test/ 目录为遗留资产 |
| 新规则首次启用 | 条件四 | 全量扫描 + 一次性清理 |
| 日常测试运行 | 条件三 | 自动清理 __pycache__ |
| 多条件同时满足 | 全部 | 按优先级：条件一 > 条件二 > 条件四 > 条件三 |
