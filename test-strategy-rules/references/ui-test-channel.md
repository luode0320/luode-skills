# 页面/UI 级测试执行通道（强制）

> 本节是「页面前端级测试执行通道」的单一权威来源。`functional-validation-rules`、`test-regression-rules`、`bug-validation-rules` 涉及页面交互验证时直接引用本节，不重复定义。补于 2026-09-14：此前测试流程只建立「代码级（本地单测）+ 接口级（apifox 用例）」两条通道，页面前端级仅被写成「不属接口通道」的排除项，没有对应通道承接，导致前后端联调交付缺一层可执行证据。

### 触发判定：前端改动面、前端调用接口、前端可见行为（强制）

- **触发条件（任一命中即判定 `applicable`）**：
  1. **前端改动面**：改动触达页面 / 组件 / 路由 / 样式与交互逻辑 / 前端可见的数据渲染或状态流转。
  2. **被前端调用的接口改动（前端代码零改动同样触发）**：改动落在前端会调用的 HTTP 接口上——新增 / 修改 handler、路由、请求或响应 DTO、参数校验、字段白名单、排序 / 筛选 / 分页口径、错误码与错误文案等接口可见行为；**前端仓库零 diff 不构成豁免**，页面渲染与交互仍会受影响。
  3. **影响前端可见行为的其他后端变更**：认证 / 鉴权 / 会话 / 权限口径、全局错误响应结构、时区或金额精度等被前端直接呈现或依赖的后端行为变更。
- **不触发条件（三条件必须同时满足，缺一不可）**：本轮为**纯后端改动**、**不影响前端可见行为**、且**不涉及前端调用的接口** → 记 `not_applicable` + 原因 + 依据，不阻断。缺任一条件一律按触发处理；**不得仅凭「改的是后端代码、前端仓库零 diff」就判 `not_applicable`**。
- **接口调用面检索（强制）**：改动涉及 HTTP 接口时，必须先在**前端代码中检索该接口的调用面**（API 封装层 / 请求路径常量 / 路由与页面组件），并把检索证据写入触发判定记录——命中则写明前端调用方文件与符号，**全仓零命中**时须明确写出「前端调用面：全仓零命中」结论。不得以「接口名看起来像内部接口」「应该只有后台在用」代替检索。
- **项目形态不影响判定（强制）**：是否存在后端、是否具备联调条件、是否有接口层，都不改变本层适用性。**纯前端项目（无后端服务，数据来自本地 mock / 静态 JSON / 浏览器存储 / 第三方公网接口）**只要存在前端改动面，同样判定为 `applicable` 并强制执行；禁止以「项目没有后端」「没有接口可测」「无法联调」为由记 `not_applicable`——无后端不是豁免理由，只是把与后端相关的要求切换到下文「最低执行要求」的无后端分支。
- **不得以层代层（强制）**：接口级用例通过**不构成**页面前端级的通过证据；「后端接口已验证 + 前端代码审查通过」不能替代真实点击与交互验证。**后端改动轮尤其成立**：接口契约正确不等于前端页面渲染与交互正确——「后端改了响应字段、前端零 diff 但页面渲染崩」正是本层拦截的典型漏检点。**无接口级层时同样成立**：不得以「项目没有后端接口、不需要第三层」为由跳过本层。这是本节拦截的主要漏触发形态。
- **条件受限**：前端服务无法在 local 环境启动、缺少可登录账号 / token / 人机验证无法通过等 → 记 `limited`，写明阻断原因、已完成的替代验证（静态检查、组件级测试、接口级证据）与人工补验步骤；`limited` 不得写成「已放行」。
- **判定落点**：触发判定结论写入测试策略摘要与对应测试主文档，与「接口测试收口证据」并列登记，不得只留在对话里。

### 执行工具：agent 内置浏览器优先，系统默认浏览器兜底（强制）

- 执行工具**不新设矩阵**，统一按 `../mcp-installation-rules/references/tool-priority.md` 的统一浏览器工具路由矩阵选择；本节只固定「页面点击测试」场景的默认优先级。
- **默认（优先）**：使用 agent 可自主驱动的内置浏览器通道——`Chrome DevTools MCP`（独立 profile 的 DOM / 控制台 / Network 观测），或在不依赖用户真实 profile 的基础自动化场景下用 `browser-session-automation-rules`（agent-browser：隔离 profile、具名 session、可脚本化 batch）。
- **兜底（回退）**：当验证必须复用用户真实 profile 中**已有**的登录态、已有标签页、Cookie 或扩展（真实账号会话、SSO、难以自行获取的授权态）时，回退 `Chrome Plugin`（即用户系统默认浏览器）。此时须先按 `browser-session-automation-rules` 的联调授权要求索取可用账号 / token，不得自行绕过授权边界。
- **「需要登录」不构成回退理由（强制）**：本地调试系统（`localhost` / `127.0.0.1` 等 local 环境）的登录凭据由调试侧提供，属可自行注入的授权；此时仍走内置浏览器通道，由 agent 用调试账号 / token 完成登录，不得因为页面需要登录就切到系统默认浏览器。
- **不得混用**：本地隔离 profile 与用户真实 profile 的登录态不得互相复制迁移；需要云端自主长链、托管并发、地域出口等专属能力时按矩阵转交 `browser-use-cloud-rules`，不属本通道默认路径。
- **通道不可用**：项目未接入任何浏览器通道时，按 `mcp-installation-rules` 先完成 provisioning（安装 / 注册 / 配置补齐）再执行；补装后仍不可用则记 `limited` 或阻断，**不得以代码审查或接口证据替代**。

### 最低执行要求（强制）

- 必须完成**至少一条真实用户路径**的自动化点击与交互：打开页面 → 定位元素 → 执行点击 / 输入 / 选择 → 观察结果 → 断言结果；全程在真实浏览器中发生，不得用 jsdom、静态渲染色或组件快照替代真实浏览器执行。
- 动作序列必须包含**关键交互点**，不得只做「打开首页 + 截图」；至少覆盖本轮改动引入或影响的交互路径（提交 / 跳转 / 弹层 / 筛选 / 分页 / 表单校验 / 状态切换等）。
- 每一步都必须有**可判定的结果断言**（预期 vs 实际），禁止只记录动作不记录结果；「页面正常显示」不构成断言。
- 必须同时观察 **Network**，并按**数据来源分支**断言（纯前端项目走无后端分支）：
  - **有后端（本地服务）**：确认页面发出的关键请求真实到达后端并返回成功。
  - **无后端（纯前端项目）**：数据来自本地 mock / 静态 JSON / 路由级 mock 时，断言该数据源被真实调用且内容符合预期；数据来自浏览器存储（localStorage / IndexedDB 等）时，断言读写路径生效；**纯静态渲染、无任何数据请求时**，改为断言静态资源加载无 4xx / 5xx、关键 DOM 与可见状态正确。
  - **数据来自第三方公网接口**：该请求不作为本地验证目标、不参与通过判定（local 红线不因此放宽），但必须在证据中登记其存在与结果，页面渲染断言照旧。
  - 无论走哪个分支，**页面表现正确但数据源报错**、**数据源成功但页面渲染错误**，两种都判为不通过。
- 本地环境红线不变：页面 URL、代理、鉴权回调与依赖服务，以及（有后端时的）后端 API，必须来自本地 `local` 配置（口径见《本地环境配置发现与连接（强制）》）；禁止把 `test` / `prod` / `staging` 域名或远端服务当作点击测试目标。**纯前端项目无后端时，该约束作用于页面自身的服务来源与数据来源**——静态资源服务（本地 dev server / 本地静态文件）与本地 mock 均须来自本机或 `local` 配置；不得为了「制造可测数据」而临时接入非 local 后端。

### 收口硬闸：前端改动轮必须给出浏览器证据（强制）

触发判定为 `applicable` 时，宣称「已完成 / 已验证可用」必须同时给出下列证据，缺任一项即不得宣称完成：

1. **被测目标**：页面 URL、页面标题或关键状态标识（登录态 / 角色 / 数据前置条件）。
2. **动作序列**：按顺序列出元素定位与动作（选择器 / 快照 ref / 文本定位 + click / fill / select），不得只写「测试了页面」。
3. **断言明细**：逐条给出预期与实际，并汇总为**断言总数 / 失败数**口径（与接口证据同口径但分列，不把两类断言合并计数）。
4. **观测证据**：关键步骤的 snapshot 文本或截图（截图须脱敏，并按 `browser-session-automation-rules` 约定在收口前清理）、控制台错误结论、关键请求的 Network 结果（无任何数据请求的纯静态场景改为静态资源加载结论）。
5. **运行环境**：实际使用的是 agent 内置浏览器通道还是系统默认浏览器通道（写通道名）；有后端时写被测服务的启动环境标识（`local`），**无后端时写前端服务来源与数据来源类型**（本地 dev server / 本地静态文件 + 本地 mock / 静态 JSON / 浏览器存储 / 第三方公网接口）。
6. **进程收口**：按《测试进程生命周期（强制）》给出的「关闭动作 + 关闭后状态检查」结论；**纯前端项目至少收口前端 dev server 与浏览器实例**，有后端时一并收口后端服务，均不得残留。
7. **结论留痕**：按 `../artifact-storage-rules` 约定的测试主文档写入本节证据小节，动作序列与断言明细内联，不得只写「已点击验证」而无凭据。

### 允许的例外

- 前端代码本轮零改动、前端不可达、无可授权会话等，按 `not_applicable` / `limited` 如实登记（原因 + 依据 + 替代验证 + 人工补验入口）。**「项目没有后端」不属于本节例外**——按触发判定中的「项目形态不影响判定」条，无后端项目仍判 `applicable`。
- 例外只针对具体验证项，不豁免整轮；也不得把一次豁免沿用到后续轮次。
