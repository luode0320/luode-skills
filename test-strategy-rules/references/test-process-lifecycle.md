# 测试进程生命周期（强制）

任何测试任务（功能验证、真实链路测试、回归、接口测试、浏览器联调等）启动的进程与服务——被测后端、前端 dev server、mock/代理、浏览器实例等——与本轮产生的临时测试数据，都必须在测试收口前清理干净。清理动作、四层清理对象、回读验证与收口话术**唯一见 `../../runtime-process-cleanup-rules/SKILL.md`**，本节不重复定义。

本文件只保留测试域的四条增量：

- **联调开场基线**：联调开始时先关闭既有前后端进程，再按本轮调试目标重新启动，避免旧代码服务污染验证结论；开场基线不替代收尾清理，禁止只做开场收口、不做收尾收口。
- **历史残留先核验归属**：发现占用被测端口或验证目标的进程时，先确认它是不是本轮或前几轮测试留下的；确认后才清理，避免误杀用户自己启动的服务。核验与清理动作同样需要「关闭 + 检查」证据。
- **不替用户保留**：测试启动的服务不得默认留给用户继续联调使用；用户需要时会自行启动，不得以「方便后续联调」为由留在后台。
- **测试数据随进程一并收口**：进程清理的同时按 `test-asset-lifecycle` 条件路由处置临时测试数据，`__pycache__` 自动清理，其他临时测试数据默认自动清理，不留待用户确认。
