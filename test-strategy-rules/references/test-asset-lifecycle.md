# 测试资产生命周期管理

## 六类资产分类

| 类别 | 定义 | 示例 | 生命周期 |
|------|------|------|---------|
| **正式测试代码** | 长期有效的测试文件 | `*_test.py`、`*_test.go` | 随 skill 生命周期；skill 持续存在则保留，skill 退役时列入清理清单 |
| **临时测试数据** | 单次测试产生的数据 | fixture JSON、CSV、YAML、临时生成的文件 | 测试收口后必须清理，不得滞留到下一轮测试 |
| **编译缓存** | 自动生成的字节码 | `__pycache__/`、`*.pyc` | 自动清理（可重建），收口时自动删除 |
| **遗留资产** | 对应 skill 已不存在的测试 | 已 merge_retire skill 的测试目录 | 自动标记→生成清理清单→用户确认后清理 |
| **共享辅助代码** | 跨测试复用的 helper | `test/shared/layout_policy.py` | 持续保留，版本管理；移除需明确评估影响面 |
| **一次性调试脚本** | 只为定位问题临时产生的脚本 | 临时 probe、triage 脚本、curl 探针 | 任务完成后必须清理，不得进入 `test/` 或 `doc/5-tests/` |

## 各分类判断标准

### 正式测试代码 vs 一次性调试脚本

- 正式测试代码：可被 `test/run_python_tests.py` 发现、有 `*_test.py` 命名、有明确的被测对象。
- 一次性调试脚本：无 `*_test.py` 命名、无断言、仅用于人工观察输出、执行后不纳入回归范围。
- 归属不清时默认标记为一次性调试脚本，不得自动晋升为正式测试代码。

### 临时测试数据 vs 遗留资产

- 临时测试数据：与当前轮测试直接关联，存储于 `test/<skill>/fixtures/` 或 `test/<skill>/temp/`。
- 遗留资产：对应 skill 的 `SKILL.md` 中无 `name` 字段或 name 在仓库中不再注册，或 skill 已被 `merge_retire` 标记。
- 归属不清时默认标记为临时测试数据，清理前生成清单供用户确认。

## 清理触发条件

1. **收口时清理（强制）**：每次测试任务收口前，必须清理本轮的临时测试数据。
2. **Skill 退役/合并时清理**：当 skill 被 merge_retire 或删除时，对应的 `test/<skill>/` 目录必须列入清理清单。
3. **定期清理**：`__pycache__` 在每次测试运行后自动清理，其他资产按需触发。
4. **存量清理**：新规则生效后，对存量 `test/` 做一次性扫描清理。

## 清理策略

- **`__pycache__`**：自动清理，无需人工确认（可重建，无副作用）。
- **临时测试数据**：收口时由脚本扫描生成清理清单，用户确认后执行。
- **遗留资产**：脚本扫描标记→生成清理清单→用户确认后执行。
- **共享辅助代码**：不自动清理，移除需评估影响面并记录原因。
- **一次性调试脚本**：任务完成后必须由开发者自行清理，脚本不负责追溯。

## 执行流程

```text
1. 命中 test-asset-lifecycle 条件路由
2. 读取本文件，确认资产归属类别
3. 按类别执行对应清理策略
4. 运行 scripts/scan_stale_test_assets.py 扫描过期资产
5. 生成清理清单（temp_assets.md 或直接输出到测试主文档）
6. 用户确认后执行清理
7. 清理证据写入测试主文档或 PROJECT_HISTORY.md
8. 需要时运行 scripts/cleanup_pycache.py 自动清理 __pycache__
```

## 通过 / 驳回标准

- 通过：临时测试数据已清理；`__pycache__` 已清理或确认无残留；遗留资产已标记并生成清理清单；一次性调试脚本未混入 `test/`。
- 驳回：临时测试数据残留在 `test/` 中；`__pycache__` 目录未清理；遗留资产未标记；一次性脚本混入 `test/` 目录。
