# 测试资产清理策略与安全规程

## 清理策略总纲

| 资产类别 | 清理方式 | 需确认 | 安全等级 |
|----------|---------|--------|---------|
| `__pycache__` | 自动删除 | 否 | 低（可重建，无副作用） |
| 临时测试数据 | 生成清单→用户确认→执行 | 是 | 中（可能影响当前轮调试） |
| 遗留资产 | 生成清单→用户确认→执行 | 是 | 中（可能误删共享引用） |
| 共享辅助代码 | 不自动清理 | — | 高（移除需评估影响面） |
| 一次性调试脚本 | 任务结束时清理 | 否 | 低（不应进入 `test/`） |

## 安全规程（强制）

### 1. 安全优先

- 清理前必须生成清理清单，明确列出**每个**要被清理的路径。
- 清单必须包含：路径、文件数、大小、类别、清理理由。
- 用户确认后才能执行清理，严禁在无确认情况下删除非 `__pycache__` 资产。

### 2. 可追溯

- 每次清理必须记录到 `PROJECT_HISTORY.md` 或知识库。
- 记录格式：
  ```markdown
  - 2026-09-08 清理 test/ 下遗留资产: 3 个目录, 12 个文件, 240KB 释放
  - 清理路径: test/old-skill-a/, test/old-skill-b/
  - 清理类别: 遗留资产(skill 已退役)
  - 确认方式: 用户明确确认
  ```

### 3. 可恢复

- 优先使用回收站/trash 机制，禁止直接 `rm -rf`。
- 如果环境不支持回收站，先 `mv` 到 `_trash/` 目录（项目根下），保留 7 天后确认再删除。
- 清理脚本必须支持 `--dry-run` 模式，只输出清单不执行删除。

### 4. 分批执行

- 每次最多清理 10 个目录项。
- 每批清理后输出清理结果（成功/失败/跳过）。
- 失败项必须记录原因，不跳过。

### 5. 排除保护

以下路径自动排除在清理范围之外，严禁脚本标记为可清理：

- `test/shared/`（共享辅助代码，需单独评估）
- `test/run_python_tests.py`（测试运行器，持续使用）
- `test/` 根目录下的 `.gitkeep` 文件
- `doc/5-tests/` 下的任何文件（非测试代码，不归本域管理）

### 6. 引用检查

- 清理 `test/<skill>/` 目录前，必须检查 `test/shared/` 和 `test/` 下其他目录是否有文件引用该 skill 的测试代码。
- 存在引用时标记为"有引用依赖"，不自动清理，生成提示供用户判断。
- 引用检查方式：`grep -r "<skill-name>" test/shared/ test/`

## 异常处理

| 异常场景 | 处理方式 |
|----------|---------|
| 清理清单为空 | 跳过本轮清理，记录"无资产需清理" |
| 文件被占用无法删除 | 记录路径和错误，跳过，告知用户 |
| 用户拒绝清理 | 记录"用户拒绝"，保持现状 |
| 清理过程中断 | 已清理的部分保持，未清理的保留，下次重试 |
| 引用的交叉检查失败 | 标记为"引用状态未知"，由用户决定 |

## 清理证据模板

清理完成后，必须将清理证据写入当前测试主文档或 `PROJECT_HISTORY.md`。证据模板见 `templates/cleanup-evidence-template.md`。
