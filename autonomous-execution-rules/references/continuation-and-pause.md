# 继续、暂停与高风险边界

本文件承载连续推进节奏和关键节点；不得扩展 `SKILL.md` 的自动触发范围。

### 允许自动继续

- 当前仅完成阶段性子步骤，整体目标尚未闭环。
- 下一步属于原执行计划内未完成的必需项，且仍是完成原始用户目标所必需。
- 下一步可在当前上下文、授权和安全边界内执行。
- 中间进度后仍可继续实现、真实测试、必要修正、`6-review` 或收口。

### 最小任务与周期节奏

- 默认节奏是“当前周期 -> 当前最小任务实施计划完成条件 -> 当前最小任务实现 -> 当前最小任务真实测试 -> 当前最小任务 `6-review` -> 下一个最小任务 -> 当前周期收口 -> 下一周期”。
- 当前最小任务未闭环不得进入下一个任务；当前周期未收口不得跳到下一周期。
- 禁止先完成多个任务的实现，再统一真实测试或统一 `6-review`。
- 当前最小任务进入 `in_progress`、完成为 `completed` 或下一个任务保持 `pending` 时，先由 `task-plan-rehydration-rules` 原子更新 `PROJECT_CURRENT.md`，再调用 `update_plan`；磁盘写入失败不得刷新 UI，工具失败不得回滚已持久化状态。
- Desktop 或宿主中断后恢复到 `in_progress` 步骤时，先核验磁盘、测试和外部状态；未知或非幂等写操作不得自动重放。任务投影恢复不改变 `confirmed/unknown/revoked` 执行许可。
- 默认执行回合取得 `confirmed` 后，无论任务大小，都必须在首个领域动作前为当前 `session_id` 持久化 `active` 或 `blocked` projection，并将持久化成功后的下一动作固定为 `update_plan`；仅投影持久化失败、会话归属冲突/不确定或执行状态不明时硬阻断领域写入，单纯 UI 同步通道不可用（磁盘投影已成功且归属明确）时保留磁盘投影并继续领域执行，下一检查点重试 UI，不得声称 UI 已恢复。当前会话仍无活动或阻断 projection 且扣除 Plan Mode、等待用户、`blocked` 与 `manual_handoff` 后严格超过 600 秒时，十分钟入口只允许先调用只读 `probe-timeout` 作为缺失投影的异常修复；`goal_check_required` 后只允许主 Agent 依次执行 `get_goal`、复用匹配 Goal 或一次 `create_goal`、Goal 安全投影和 `update_plan`。不匹配、不可用、失败或不明确时降级原 `ensure-timeout`，禁止重复创建。恰好 600 秒、任务完成、许可不足或计时丢失均不触发。
- 可自行消解的不确定项采用最小可逆决策继续；不能自行消解且会改变目标、接口或风险时暂停。

### 必须暂停

- 首次进入编码且执行许可不是 `confirmed`。
- 开工指令缺少有效计划，或采纳的建议尚未转为计划。
- 上下文压缩后编码许可为 `unknown` / `revoked`。
- 需要新增超出已确认范围的模块、依赖、数据结构或业务逻辑。
- 删除或覆盖大量文件、破坏性数据操作、生产动作、密钥或权限变更等高风险或不可逆操作。
- 外部付费、跨系统联动或预计成本显著增加。
- 信息冲突无法靠现有证据收敛，继续执行有较高做错概率。
- 任务准备进入 Git 动作但当前轮无 Git 授权；若用户当前轮已明确 Git 动作，直接交给 `git-collaboration-rules`。
- 命中用户结束、无合法后续或真实阻断条件。
- Goal 模式下本节暂停项整体收缩：除「Goal 模式免确认推进」列出的安全与合规红线外，其余分歧自行裁决并按推荐方案推进，不再暂停确认。

### Goal 模式免确认推进（分歧按推荐方案执行）

Goal 模式一旦激活（用户当前轮显式使用 `/goal` 开启目标模式，或用户已显式确认的 Goal 处于 `active`），即视为**计划阶段已经完成、用户已交付结果授权**：用户要的是结果，不是过程中的确认。

- **计划视为已完成**：Goal 激活时不再重复征求计划确认，也不回到需求澄清或方案确认；已落盘的执行计划直接进入实现。
- **分歧自行裁决并推进**：执行中出现多个可行方案、路径冲突、口径不一致或约束互相牵制等分歧时，agent 必须自行完成对比分析，给出最推荐方向并**直接按推荐方向执行**，不暂停、不抛选择题、不等待确认。
- **推荐方向的判定顺序**：① 是否满足已落盘计划与验收条件；② 是否改动最小且可逆（优先最小可逆方案）；③ 是否有当前代码、文档、真实运行结果等证据支撑；④ 是否守住安全与合规红线。
- **证据不足时按最安全兜底推进**：无法判定哪个方向更优时，选最小可逆、最保守、可回滚的方案继续推进，并把分歧、依据与选择写入任务计划文档，不停下来问用户。
- **许可与计划口径**：用户显式开启或确认的 Goal 模式，视为执行许可已 `confirmed`、执行计划已冻结，无需再走开工短句确认；越界或高风险不再作为暂停理由，而作为「按红线收敛方案后继续推进」的理由。
- **不适用对象（防自我授权）**：agent 为补建任务投影、异常修复或超时探测而自动 `create_goal` 产生的 Goal，不属于用户开启的 Goal 模式，仍按原规则不自动取得任何实现授权；免确认推进必须建立在用户显式开启或确认的 Goal 之上。
- **仍不得突破的红线**（不因 Goal 模式放开）：系统安全限制与权限审批、高风险或不可逆操作、`local` 连接调试红线、凭据不回显、Git 写历史红线（提交/推送仍要求当前轮显式授权）、跨项目写入红线与 `WRT-*` 授权边界、个人文件删除保护。
- **退出条件**：用户显式改变、缩小或撤销目标时回到正常确认流程；Goal 未激活或处于 Plan Mode 时不适用本条。

### 关键节点提问

只说明当前阶段结果、节点类型和 2-3 个互斥选项；推荐项置首。不得用开放式“你想让我接下来做什么”替代可执行决策。

固定格式：

```text
我已完成 <当前阶段结果>。当前进入关键节点：<节点类型>。
建议选项：
1) <推荐选项>（推荐）
2) <备选选项>
3) <保守选项>
```

连续执行示例：当阶段性证据分析完成且下一步仍属于原计划必需项时，不停在“如果你要，我可以继续”的可选话术；应直接推进到下一项必需动作。只有进入提交授权、高风险或越界节点时，才使用上述格式暂停；Goal 模式下该格式只在「Goal 模式免确认推进」红线上保留，其余分歧自行裁决推进。

### 安全与审批

自主执行不能绕过系统安全限制、权限审批、local 环境边界、外部副作用确认或高风险防护。任何更高优先级安全规则要求暂停时，本 Skill 必须停止继续。
