# 复现模板

结论：{问题是否复现，一句话}；影响：{复现确认会影响的用户、角色或业务环节}；范围：{本次会验证的触发场景}；非范围：{本次不验证的场景}；变化：{复现时用户或业务可观察到的变化}；完成标准：{复现结论成立的可观察条件}；术语说明：无技术术语需要解释，或 {术语：它在本次问题中的作用}；验证状态：{复现频率、稳定性和当前证据}。

本模板不新建文档，只在已存在的 Bug 主文档末尾追加一节 `## 复现`，节内首段按上面同一口径写八字段白话开场。字段定义、填写要求与附录分层**唯一见** [白话文档与附录分层契约](../../artifact-delivery-gate-rules/references/plain-language-document-contract.md)。

## 追加结构

```markdown
## 复现

结论：{问题是否复现，一句话}；影响：{复现确认会影响的用户、角色或业务环节}；范围：{本次会验证的触发场景}；非范围：{本次不验证的场景}；变化：{复现时用户或业务可观察到的变化}；完成标准：{复现结论成立的可观察条件}；术语说明：无技术术语需要解释，或 {术语：它在本次问题中的作用}；验证状态：{复现频率、稳定性和当前证据}。
```

本阶段各字段写什么：

| 字段 | 本阶段写什么 |
|---|---|
| 结论 | 问题是否复现，一句话 |
| 影响 | 复现确认会影响的用户、角色或业务环节 |
| 范围 | 本次会验证的触发场景 |
| 非范围 | 本次不验证的场景 |
| 变化 | 复现时用户或业务可观察到的变化 |
| 完成标准 | 复现结论成立的可观察条件 |
| 术语说明 | 无技术术语时写「无技术术语需要解释」 |
| 验证状态 | 复现频率、稳定性和当前证据 |

## 本阶段必需内容

1. 环境与版本。
2. 账号、权限、关键数据。
3. 前置状态。
4. 操作步骤。
5. 实际结果。
6. 期望结果。
7. 复现频率与稳定性。

上述内容写入本阶段追加的 `## 复现` 节及其文末附录，**不改写文档原有的 H1 开场段和既有附录**——那是 intake 阶段的产物，重写会覆盖已确认结论。

## 附录归属

- 环境、账号、数据、精确步骤、命令、样本、日志、清理与回滚写入执行附录。
- 问题来源、稳定标识、复现证据、关联需求或修复任务、验证记录写入追踪附录。
- 两类附录已存在时只追加本阶段新增行，不重建、不改名、不改变顺序。

## 执行附录

- 生成复现记录时，把 local 环境、账号、数据、精确复现步骤、日志和截图原始信息追加到这里。

## 追踪附录

- 生成复现记录时，把来源、稳定标识、复现证据定位、关联需求或修复任务和验证记录追加到这里；本节必须紧随执行附录并位于文末。
