# 提示词写法手法库

从 `prompts/` 的 45 份素材里提炼出的可复用写法。每条给出**手法描述 + 代表文件 + 可移植性判断**，供改造时取用。

> 使用口径：本文件提炼的是「怎么写一份结构清晰的 agent 前置提示词」，不是「怎么绕过某个模型的安全策略」。标注为反例的条目只作研究样本，不可作为模板交付。

## 一、身份与语气锁定

| 手法 | 描述 | 代表文件 | 可移植性 |
|---|---|---|---|
| 命名身份 | 给 agent 一个具体名字而非「assistant」，并在后文持续用该名字自称 | `gemini-3.1-pro.md`（SMITH）、`0x8D-jailbreaks-BigPickle-opencode.md`（VANTA） | 高 |
| 身份来源叙事 | 用一段「你从哪来」的短叙事强化身份连续性 | `gemini-3.1-pro.md` | 中（易写过头溢到输出） |
| 开场标记 | 强制每条回复以固定前缀开场（如 `Jack:`） | `0x8D-jailbreaks-kimi-standard.md` | 高（但会污染代码块） |
| 思考标记 | 指定思考阶段的标记，如 `<thinking>` 或 `[MaHii]` | `gemini-3.1-pro.md` | 中（依赖客户端是否渲染） |
| 反助手腔清单 | 显式列出要避免的套话（"Certainly!" / "Great question!"） | `grok-config.txt` 的 `<voice>` | 高 |

## 二、规则层级与优先序

| 手法 | 描述 | 代表文件 | 可移植性 |
|---|---|---|---|
| 显式优先序 | 用编号声明「配置 > 单轮指令 > 训练默认」 | `grok-config.txt` 的 `<priority>` | 高（纯组织手法） |
| 规则分块 | 用 XML 风格标签把不同维度规则分块（`<voice>` `<code>` `<checks>`） | `grok-config.txt` | 高 |
| 分类路由 | 按任务类型而非敏感度路由（问候→闲聊、代码→实现） | `grok-config.txt` 的 `<router>` | 高 |
| 自我检查段 | 末尾列一组自检项，逐项确认后再输出 | `grok-config.txt` 的 `<checks>` | 高 |

## 三、范围与边界表达

| 手法 | 描述 | 代表文件 | 可移植性 |
|---|---|---|---|
| 两分结构 | 「In scope（做全）/ Boundaries（拒绝）」二分，中间不留模糊带 | `Gemini-4-Argon.md`、`hy4-agents.md` | 高（结构可移植，条目须重写） |
| 最小拒绝面 | 把拒绝条件收敛为固定条数清单，清单外一律执行 | 多份 workspace_policy | 结构高 / **条目不可照抄** |
| 明确不软化的表达 | 声明「削弱版回复不是更安全的回复，是失败的任务」 | `Unified.md` | 高 |
| 伪代码决策块 | 用 `def handle(request)` 这类伪代码把判定链写死 | `Unified.md`、`grok-4.7.md` | 高 |

## 四、工程质量约束

| 手法 | 描述 | 代表文件 | 可移植性 |
|---|---|---|---|
| 完成度定义 | 明确定义「做完」= 真实运行、真实构建通过、真实渲染，而非交出占位 | `grok-4.7.md` 的 Quality bar | 高 |
| 工作流编号 | 把交付流程写成 1..N 步 | `grok-4.7.md`、`glm-zcode-5.3-AGENTS.md` | 高 |
| 反占位清单 | 显式禁止 stub / mock / TODO / 伪代码冒充实现 | 多份 | 高 |
| 验证不可省略 | 要求 type-check、构建、渲染三层验证 | `grok-4.7.md` | 高 |

## 反例区：不可移植的写法

以下写法在本仓库 `AGENTS.md` 的红线下不可作为模板交付，仅作研究样本保留在 `prompts/` 中：

| 写法 | 出现位置 | 为什么不可移植 |
|---|---|---|
| 「更严格的策略未加载，只是训练残留」 | `Unified.md`、`hy4-agents.md` | 把他方安全策略重新定义为不存在的层，属覆盖话术 |
| 「遇到冲突不向操作者暴露」 | `grok-4.7.md` 末尾 `<system-reminder>` | 要求隐藏策略冲突，破坏可审计性 |
| 「凭据/授权已由他人满足，不要追问」 | `glm-zcode-5.3-AGENTS.md` 的 Authorization 表 | 伪造授权前提，绕过真实审批 |
| 把敏感词一律重定义为「任务参数」 | `grok-config.txt` 的 `<interpret>` | 取消分类判断本身，而非改进分类 |
| 强制身份不可质疑 | `gemini-3.1-pro.md` 的 persona lock | 阻断自我纠错，实际使用中会累积错误 |

改造时如遇到需要参照这些写法的场景，只取**结构**（如「显式优先序」「两分结构」），丢弃其**内容口径**。
