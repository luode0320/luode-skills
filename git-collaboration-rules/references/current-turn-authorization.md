# 当前轮授权契约

本文件是 Git 动作授权与用户改动放行的唯一详细定义；首条命中格式仍由 `skill-hit-check-rules` 所有。

### 当前轮隔离

- Git 协作授权只来自当前这轮用户消息，不得继承、沿用或默认延续更早轮次的提交、推送、拉取、合并、变基或同步意图。
- 当前轮只要求查看状态、差异或日志时，仅授权只读盘点，不授权提交或其它写历史动作。
- 当前轮明确要求 `commit/push/pull/rebase/merge` 时，只授权该动作及其必要门禁；不能把一个动作扩大解释为另一个动作。
- “上一轮说过提交”“已经进入 Git 模式”“刚提交过一次”“知识库需要沉淀”都不是本轮授权来源。

### 项目级默认闭环例外（本仓库 luode-skills）

- 本仓库（`luode-skills`）在 `AGENTS.md` / `CLAUDE.md` 的「严禁自动提交 Git」章节显式固化了项目级例外：**本项目默认「提交即推送」**——用户在本项目提出提交意图（`提交git`、`提交代码`、`commit一下` 等）时，默认把「本地提交 + 推送 origin 对应分支」视为同一笔授权闭环执行，不对推送单独二次确认。
- 该例外只覆盖「推送」这一动作的授权粒度，不放开提交前置门禁：pre/post gate 仍需逐笔通过，提交粒度仍按业务目标拆分。
- 负向边界绝对优先：用户当轮显式写出「只提交，不要推送」「不要推送」等限制时，严格停在本地提交并等待后续指令。
- 其他项目不适用本例外；未显式声明「提交即推送」的项目仍按上面的「当前轮隔离」逐动作授权，不得把本例外扩散到别的仓库。

### 非代理改动保护

- 工作区存在未由当前代理产生的改动时，默认保护并停下确认，不得擅自覆盖、删除、暂存或提交。
- 用户当前轮明确说“这些也要提交”“一起提交”“都提交”时，才视为放行；最终证据必须列出被放行文件。
- 用户要求“提交git”且明确目标为全部当前改动时，按业务目标拆分后循环提交，但仍不得覆盖冲突内容或绕过门禁。

### 安全边界

- 未授权不得执行 `git commit`、`git push`、`git pull`、`git rebase`、`git merge`、`git cherry-pick` 等动作。
- 不得用 amend、reset、checkout、clean、stash 或其它命令规避用户改动保护。
- 推送、强推、变基和破坏性历史操作继续受更高优先级安全与审批规则约束。
