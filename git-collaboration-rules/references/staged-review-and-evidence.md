# Staged 基础核查与证据

每次 `git commit` 前均以当前 staged 改动为准执行本文件；最近的审查或验收文档不能替代，也不能被当作提交前置依赖。

### 索引漂移前置核对（强制）

大面积“已暂存删除”不等于用户删了文件，可能是索引被整体回退到旧提交；未排除前必须视为阻断，不得直接提交。

- 判据一：`D` 条目对应的路径仍存在于工作树。批量比例越高越可疑；正常删除的文件不会还在磁盘上。
- 判据二：命中的文件与 `HEAD:<path>` 内容一致，或差异只有 CRLF/LF。内容一致说明工作树没变，变的是索引。
- 判据三：`git write-tree` 的结果等于某个历史提交的树（用 `git rev-parse <commit>^{tree}` 比对）。命中即证实索引被回退，通常会连带吞掉期间所有提交的改动。
- 处置：先 `git reset`（混合重置，只回写索引、不动工作树）恢复到 `HEAD`，再重新盘点真实变更集；禁止用 `git checkout`、`git restore` 或 `rm` 处理这类条目，否则会真的删掉用户文件。
- 证据：记录命中条数、内容一致条数、比对命中的历史提交，以及恢复后的 `git status` 变更数。

### 基础代码核查

- 格式：运行 `git diff --cached --check`；若包含代码、脚本、配置或测试，再复用项目已有格式检查命令。
- 索引一致性：已完成「索引漂移前置核对」；出现批量假删除时记录恢复前的异常条数与恢复后的真实变更数。
- 注释：非直观业务规则、并发约束、错误处理和边界行为具有准确且未过期的必要注释。
- 安全性：输入、权限、敏感信息、日志、文件/网络访问和注入面没有明显误放行、泄露或不安全默认值；受版本管理代码、配置和普通维护文档中的有意凭据持久化不构成泄露，日志、错误、测试证据和过程性输出回显原值仍属阻断。
- 并发安全性：共享状态、锁、线程/goroutine、取消、资源关闭和异步回调没有明显竞态、死锁、泄漏或重复执行风险。
- 系统崩溃风险：空值、panic/异常、越界、类型断言、资源耗尽和错误传播不会让进程或关键链路意外中断。
- 边界条件：空值、零值、范围/溢出、超时、分页/批量上限、状态顺序与外部依赖失败路径已覆盖。

发现 P0/P1、关键注释缺失、安全/并发/崩溃风险、边界缺陷或明显潜在 Bug 时，必须先修复或补齐验证再提交。

### 基础验收

按 staged 改动的实际风险确认已有真实测试、功能验证或等价验证是否覆盖。纯文档也必须核查；无关联源码的维度写明“不适用 + 原因”。不得因普通提交自动生成 `doc/6-review/` 或 `doc/7-验收/` 文档，只有用户显式发起独立总审查或正式最终验收时才进入对应归档流程。

### 最基本编译

代码项目在基础验收之外，还要单独确认编译闸门结论：按 `references/baseline-compile-gate.md` 记录实际执行的命令、退出码和结果。编译通过只算最低门槛，不能顶替基础验收里的真实测试与功能验证；非代码项目写明跳过的判定依据。

### 最终证据

使用 `templates/evidence-template.md`，按时间顺序列出：

- 本轮产生的全部 commit hash 与标题。
- 每个 commit 的业务目标和文件范围。
- 格式、注释、安全、并发、崩溃、边界和基础验收结论；不适用项附原因。
- 索引漂移核对结论：命中条数、内容一致条数、比对命中的历史提交与恢复后真实变更数；未命中写“无”。
- 代码项目最基本编译的命令、退出码与结论；非代码项目写明跳过依据。
- pre/post gate 使用的脚本或回退路径及结果。
- 用户显式放行后一并提交的文件。
- 剩余阻断项和未清空文件；没有则明确为无。

最终固定校验行仍按 `skill-hit-check-rules` 与当前 Git 场景要求输出，不在此复制首条格式。
