# Markdown 视觉检查清单

## 检查顺序

1. 结论是否在开场直接说明。
2. H1 后是否只有一段八字段白话开场。
3. H2/H3 是否反映真实阅读层级。
4. 每个段落是否只承载一个结论。
5. 列表是否表达同层级项目。
6. 表格是否用于稳定字段比较，表头是否包含单位、来源或判定方式。
7. 代码块是否有用途说明，命令、日志、SQL 和接口报文是否进入执行附录。
8. Mermaid 是否选择了正确图类型，图前是否有目的和关联 ID，图后是否有异常边界。
9. 图片决策是否写成需要或 N/A + 原因 + 证据。
10. 文档末尾是否按执行附录、追踪附录顺序收口。

## 图形验收

| 图形类型 | 使用场景 | 必须检查 |
| --- | --- | --- |
| flowchart | 流程、依赖、周期和任务顺序 | 存在边、节点名称与正文一致、阻断路径明确 |
| sequenceDiagram | 多角色调用和 Owner 路由 | 参与者完整、消息方向正确、异常响应存在 |
| stateDiagram-v2 | 状态、通过、阻断和停止 | 初始状态、成功路径、阻断路径和停止状态完整 |
| erDiagram | 数据实体和关系 | 实体、关系和字段名称与正文一致 |

## 表格验收

- 表头使用业务读者能理解的名称。
- 对比表的列顺序固定，状态、来源、证据和完成标准不能混在同一列。
- 表格过宽时拆成垂直切片，不用压缩字体解决。
- 表格行不能承载完整段落；完整解释移到段落或附录。

## 视觉阻断条件

- 标题层级跳跃导致读者无法判断章节归属。
- 表格列没有单位、来源或判定方式。
- Mermaid 只存在节点没有关系或消息。
- 图形与正文使用不同术语或 ID。
- 图片没有 IMG-*、非空 alt、相对路径或资产清单。
- 附录结束后继续添加业务正文。

## 验收证据

- 文档 profile 输出。
- Mermaid parser 输出。
- 本任务的 STYLE: PASS。
- 工作树范围核对结果。
