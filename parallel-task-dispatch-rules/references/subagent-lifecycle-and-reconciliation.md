# 子 Agent 生命周期与终局对账

本文件是当前会话子 Agent 实例扫描、回收、关闭、复查和数量对账的唯一细则。`SKILL.md` 只保留强制入口和放行边界，其他 reference 不得重新定义关闭成功标准。

## 适用范围

- 只枚举当前会话可见的非根 Agent。
- 根 Agent、其他会话、全局任务和身份无法确认的实例不在自动关闭范围内。
- 当前会话中仍被当前任务需要的实例保留并继续观测；其余实例进入回收流程。
- 平台列表能力不能限定当前会话时，停止自动清理，不得扩大扫描或关闭范围。

## 三段强制扫描

1. **进入前预检**：每次准备进入并行分类或真实启动前，先枚举当前会话全部非根 Agent，处理上轮或跨轮遗留实例。
2. **批次回收**：每批结果完成、失败、取消、放弃或不再需要后，逐实例回收并复查；存在未关闭实例时禁止启动下一批。
3. **终局扫描**：最终回复前再次全量枚举当前会话非根 Agent，更新实例台账和数量；无法关闭的实例只按告警收口，不阻断已经完成的主体任务。

重复扫描必须幂等：同一 `agent_id` 的终态、关闭成功和未关闭告警只能按最新事实更新，不得重复累加。

## 实例状态与回收顺序

每个可见实例至少记录：`agent_id`、`logical_agent_name`、`platform_nickname`、`scan_stage`、`execution_state`、`close_action`、`close_tool_result`、`verification_result` 和 `warning_reason`。

- `scan_stage`：`preflight`、`batch_reclaim` 或 `final_sweep`。
- `execution_state`：`running`、`completed`、`failed`、`canceled`、`interrupted`、`abandoned` 或 `unknown`。

回收顺序固定如下：

1. `running` 且不再需要：先调用平台真实停止或取消能力，再进入关闭。
2. 已终态且不再需要：直接调用平台真实关闭能力。
3. `unknown`：只报告并暂停该实例的自动关闭，不猜测状态。
4. 关闭动作后：重新枚举当前会话，复查该 `agent_id` 是否仍活跃或仍占用资源。

## 真实关闭判定

只有同时满足以下两个条件，实例才可计入 `关闭数`：

1. 平台真实 `close_agent` 或等价资源释放工具明确返回成功。
2. 关闭后重新枚举，实例不再活跃且不再占用并发资源。

下列结果均不等于关闭：

- `interrupt_agent` 成功。
- 停止采样、取消当前 turn 或暂停执行。
- 收到 completed、failed、canceled 或 interrupted 通知。
- 结果已经被主 Agent 接纳或丢弃。
- 关闭工具返回成功，但复查仍显示实例活跃或仍占用资源。

所谓“等价回收”必须由平台契约明确保证释放实例资源，并通过关闭后复查；仅让实例停止工作但仍可继续使用的能力不能作为等价关闭。

平台没有真实关闭能力时：

- 不调用 `interrupt_agent` 冒充关闭。
- `关闭数` 不增加。
- 实例计入 `未关闭数`，并记录 `warning_reason=平台未提供真实关闭能力`。
- 最终回复允许告警收口，但不得声明“全部已关闭”。

## 批次门禁与最终收口

- 准备启动下一批时，当前会话中任何不再需要但尚未关闭的非根 Agent 都构成批次门禁；`can_start_next_batch=false`。
- 批次门禁只阻止新增子 Agent，不回滚已经验证通过的主体结果。
- 最终回复前即使仍有未关闭实例，主体任务可以按真实完成状态收口；必须逐实例列出 `agent_id`、逻辑名、平台昵称、执行终态、已尝试动作、复查结果和告警原因。
- 未关闭告警不允许被省略、折叠为“平台限制”或改写成关闭成功。

## 数量口径与恒等式

保留既有字段：`计划线程数`、`实际启动数`、`完成数`、`关闭数`、`回退原因`。

新增字段：`终态数`、`终局扫描数`、`仍活跃数`、`未关闭数`、`告警原因`。

数量从实例台账去重重算，不直接信任手工汇总：

- `终态数`：执行状态属于 completed、failed、canceled、interrupted、abandoned 的已启动实例数。
- `完成数`：成功完成目标且结果已被主 Agent 接纳的实例数；失败、取消、中断和放弃不计入。
- `关闭数`：满足真实关闭双重判定的实例数。
- `终局扫描数`：最终扫描实际枚举到的当前会话非根 Agent 数。
- `仍活跃数`：最终扫描后仍为运行或仍占用资源的实例数。
- `未关闭数`：不再被当前任务需要、但未满足真实关闭双重判定的实例数。

必须满足：

- `实际启动数 >= 完成数`。
- `实际启动数 >= 终态数`。
- `关闭数 <= 实际启动数 + 进入前发现的遗留实例数`。
- `未关闭数 = 不再需要且未满足真实关闭判定的去重实例数`。
- `未关闭数 > 0` 时，`告警原因` 非空且不得声称全部已关闭。

`关闭数` 不要求等于 `完成数`：失败、取消、中断或放弃的实例也可能被成功关闭。

## 通过与驳回

- 通过：三段扫描均有真实列表证据；每个不再需要的实例完成回收尝试和复查；数量可从台账重算；未关闭实例准确告警。
- 驳回：未做进入前或终局扫描；把中断、完成通知或停止采样计作关闭；未复查就增加关闭数；未关闭仍启动下一批；有未关闭实例却声明全部已关闭。
