# 测试主文档：珍珠玻璃组件库后台化（后台承载全部组件与用法示例）

结论：组件库后台化改造验证通过，一百五十一个组件全部在管理后台内可达并带可操作示例，独立网页入口已退役。影响：后台菜单新增一个组件库分组共十个分类页；上游登记表中开出一条本地页面注册缝隙；独立示例入口退役后示例只剩一套入口。范围：本轮验证覆盖静态守卫链、类型检查与构建、单元测试、污染扫描、浏览器真实交互，以及两条守卫的反向变异自证。非范围：不改动任何上游业务页面实现，不改动上游组件源码，不执行版本提交。变化：示例入口由两套收敛为一套后台入口，覆盖率从无法度量变为由守卫当场从磁盘推导。完成标准：后台组件覆盖率全部可达、后台内示例浏览器实测可操作、独立入口退役且无残留引用、上游还原度守卫通过且漂移全部声明式可见、分类口径与既有单一真相源一致、构建类型检查单测与污染扫描全绿。术语说明：覆盖率指以后台入口页为起点，沿组件之间真实引用关系走完后能到达的组件数量占全部组件数量的比例。验证状态：全部结论来自本轮真实命令输出与本地真实浏览器实测，无仅凭静态阅读得出的通过项。

## 通过标准

- 覆盖率守卫必须当场从磁盘枚举组件全集与后台入口，不接受任何硬编码组件名单；组件全集枚举口径与目录索引守卫一致。
- 后台示例页必须在真实浏览器内逐个分类完成挂载，卡片数量与分类守卫一致，且控制台无组件渲染错误。
- 独立网页入口退役必须同时满足文件不存在、构建产物无该入口、全仓引用扫描命中 0 三条，缺一不算收敛完成。
- 还原度守卫必须对「缝隙之外的未声明改动」仍然失败，覆盖率守卫必须对「示例页发现面被收窄」仍然失败；两条守卫都需反向变异自证有效。
- 类型检查、构建、单元测试、污染扫描四项全部为真实命令退出码与真实计数，不接受口头说明。
- 只读展示类组件不产生状态，不为其强行补交互；该项判据沿用上一轮逐个组件复核结论，本轮不重复枚举（N/A 补测理由见下节）。

补充证据与口径说明：

- 覆盖率守卫的判据是「导入的本地名在该文件里真的被使用」，仅写批量导入不会被计为覆盖；组件全集与后台入口均当场遍历磁盘得到。
- 还原度守卫的参照物只能是上游冻结提交在对象库里的原始字节：临时克隆会继承本机行尾转换配置，直接读工作树会把参照物算错，因此统一走对象库读取。
- 登记缝隙采用「剥掉声明行后再与上游逐字节比对」，而不是整文件豁免，因此缝隙之外的真实改动仍然可见，MUT-02 即为此断言的反向自证。
- 污染扫描以「本轮改动面」为准：`--diff-only` 与改动域作用域复扫均为 PASS。无豁免的全仓树扫会额外命中 11 条来自 `browser-use-cloud-rules`、`continuous-code-quality-supervisor-rules` 两个与本轮无关且本轮未修改的 skill 脚本，以及 3 条来自 `.gitignore` 已忽略的 `Python/` 解释器缓存目录，均不属于本轮变更集，不构成本轮阻断。
- 单元测试入口是项目自带的 Node 原生测试脚本；仓库未配置 Vitest，直接调用第三方测试运行器会因找不到用例而失败，该失败不属于本项目回归。
- 本轮为回到 200 行与 80 行基准线，把覆盖率守卫拆为裁决入口、可达图访问器、引用边遍历、源码解析四个文件，把还原度守卫拆为本地扫描裁决侧与上游参照物侧两个文件；拆分后所有守卫输出与拆分前一致，且两条变异自证仍在拆分后的文件上复跑通过（发现面收窄后仍为 75/151 并列出缺口）。
- 引用边遍历侧的 barrel 通道经插桩实测在当前引用图里被调用 178 次，属真实遍历通道，不是未经运行的分支。
- 变异自证的还原必须按字节而非按文本：首次还原登记缝隙文件时用文本改写多留下一个文件末尾空行，导致还原后仍判漂移、且校验和与注入前不一致；改为按原始字节截去多余换行后，校验和回到注入前且守卫恢复通过。因此本文件的 MUT-02 还原以校验和一致为完成判据，不只看守卫恢复。
