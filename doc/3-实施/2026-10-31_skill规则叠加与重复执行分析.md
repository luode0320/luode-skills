# Skill 规则叠加与重复执行分析

结论：自建 skill 体系中存在 34 处会被重复执行的规则叠加，其中 4 项 P0/P1 涉及安全口径分裂与最大重复面，已全部收敛；P2、P3 六项为体积与结构优化，亦已按序完成。影响：所有加载 skill 的会话，重复规则会让同一个动作被要求执行两遍并增加规则体积。范围：125 个自建 skill 的 `SKILL.md` 与 references、根 `AGENTS.md` / `CLAUDE.md`。非范围：60 个 `__skillhub` 第三方种子、`doc/` 历史评审记录。变化：阈值、联调流程、Goal 授权、Bug 模板、进程生命周期等重复定义收敛为单一真相源。完成标准：每个重复簇只剩一处权威定义，其余为引用；守卫测试与污染扫描通过。术语说明：「叠加」指同一动作被两处以上规则要求执行；「引用式写法」指只写「见某处」而不复制正文，属合法形态。验证状态：P0-P3 全部完成，守卫测试与污染扫描已实测通过，报告经 `--profile architecture` 校验通过。图片资产决策：N/A 原因：本文档为规则体系分析，结论全部由文本对比与命令输出支撑，无需图示或位图资产；证据：全文无图片引用，校验器 `images.count = 0`。

## 一、先分清三类「重复」

不是所有重复都需要处理。判定口径分四类：

| 类别 | 含义 | 处理 |
|---|---|---|
| A-模型原生 | 大模型不写规则也会做的事（如「想清楚再写」「不要重复代码」） | 可删，但删了无收益，低优先 |
| B-宿主原生 | 宿主平台已提供（description 自动匹配、TaskCreate 待办、编辑前自动校验文件） | 可删 |
| C-跨 skill 重复 | 两个 skill 都写了完整执行要求，会真的被要求做两遍 | **必须收敛** |
| D-确需保留 | 具体阈值、路径、字段名、强制命令 | 保留 |

关键区分：写了「本节不重复定义」「统一遵循 XX」的是**引用式写法**，属于正确的单一真相源形态，判 D，不处理。只有两边都写了完整正文的才算 C。

## 二、会让同一个动作被要求执行两遍的九处

按影响排序，前四项为 P0/P1。

### 2.1 Goal 免确认授权（四处完整副本）

同一套「Goal 模式免确认推进」判据在四处各写一遍完整版本：`goal-loop-rules/SKILL.md`、`autonomous-execution-rules/SKILL.md`、`autonomous-execution-rules/references/continuation-and-pause.md`、`AGENTS.md`。四处字节数分别为 835 / 1,164 / 1,350 与独立章节。

这是唯一涉及**安全口径分裂**的项：四份口径不完全一致，按哪份执行会得到不同授权范围。

应保留：`goal-loop-rules/SKILL.md` 的《Goal 模式免确认推进》为唯一权威，其余三处改为引用。

### 2.2 `codegraph-analysis-rules` 与 `AGENTS.md` 直接矛盾

| 位置 | 表述 |
|---|---|
| `AGENTS.md` 的「CodeGraph 与代码检索」 | 未安装或初始化失败时用 `rg`、`find`、`read`，**不阻断任务** |
| `codegraph-analysis-rules/SKILL.md` | **必须立即强制下载并安装，不需要也不得等待用户确认** |

两处结论互斥，且后者会把一次普通代码理解任务变成强制的工具安装。

应保留：`AGENTS.md` 的不阻断口径；skill 内安装改为可选前置，保留安装命令等技术内容。

### 2.3 Bug 域四份模板要求整篇重写

`bug-intake-rules`、`bug-reproduction-rules`、`bug-fix-proposal-rules`、`bug-validation-rules` 各有一份模板，四份都在模板里完整重复同一段八字段开场。同一份 Bug 主文档在生命周期内被要求整篇重写多次。

应保留：模板改为「在现有主文档末尾追加一节」，八字段定义统一指向白话文档契约。

### 2.4 浏览器两个 skill 的 11 条同文

`browser-advanced-testing-rules` 与 `browser-session-automation-rules` 各写了同一套本地联调流程：触发条件、进程基线收口、local 环境边界、授权注入、进程收口与证据要求，共 11 条逐字相同，行号一一对应。

应保留：联调流程归 `test-strategy-rules` 的页面通道与进程生命周期；两个浏览器 skill 各留自己的执行边界。

### 2.5 代码分解阈值在 10 个文件复述

阈值原文在 `AGENTS.md` 已锁死，但 `code-quality-rules/SKILL.md` 又抄了 3 遍，`readability-general.md` 抄 1 遍，`package-structure-rules/SKILL.md` 自称「核心边界第 12 条」再抄一遍，`project-layout-v2.md`、`structure-general.md`、`function-structure-rules.md`、`function-signature-rules.md`、`readability-examples.md` 与两个 `description` 各有副本。

全仓含「200 行」的 Markdown 文件共 34 个、`SKILL.md` 10 个。同一个阈值被读五遍。

应保留：数字只在 `AGENTS.md` 的「代码分解与目录内聚规则（强制）」出现一次；`code-quality-rules` 只保留该节没有的增量（两类合法特例、`// exemption:` 写法）。

### 2.6 测试进程生命周期双权威

`test-strategy-rules/references/test-process-lifecycle.md` 自称「本节是测试域『测试进程生命周期』的单一权威来源」，而 `runtime-process-cleanup-rules/SKILL.md` 是另一个独立 skill，有完整规则（零豁免原则、四层清理对象、TaskStop 与 taskkill 区别、WSL DrvFS 死锁机理）。两者互不引用、各自自称权威。

应保留：`runtime-process-cleanup-rules` 保留全部执行细节；`test-process-lifecycle.md` 只留测试域增量并显式指向 runtime。

### 2.7 `cleanup-strategy.md` 与在线规则冲突且不可达

`test-strategy-rules/references/cleanup-strategy.md` 写「用户确认后才能执行清理，严禁在无确认情况下删除非 `__pycache__` 资产」，而 `test-asset-lifecycle.md` 写「编译缓存自动清理、遗留资产自动标记后生成清单」，两者结论相反。

更关键的是，这两个文件已经不可达：全仓唯一指向它们的是同样不可达的 `integration-map.md`，构成自闭环死簇。

### 2.8 `skill-hit-check-rules` 的 references 全部不可达

`skill-hit-check-rules/SKILL.md` 正文没有任何一句引用自己的 `references/`（`hit-checklist.md` 96 行、`deferred-gate-registry.md` 17 行）。`hit-checklist.md` 的内容是各 skill 触发词的手抄本，而宿主按 `description` 匹配本身就能覆盖这些触发词。

### 2.9 `local-environment-connection.md` 四条红线重复 `AGENTS.md`

该 reference 的四条红线与 `AGENTS.md` 的「本地连接调试测试红线」是同构重复：判定标准看配置归属不看地址、test/prod 一律禁、用户提供也不得连、写入须清理——连例句都一致。增量只有四条：配置文件搜索模式、`config.apifox.yaml` 优先、确认后回写 `PROJECT_MEMORY.md`、凭据只在配置里持久化。

## 三、属于模型或宿主原生能力的 21 条

这些写了不会错，但模型不写也会做，或宿主已提供同类机制。删了不减正确性，只减体积。

| 类型 | 典型规则 | 判定 |
|---|---|---|
| 模型原生 · 思考纪律 | 「先想清楚再写」「存在多种解释先澄清」 | A |
| 模型原生 · 最小实现 | 「不要过度封装」「没有第二实现不抽接口」 | A（但阈值、豁免写法属 D） |
| 模型原生 · 改动范围 | 「只改必要行」「不顺手重构」 | A |
| 模型原生 · 验证意识 | 「改完要验证」「不能只静态检查就说完成」 | A（但真实运行通道属 D） |

## 四、需求域与 Bug 域的路由环

需求域与 Bug 域之间的路由规则存在循环：Bug 文档要求「先读需求接入规则」，需求接入规则又要求「历史缺陷转 Bug 域」。单看每条都对，连起来会让 agent 在两域之间来回跳转。

处理：保留两域各自的边界条款，删掉「收到任何相关内容都要求先回另一域」的强制措辞。

## 五、附带发现的结构问题

- **孤儿 reference**：全量扫描 636 份 references，发现 1 个自闭环死簇（`integration-map.md` → `cleanup-strategy.md` / `cleanup-triggers.md`）、4 个零引用文件、4 个误放在 `references/` 下的 `*-openai.yaml`、4 个有内容但未挂入口的文件。
- **注释格式无机器校验**：`comment-rules` 要求函数头必须带 `[参数]`/`[返回]`/`最近修改时间`，但没有任何脚本校验，全靠人工核对清单。实测 1,550 个函数中 609 个遵守、355 个有 docstring 但不带元信息，形成两套并存写法。
