# Codex Desktop 任务悬浮窗断点恢复实施总览

结论：保留既有任务投影恢复方案，并为没有活动悬浮窗但执行超时的任务增加第五实施周期；影响：简单任务执行较久后也能获得可见、可恢复的进度列表；范围：需求与验收文档、任务投影 Skill、相邻执行规则、`ensure-timeout` CLI、测试、字典和项目四件套；非范围：Desktop 产品代码、后台定时器、投影 schema 迁移和 Git 历史写入；变化：主动执行时间严格超过 600 秒时，当前会话按精确优先、固定三步兜底的规则补建悬浮窗；完成标准：十三个最小任务均按各自适用门禁闭环，第四周期的真实重启与第五周期的超时回归都通过后才正式放行；术语说明：本地实施分支是可以独立完成代码和自动测试、但不能替代另一分支人工验收的实施路径；验证状态：任务一至任务七和任务十已完成，任务八和任务九仍在第四周期等待真实宿主证据，第五周期下一执行点是任务十一。

## 风险与阻断项

- 工作树已有大量未提交改动；处理：每次编辑前核验 scoped diff，只做精确补丁。
- `PROJECT_CURRENT.md` 覆盖式维护可能删除托管区；处理：明确原样保留契约并用脚本窄范围更新。
- 严格追踪校验器当前硬编码旧来源；处理：改为按目标文档共同 `source_ids` 选域并补回归测试。
- 真实 Desktop 关闭重开需要用户操作；处理：本地契约完成后停在受限验收，重开后继续 `TASK-RTP-08`。
- `CYCLE-RTP-04` 尚未闭环而新增变更已经授权；处理：第五周期仅依赖已完成的 `CYCLE-RTP-01..03` 本地基础，作为独立分支推进，最终放行图明确要求第四、第五周期汇合，禁止把任务八、九伪报完成。
- 超时计时无法跨回合可靠持久化且不能后台唤醒；处理：只在当前执行上下文维护起点和暂停秒数，在工具返回、阶段进度和回合结束前检查；上下文丢失时停止升级而不猜测。
- exact 证据不足可能错投任务；处理：唯一正式来源和明确步骤提示同时成立才 exact，否则固定 fallback，并按 `session_id` 隔离。
