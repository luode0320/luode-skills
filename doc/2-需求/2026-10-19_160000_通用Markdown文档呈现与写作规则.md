## 目标与非目标

### 目标

1. 建立独立的公共 Markdown skill；
2. 统一 Markdown 文档的读者定位、结论顺序、层级、留白、密度、表格和图形规则；
3. 抽取 PPTX 中可以迁移到 Markdown 的表达原则；
4. 让需求、Bug、计划、架构、测试和交付 skill 通过路由复用公共规则；
5. 建立可验证、可回滚、可审查的 skill 资产变更链。

### 非目标

1. 不重写历史 Markdown；
2. 不改变领域业务语义；
3. 不改变 PPTX 的生成方式；
4. 不引入新的业务运行时；
5. 不创建图片生成和图片后处理链；
6. 不安装外部依赖；
7. 不执行 Git 历史写入。

## 功能需求与规则要求

### REQ-MD-DOC-AUTHOR-001-01：公共呈现 Owner

公共 skill 必须提供 Markdown 文档结构、正文与附录分层、层级、留白、密度、表格、代码块和图形选择规则。

- 输入：领域 skill 提供的业务目标、读者、范围、完成条件和证据；
- 处理：公共 skill 判断正文、附录、表格、Mermaid 和图片的表达方式；
- 输出：可读、可审查、可验证的 Markdown 文档；
- 异常：发现多个呈现 Owner、职责重复或引用循环时阻断；
- 验收：AC-MD-001、AC-MD-003、AC-MD-005。

### REQ-MD-DOC-AUTHOR-001-02：PPTX 原则适配

公共 skill 必须吸收内容优先、层次清晰、留白、对齐、对比度、图表自解释和最终视觉验收原则。

- 不迁移固定字号、英寸、页面比例、幻灯片布局和 OOXML；
- 验收：AC-MD-002。

### REQ-MD-DOC-AUTHOR-001-03：图形与图片选择

公共 skill 必须规定 Mermaid、表格和图片的选择边界。

- 流程、时序、状态、依赖、数据关系和风险分支使用 Mermaid；
- 图片只用于 UI、截图、真实产物、视觉对比或 Mermaid 无法表达的外观信息；
- 本需求与实施文档图片资产为 N/A；；原因：本轮不涉及业务运行时或图片资产；证据：当前需求文件范围和 visualization-standard.md。
- 验收：AC-MD-004、AC-MD-008。

### REQ-MD-DOC-AUTHOR-001-04：领域路由

需求、Bug、计划、架构、项目设计、测试和交付 skill 必须引用公共呈现 skill，但继续保留业务语义和验证职责。

- 验收：AC-MD-005、AC-MD-009。

### REQ-MD-DOC-AUTHOR-001-05：验证与交付

新增和修改的 skill 必须通过 quick validation、字典生成、引用检查、工程文档 profile、Mermaid 真实解析、skill 合规审计和测试后的 6-review。

- 验收：AC-MD-006、AC-MD-007、AC-MD-008、AC-MD-010、AC-MD-011、AC-MD-012。
