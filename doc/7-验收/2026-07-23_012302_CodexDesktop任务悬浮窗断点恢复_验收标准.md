# Codex Desktop 任务悬浮窗断点恢复验收标准

结论：在原有磁盘一致性、UI 重建和中断安全验收上，增加无悬浮窗任务超时升级的边界验收；影响：决定简单任务执行较久后能否获得稳定、无重复的进度展示；范围：主动执行时间计算、严格 600 秒边界、精确与兜底投影、原子写入、失败保护和兼容性；非范围：后台定时唤醒、投影 schema 变更和计时事实持久化；变化：验收从“已有投影能恢复”扩展为“没有投影且执行超时也能安全补建”；完成标准：新增四项验收的主路径、异常和边界场景全部得到二值断言；术语说明：精确投影是从唯一正式来源提取任务步骤，兜底投影是来源不唯一时使用的固定安全三步；验证状态：验收标准已冻结，实现证据由第五实施周期逐项补齐。

## 输入与预期结果

- 输入合法活动投影时，脚本输出与 `update_plan` 一致的 `steps` 列表和固定恢复说明。
- 输入过期指纹、来源不匹配或损坏投影时，命令非零退出且原文件哈希不变。
- 状态迁移 `pending -> in_progress -> completed` 时，磁盘先更新，随后工具 payload 与磁盘一致。
- 真实关闭重开后，用户发送“继续任务”，Agent 在领域动作前重建悬浮窗。
- 输入 599 秒、600 秒和 601 秒主动执行时间时，分别得到 `not_due`、`not_due` 和 `escalated`；暂停秒数先从墙钟差中扣除。
- 到期且来源唯一时返回 `mode=exact`；来源缺失、冲突或不唯一时返回固定三步 `mode=fallback`，两条路径都必须能从已写入磁盘的当前会话 projection 重新生成相同 payload。
- 当前会话已有活动 projection 时返回 `already_active`；非法 UTC 时间、观察时间早于开始时间、负暂停、暂停超过墙钟时长或损坏 registry 时非零退出且原文件哈希不变。

## 异常与边界条件

- 两个 `in_progress`、超过 20 步、单条超过 256 字符、未知字段、敏感字段和超 51,200 字节均拒绝。
- `update_plan` 不可用时，验收允许磁盘状态保留，但 UI 恢复判定失败，不能正式放行。
- 无法确认来源对象或中断点含未知幂等性写操作时，只恢复展示状态并暂停执行。
- 任务已完成、当前处于 Plan Mode、执行许可不是 `confirmed` 或当前 `session_id` 已有活动 projection 时，超时入口不得创建或替换投影。
- 恰好 600 秒仍属于未到期；只有计算结果严格大于 600 秒才允许升级。
- `started_at`、`observed_at` 必须为 UTC ISO-8601；`paused_seconds` 必须非负且不超过墙钟时长，否则拒绝并保持原文件字节不变。

## 范围外说明

- 范围外：修改 Desktop 本体、数据库或 UI 源码；依据：`BOUND-RTP-004`。
- 范围外：在用户没有发起新回合时自动运行 Skill；依据：Skills 不具备启动钩子。
- 范围外：恢复多个并行活动投影；依据：`BOUND-RTP-006`。
- 范围外：后台线程、系统定时器或无新检查点的第 601 秒自动唤醒；依据：`BOUND-RTP-008` 和 Skills 运行时能力边界。
- 范围外：把起始时间、观察时间或暂停秒数写入 v4 registry、projection 或项目长期状态；依据：`RULE-RTP-010`。
