# Codex Desktop 任务悬浮窗断点恢复验收标准

结论：在原有磁盘一致性、UI 重建和中断安全验收上，增加“首次持久化即刷新悬浮窗”的默认执行硬闸门验收，并把十分钟入口降为异常修复；影响：任何已确认执行任务都应在第一个领域动作前出现可恢复列表，避免会话运行很久仍无可见进度；范围：首次投影写入、立即 `update_plan`、UI 同步失败、活动/阻断/完成状态的可见性、session 解析和十分钟异常修复；非范围：后台定时唤醒、投影 schema 变更和计时事实持久化；变化：验收从“没有投影超时后补建”扩展为“默认先显示，超时只修复漏显示”；完成标准：新增四项验收的顺序、失败关闭、权限边界、会话冲突和真实 UI 场景均得到二值断言；术语说明：宿主同步阻断表示投影已保存但 UI 调用失败，不能当作悬浮窗已显示；验证状态：标准已冻结，实施周期 07 负责实现与回归，真实 Desktop 可见性仍可能受宿主阻断。

## 输入与预期结果

- 输入合法活动投影时，脚本输出与 `update_plan` 一致的 `steps` 列表和固定恢复说明。
- 输入过期指纹、来源不匹配或损坏投影时，命令非零退出且原文件哈希不变。
- 状态迁移 `pending -> in_progress -> completed` 时，磁盘先更新，随后工具 payload 与磁盘一致。
- 真实关闭重开后，用户发送“继续任务”，Agent 在领域动作前重建悬浮窗。
- 输入 599 秒、600 秒和 601 秒主动执行时间时，分别得到 `not_due`、`not_due` 和 `escalated`；暂停秒数先从墙钟差中扣除。
- 到期且来源唯一时返回 `mode=exact`；来源缺失、冲突或不唯一时返回固定三步 `mode=fallback`，两条路径都必须能从已写入磁盘的当前会话 projection 重新生成相同 payload。
- 当前会话已有活动 projection 时返回 `already_active`；非法 UTC 时间、观察时间早于开始时间、负暂停、暂停超过墙钟时长或损坏 registry 时非零退出且原文件哈希不变。
- 默认执行取得 `confirmed` 后，首个领域动作前先写入当前 session `active`/`blocked` projection；写入成功后的下一条工具动作必须是 `update_plan`，在其前不得出现领域写或委派。
- `update_plan` 模拟失败时，投影仍可从 `PROJECT_CURRENT.md` 读取，运行时结果为 `UI_SYNC_BLOCKED`，不把磁盘成功误报为 UI 成功，也不继续下一个领域写。
- `active` 和 `blocked` 都必须有悬浮任务列表；`inactive` 不得触发新列表；显式 `--session-id` 覆盖环境变量，冲突/缺失必须失败关闭。
- 首次列表缺失时，只有主动执行时间严格大于 600 秒且到达可执行检查点才允许走 `ensure-timeout`；该入口不是默认首次显示路径。

## 异常与边界条件

- 两个 `in_progress`、超过 20 步、单条超过 256 字符、未知字段、敏感字段和超 51,200 字节均拒绝。
- `update_plan` 不可用时，验收允许磁盘状态保留，但 UI 恢复判定失败，不能正式放行。
- 无法确认来源对象或中断点含未知幂等性写操作时，只恢复展示状态并暂停执行。
- 任务已完成、当前处于 Plan Mode、执行许可不是 `confirmed` 或当前 `session_id` 已有活动 projection 时，超时入口不得创建或替换投影。
- 恰好 600 秒仍属于未到期；只有计算结果严格大于 600 秒才允许升级。
- `started_at`、`observed_at` 必须为 UTC ISO-8601；`paused_seconds` 必须非负且不超过墙钟时长，否则拒绝并保持原文件字节不变。
- 默认执行持久化失败、来源无法确认或 session 冲突时，不执行领域写、不委派、不调用 `update_plan`，并保留原文件。
- `update_plan` 失败只允许进入 `UI_SYNC_BLOCKED`；不得删除刚持久化的 projection，不得把 active/blocked 变成 inactive，也不得用十分钟入口绕过 UI 阻断。
- Plan Mode、等待用户、许可非 `confirmed` 和任务已完成均不得创建 projection 或刷新主悬浮窗；子 Agent 只读或局部工作不得调用主 `update_plan`。
