## 检查步骤与证据

步骤由 `code-style-consistency-rules/scripts/static_owner_router.py` 按变更路径推导，退出码 0。

### STYLE-01 静态格式与编码一致性

- 变更文件尾随空白：`grep -cP '[ \t]+$'` 全部为 0。
- 换行与编码：`tr -cd '\r' | wc -c` 全部为 0（LF）；首三字节分别为 `23212f`、`2320e4`、`2d2d2d`、`222222`，均无 BOM。
- 过程更正：初次用 `grep -c $'\r'` 判断 CRLF 得到全文件命中，与 `git ls-files --eol` 显示的 `w/lf` 矛盾；改用字节统计确认 CR 为 0，前一次为 Git Bash 正则处理造成的误报，已按字节证据定论。
- 结论：与 `.gitattributes` 的 `*.sh text eol=lf` 及仓库其余文件一致，无格式跳变。

### STYLE-02 命名与符号引用一致

- 新增脚本函数 `run_compile_command`、`compile_python_staged`、`compile_gate` 与既有 `staged_name_only` 同为「动词 + 对象」的小写下划线风格。
- 新增测试类 `CompileGateTests`、`CommitScopeGateTests`、`GateTestCase` 与既有 `PreCommitGateTests` 同为 `*Tests` 后缀。
- 测试方法统一 `test_<对象>_<行为>`，与拆分前既有 5 个用例同构。
- 结论：无同义不同名，无命名跳变。

### STYLE-03 注释分层与定义位置

- 三个新增脚本函数均具备完整函数头三层（`[参数]` / `[返回]` / `最近修改时间` 含一句话说明）。
- 方法体使用 `# 1)` `# 2)` `# 3)` 步骤编号；测试方法统一 `# 1.` `# 2.`。
- 字段与行内位置只写一句话作用，未平摊完整函数头格式。
- 发现并修复：`compile_gate` 在后续改动（node 三态判定、tsc 分支压缩）后，函数头「最近修改时间」仍为 `2026-10-22 10:20:00`；已更新为 `2026-10-22 10:40:00` 并改写说明为该轮真实变化。
- 结论：修复后 PASS。

### STYLE-04 函数签名与参数结构

- 脚本函数入参均 ≤ 2（`run_compile_command` 为 label + 透传命令，其余无参），无多行签名。
- 测试 `run_gate` 新增 `fake_node` 为关键字参数，总数仍为 3 个具名参数且均为关键字传递，未用多行签名代替收敛。
- 结论：符合，不构成结构体化触发条件。

### STYLE-05 结构与落点

- 编译闸门逻辑落在 `git-collaboration-rules/scripts/pre_commit_gate.sh`（该 skill 自有脚本位置），未新建平行脚本。
- 细则文档落在 `git-collaboration-rules/references/`，与同目录既有 `pre-post-gates.md` 等并列。
- 测试落在根 `test/git-collaboration-rules/`，镜像被测 skill 目录。
- 结论：落点未越界。

### STYLE-06 公共复用与工具落点

- 复用既有 `staged_name_only` 取 staged 文件，未重复实现中文路径处理。
- `run_compile_command` 收敛了原本会重复三次的「探测命令 + 超时 + 输出」逻辑，按最小实现阶梯判断为必要收敛。
- 结论：无同语义重复封装，未引入项目未使用的新依赖。

### STYLE-08 语言与框架特异写法

- Shell：使用 `set -euo pipefail`；`local -a` 数组；命令经数组传递避免分词；未使用 `eval`；错误输出走 `>&2`。

- Python 测试：使用 `from __future__ import annotations`、`unittest`、显式 `encoding="utf-8"`，与拆分前一致。
