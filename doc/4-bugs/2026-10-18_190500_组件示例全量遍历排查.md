# 组件示例全量遍历排查 Bug 主文档

结论：对组件库示例页做了逐组件、逐示例的全量遍历体检（101 个页面、749 张示例卡），在既有守卫覆盖的「可见性 / 逐格提示 / 内容留白 / 边角遮挡 / 投影裁切」之外，又查出 11 个真实缺陷和 1 个上游冻结面缺陷；影响：其中 1 个是系统性缺陷——749 张卡里 341 条可点事件的处理器根本没接上，用户点了关闭、确认、提交、复制、切换等按钮后界面毫无反应，示例页因此失去核对价值，另有 1 条长期守卫因自身选择器写错而常年报红、1 组示例因把文字当图片地址而显示裂图、浅色主题下加载遮罩文字对比度只有 1.46、排版组件的复制按钮在剪贴板不可用时静默失败；范围：示例变体生成器、示例层受控状态、6 个组件的实现与声明、1 条长期守卫的作用域、1 处残留目录；非范围：组件的既有业务语义、上游 139 个冻结文件、Arco 品类对齐口径、分类真相源结构；变化：变体生成器改为深度感知地识别数组枚举并回退到嵌套元素类型，示例层按派生事件表为全部声明事件补齐带回写的通用反馈处理器，`TreeSelect` 的类型声明放宽到与实现一致，`Comment` 头像示例改用真实图片地址，`Image` 放大控件补齐可访问名与空格激活，`Spin` 遮罩文字改用随主题翻转的墨色令牌，`CollapseItem` 增加无父级时的本地开合态，`Typography` 改为复用库内既有复制工具并把失败结果落到图标与可访问名上，帮助提示守卫的作用域收窄到示例卡内容区，删除残留缓存目录；完成标准：全部守卫（含本轮新增 3 条）在浅色与暗色主题下同时绿灯、示例卡总数与派生表一致、类型检查零报错、单元测试全通过、生产构建成功、测试污染扫描放行；术语说明：出卡指组件根元素完全落在示例卡内容区可视矩形之外，受检事件指守卫纳入判定的非 `update:` 声明事件，豁免指事件的可观察结果本来就在组件自身形态上因而不需要额外反馈；验证状态：已用运行时真实点击、双主题全量扫描、事件接线遍历、几何与对比度实测、剪贴板授权与未授权双上下文取证、类型检查、单元测试、生产构建和污染扫描共同确认。

## 1. 结论

全量遍历 101 个页面、749 张示例卡后，共确认 11 个真实缺陷，另有 1 个缺陷位于上游冻结面，本轮只登记不修改。

| 编号 | 缺陷 | 性质 | 影响面 |
| --- | --- | --- | --- |
| BUG-01 | 帮助提示长期守卫选错了被测对象，常年报红 | 守卫自身缺陷 | 1 条守卫失效 |
| BUG-02 | 变体生成器把数组枚举属性当标量派生 | 生成器缺陷 | `Trigger` 等组件产出非法示例并触发 Vue 属性告警 |
| BUG-03 | 变体生成器从嵌套联合类型里误取枚举 | 生成器缺陷 | `SpecPlate` 产出与基础示例完全相同的重复格 |
| BUG-04 | `TreeSelect` 的值类型声明窄于实现，被迫用 `as any` 绕过 | 组件声明缺陷 | 类型契约失真，调用方按声明写会编译失败 |
| BUG-05 | `Comment` 头像示例把文字「罗」当图片地址 | 示例数据缺陷 | 1 格裂图，浏览器发出 `/gallery/display/罗` 的 404 请求 |
| BUG-06 | `Image` 放大控件有 `role="button"` 却没有可访问名，也不响应空格 | 无障碍缺陷 | 5 格读屏无名、键盘用户少一种激活方式 |
| BUG-07 | 浅色主题下 `Spin` 遮罩文字对比度仅 1.46 | 主题令牌误用 | 浅色主题下加载提示几乎不可读 |
| BUG-08 | 示例层只给 `update:` 事件建了回写，其余声明事件全部没接处理器 | 系统性缺陷 | 749 卡中 341 条可点事件点了没反应 |
| BUG-09 | `CollapseItem` 脱离 `Collapse` 单独挂载时点不开 | 组件实现缺陷 | 单独使用的折叠项完全失效 |
| BUG-10 | 示例目录下残留 456K 的 `.npm-cache` | 交付残留 | 污染仓库目录 |
| BUG-11 | `Typography` 复制在剪贴板不可用时静默失败，且重复实现了库内已有的复制工具 | 组件实现缺陷 | 复制按钮退化成点了没反应的死按钮 |
| DEF-01 | GSAP 在每个示例页都打印空目标告警 | 上游冻结面缺陷 | 101 页控制台噪声，本轮只登记 |

其中 BUG-08 是本轮最重要的发现：它不是某个组件的问题，而是示例层受控状态的设计遗漏，导致近半数示例卡的交互按钮形同摆设。

## 2. 症状

- 点 `Alert` 的关闭按钮、`Popconfirm` 的确认/取消、`Form` 的提交、`Typography` 的复制、`Tabs` 的关闭、`Upload` 的移除、`Topbar` 的五个入口、`Sidebar` 的导航、`ShortcutGrid` 的选项、`DropdownButton` 的点击与选择，界面没有任何变化，控制台也没有输出。
- `/gallery/display/comment` 的「带头像」示例里头像位置是裂图占位，浏览器网络面板出现一条对 `/gallery/display/罗` 的 404 请求。
- 浅色主题下 `Spin` 的包裹态遮罩里，提示文字与半透明浅色蒙版几乎同色，肉眼难以分辨。
- `python frontend-design/scripts/check_help_tip_interaction.py` 长期输出 `HELP_TIP: FAIL`，但人工在页面上悬停、聚焦、按 Esc 收起帮助气泡，八项交互逐项都能观察到预期结果。
- `/gallery/feedback/trigger` 的部分示例在控制台触发 Vue 属性类型告警；`SpecPlate` 出现两格渲染结果完全相同的示例。
- `/gallery/display/collapse` 里单独挂载的 `CollapseItem` 点击标题栏没有展开反应。
- 每个示例页控制台都有一条 `GSAP target [object NodeList] not found.`。
- `frontend-design/component-library/src/views/gallery/.npm-cache/` 存在一个 456K 的目录，与示例页无任何关系。
- `/gallery/general/typography` 的复制按钮点下去没有任何变化：图标不翻、无提示、控制台无输出；库内 `@/utils/clipboard` 已有 `copyText` 且被 `GeneratorPipeline` 使用，`Typography` 却自己重写了一份并在失败分支里静默吞掉。

## 4. 诊断证据

| 判据 | 取证方式 | 实测结果 |
| --- | --- | --- |
| 帮助提示守卫作用域 | 读守卫源码选择器并在页面实测 | 守卫用 `.x-help` 命中了卡片头自带的说明图标，被测组件自己的帮助图标从未进入判定 |
| 数组枚举派生 | 对比生成器输出与组件 `defineProps` 声明 | `Trigger.trigger` 声明为 `Array<'click'\|'hover'\|'focus'\|'contextmenu'>`，生成器却派出标量 `'hover'`，触发 Vue 属性告警 |
| 重复格 | 生成器差异指纹比对 | `SpecPlate.rows` 的元素类型里嵌了一个 `tone` 联合，生成器把嵌套联合当顶层枚举，派生出与基础格渲染结果相同的示例 |
| `TreeSelect` 声明 | 读组件源码与 `emit` 调用 | 实现会回传 `Array<string \| number>` 与 `null`，声明只有 `string \| number`，两处被迫写 `as any` |
| 裂图 | 运行时读 `img.currentSrc` 与网络请求 | `src` 解析为 `/gallery/display/罗`，返回 404，`naturalWidth` 为 0 |
| 无障碍 | 运行时遍历 `[role="button"]` 取可访问名与键盘处理器 | `Image` 的放大控件无可访问名，只绑了 `Enter`，未绑 `Space` |
| 对比度 | 逐层 alpha 合成后按 WCAG 相对亮度算比值 | 浅色主题 `Spin` 遮罩文字实测 1.46，低于守卫阈值 1.5；暗色主题充足 |
| 事件接线 | 从 `body.__vueParentComponent.subTree` 遍历 vnode 子树取组件实例的 `on*` 属性 | 修复前 749 卡中 341 条受检事件全部无处理器；`update:` 类由样本状态回写覆盖，不在判据内 |
| 折叠项 | 读组件源码 `inject` 分支 | `open` 完全依赖注入的父级上下文，无父级时 `ctx` 为 `null`，点击只调用 `ctx.toggle` 因而抛空 |

| 残留目录 | 目录列举与体积测量 | `src/views/gallery/.npm-cache/` 共 456K，无源码引用 |
| 复制静默失败 | 双上下文真实点击并读按钮类名、可访问名与计算色 | 未授予剪贴板写权限时点击后类名仍为 `x-typo-copy`、可访问名仍为「复制」、颜色无变化、无提示；授予权限时同一次点击可读到提示文案「Typography 触发 copy」，证明失败分支被 `catch {}` 整段吞掉 |
| 复制工具重复实现 | 全库检索剪贴板调用点 | `navigator.clipboard` 的直接调用只有 `Typography.vue` 一处，而 `src/utils/clipboard.ts` 的 `copyText` 已存在且被 `GeneratorPipeline.vue` 使用，两处口径不一致 |

## 5. 根因

- BUG-01：守卫的选择器没有区分「卡片头自带的说明图标」与「本格示例正在演示的帮助图标」，两者类名相同，`querySelector` 取到的是前者。
- BUG-02 / BUG-03：变体生成器用一个朴素的字面量扫描器识别枚举，它按 `|` 切分时不感知括号深度，既会把 `Array<'a'|'b'>` 的外层当成顶层联合而丢掉数组语义，也会把元素类型里的嵌套联合误当成顶层枚举。
- BUG-04：`TreeSelect` 先写了单选实现，后补多选能力时只改了实现没回头放宽声明，用 `as any` 压住了编译错误。
- BUG-05：示例样本把「头像」当成文字缩写填了个汉字，而组件的 `avatar` 属性是图片地址。
- BUG-06：`Image` 的放大控件是后来补的语义化 `role="button"`，只补了角色没补可访问名，键盘激活也只写了 `Enter`。
- BUG-07：`Spin` 遮罩的背景用了随主题翻转的 `--overlay`，但文字用了只在深色底板上成立的 `--plate-ink` / `--plate-soft`；浅色主题下蒙版变浅，深色底板令牌却不变，两者叠加导致对比度塌陷。
- BUG-08：示例层的受控状态只按「样本里已有的属性键」派生 `onUpdate:<键>` 回写，从未消费组件声明的其余事件；组件声明了 `close`、`confirm`、`submit`、`copy` 等事件，示例层没有对应处理器，事件发出后无人接收。
- BUG-09：`CollapseItem` 把开合态完全托付给 `inject` 到的父级上下文，没有为「单独使用」这一合法用法准备本地兜底。
- BUG-10：前序会话在示例目录下执行过一次 npm 操作，缓存目录未被清理。
- BUG-11：`Typography` 的复制没有复用库内既有的 `copyText`，而是就地写了一份 `navigator.clipboard.writeText`，并把失败整段放进空 `catch`；组件自身只有「成功」一个视觉状态（`copied` 翻对勾），没有失败状态，于是失败路径对用户完全不可见。
- DEF-01：上游 `motion.ts` 的入场动画对两个选择器分别处理，其中一个漏了空集合守卫。该文件属 139 个冻结文件之一，本轮不修改。

## 9. 未覆盖说明

- DEF-01（GSAP 空目标告警）位于上游 139 个冻结文件之内，本轮只登记豁免与上游修法，未修改；重新冻结上游后应删除该条豁免。
- 体检守卫的对比度判据在文字与不透明底之间存在渐变或图片背景时跳过判定（`measurable = false`），这类位置的低对比度需要人工目检，不在自动化范围内。
- 事件接线守卫只判「声明事件是否有处理器」，不判处理器内部行为是否正确；处理器语义由真实点击取证覆盖，未做全量逐事件语义断言。
- 8 类豁免事件（`Image.load`、`Image.error`、`Countdown.change`、`Upload.progress`、`RelationGraph.hover`、`ResizeBox.resize`、`SplitPane.resize`、`Carousel.change`）不产生额外提示，其可观察结果本就在组件形态上；豁免表由守卫自测核验是否陈旧。
- 交互遍历不覆盖需要拖拽轨迹、需要真实文件选择、需要真实网络上传的示例；这些示例只验证了接线，未验证端到端行为。
- 上游组件的业务语义正确性不在本轮范围，本轮只判「示例是否可用、可见、可操作、可读」。
- BUG-11 只把失败结果变可见，没有为 `@/utils/clipboard` 增加降级写入通道（如临时文本域加 `execCommand`）。该工具是 `Typography` 与 `GeneratorPipeline` 的共用入口，加降级会同时改变两处的行为语义，属独立决策；本轮的取舍是「宁可明确告知不支持，也不引入已废弃接口」。若后续确实需要在非安全上下文的 http 站点上支持复制，应在 `copyText` 一处补降级并同步两处调用方的提示文案。

## 11. 排查过程中修正的判据与设计错误

| 错误 | 表现 | 修正 |
| --- | --- | --- |
| 用 `el._vei` 读已绑定的事件处理器 | 该构建里 `_vei` 恒为空，全部示例被判成未接线 | 改用 `el.__vnode.props` 的 `on*` 键，并用已知接线（Switch/Tabs/Checkbox）与已知未接线（Button）双向校验 |
| 交互判据按「点了有没有 DOM 变化」 | 247/906 被判死，其中大量是纯布局演示按钮、未改值的输入、已激活控件和拖拽手柄 | 改为按声明事件是否接了处理器判定，把「有没有反馈」交给真实点击取证 |
| 按 DOM 遍历查找被演示组件实例 | Teleport 到 `body` 且关闭态未渲染的 8 个组件共 48 处误报 | 改为从 `body.__vueParentComponent.subTree` 遍历 vnode 子树，覆盖 `component`、数组 `children` 与 `suspense.activeBranch` |
| 事件名直接比对处理器名 | `row-click` 与 `onRowClick` 全量误报 | 增加 `norm()` 去掉 `-` 与 `:` 后小写比对 |
| 对比度判据跳过半透明祖先 | `Spin` 读到 1.07 而真实是 1.46，量级失真 | 改为逐层 alpha 合成到不透明底 |
| 对比度判据不认渐变背景 | `RelationGraph` 核心标签读 1.07，实为深底板配浅文字 | 增加 `measurable` 标记，中间存在渐变或图片背景时不判定 |
| 裁切判据不豁免视觉隐藏文本 | `.sr-only` 的 4 处「环比」被误报裁切 | 增加视觉隐藏豁免 |

| 用 `python -c` 就地改探针脚本 | 字符串转义被破坏，报 `unterminated string literal` | 删除文件改用编辑器整文件重写 |
