# Panel 内容贴边 Bug 主文档

结论：组件库 `Panel` 的默认插槽内容没有内边距，文字左右与底部直接贴到面板边框；影响：示例页 `/gallery/layout/container` 的 4 张 Panel 卡；范围：一条本地样式覆盖与一个新守卫；非范围：上游冻结组件模板、其他组件的既有排版语义；变化：给「除标题区外的直接子元素」补 20 像素左右与底部留白；完成标准：Panel 文字四周留白不小于 20 像素、全量 750 张示例卡扫描无同类贴边、阳性对照能精确复现、其余守卫全绿；术语说明：文本字形矩形指用 Range 测得的文字实际占据区域，区别于元素盒；验证状态：已用运行时几何、全量扫描与阳性对照验证通过。

## 1. 结论

截图里的「文字跑到输入框外面」不是元素溢出，而是**内容区根本没有留白**。

`Panel` 的模板结构是 `<section class="panel">` 里先放 `header.panel-head`，再把 `<slot />` 直接挂在 section 下。`components.css` 里确实定义了 `.panel-body { padding: 0 20px 20px }`，但模板从未使用这个类，于是默认插槽里的 `<p>` 成为 section 的直接子元素，左右与底部都贴着边框。标题区因为有 `padding: 14px 20px` 看起来没问题，正文却没有，落差就出现了。

修复放在本地覆盖层 `overrides.css`：给 `.panel > :not(.panel-head)` 补左右 20 像素与底部 20 像素，无标题时首个子元素再补上边距。不动上游冻结模板。

## 2. 症状

- `/gallery/layout/container` 的 4 张 Panel 示例卡中，正文「面板内容：承载一组相关读数与操作。」左右与底部贴到面板边框。
- 有标题的卡片标题行看起来对齐，正文没有留白，形成明显错位。
- 无标题卡片整块内容贴着上边框。

## 3. 复现步骤

1. 启动组件库：双击 `frontend-design/component-library/启动组件库.bat`，或执行 `npm run dev`。
2. 用任意账号密码登录（本地 mock 放行）。
3. 打开 `/gallery/layout/container`。
4. 观察 Panel 四张示例卡：正文左右与底部与面板边框距离为 0。

稳定性：稳定复现，与数据、视口宽度无关。

## 4. 诊断证据

| 证据 | 来源 | 结论 |
| --- | --- | --- |
| 实测 `panel > P` 的 pads = `{l:0, r:0, b:0}`，`t:60`（标题区高度） | 浏览器 `getBoundingClientRect` 逐边比对 | 左右与底部完全没有留白 |
| 模板 `<section class="panel">` 内只有 `header.panel-head` 与裸 `<slot />` | `src/components/ui/Panel.vue` 第 9 至 20 行 | 默认插槽没有内容区包裹层 |
| `components.css` 定义了 `.panel-body { padding: 0 20px 20px }`，但全仓库无任何 `.panel-body` 使用 | `grep -rn "panel-body" src/` 返回空 | 样式写了却从未被消费，属上游模板遗漏 |
| 标题区 `.panel-head` 有 `padding: 14px 20px` | `src/styles/components.css` 第 332 行 | 解释了「标题有留白、正文贴边」的落差 |

## 5. 根因

上游 `Panel.vue` 把默认插槽直接挂在根元素下，内容区包裹层缺失；对应的 `.panel-body` 样式成了死样式。组件级修复需要改冻结模板，因此改为在本地覆盖层用结构选择器补留白。

## 6. 修复

| 项 | 内容 |
| --- | --- |
| 落点 | `src/styles/overrides.css`（本地覆盖层，已由 `main.ts` 缝隙行引入） |
| 规则 | `.panel > :not(.panel-head)` 补左右 20 像素、底部 20 像素；`:first-child` 补上 20 像素 |
| 为什么用 margin 而非 padding | 不改变子元素自身盒模型，避免影响组件内部的背景与描边 |
| 为什么不改模板 | `Panel.vue` 属 139 个上游冻结文件，任何改动都会让 `FIDELITY` 报 `DRIFTED` |
| 回滚 | 删除该段规则即可，无其他依赖 |

## 7. 全量排查

用户要求「检查所有组件是否也有同样的问题」，因此新增守卫 `frontend-design/scripts/check_content_padding.py`：

- 路由从分类真相源 `component-categories` 派生（101 个三级示例页），不手写清单。
- 对每张卡里「四边有可见边框或带非透明背景」的卡片类容器，用 Range 取内容区直接子元素的文本字形矩形，与容器边框内沿比对。
- 左右或底部贴边（小于 1 像素）判 FAIL。
- 表格单元格、泳道、分页、交互控件、自身可滚动的容器按语义豁免。

首轮扫描 750 张示例卡共命中 21 处，逐条甄别后只有 Panel 的 4 处是真实缺陷，其余为按钮内边距、栅格贴边、外壳滚动等既定语义。收紧判据后全量扫描 `CONTENT_PADDING: PASS`。

## 8. 验证

| 项目 | 结果 |
| --- | --- |
| 修复后 Panel 几何 | `panel > P` pads = `{l:21, r:21, b:21}`，标题区仍为 20 像素 |
| 全量扫描 | `CONTENT_PADDING: PASS (扫描 750 张示例卡，无文本贴边)` |
| 阳性对照：移除覆盖层 Panel 规则 | `FAIL (4 处贴边)`，全部为 `panel.m-surface > P`；恢复后 `PASS` |
| 上游还原度 | `FIDELITY: PASS (261 local / 139 upstream-tracked)` 加 2 条 `SEAM` |
| 测试污染 | `POLLUTION: PASS` |
| 投影留白与边角 | `SHADOW_CLIP: PASS`、`CORNER_OCCLUSION: PASS (112 页)` |

## 9. 未覆盖说明

- 判据只覆盖「卡片类容器 + 直接子元素文本」：更深层级的贴边属子组件自身排版（表格单元格、泳道标签等），不纳入本轮判定。
- 顶部方向不判：`inline-flex` 居中排布的行内控件（如勾选框标签）字形与容器顶沿对齐属行内居中对齐。
- 守卫依赖本地开发服务与 Python Playwright；CI 环境若未安装 Chromium，需先执行 `python -m playwright install chromium`。

## 10. 完成标准

本 Bug 以「截图中 Panel 文字回到框内」且「全部组件页面无同类缺陷」为完成标准，逐项对照如下：

| 标准 | 判定方式 | 实际结果 |
| --- | --- | --- |
| 截图中 Panel 正文左右与底部回到框内 | 运行时测量 `panel > P` 三向留白 | 均为 21 像素 |
| 无标题面板不贴上边框 | `:first-child` 补上边距 | 已覆盖 |
| 所有其他组件无同类缺陷 | 内容留白守卫扫描全部示例页 | 750 张卡全部 `PASS` |
| 守卫能真实抓到该缺陷 | 移除修复后必须转 `FAIL` | 精确报出 4 处 `panel > P`，转 `FAIL` |
| 守卫不误报既定排版语义 | 全量扫描应无假阳性 | 收紧判据并修正排除面后为 0 |
| 无上游漂移 | 还原度守卫剥离缝隙后逐字节相等 | `FIDELITY: PASS`（261 本地 / 139 上游） |
| 无测试污染 | 污染扫描 | `POLLUTION: PASS` |

## 11. 排查过程中修正的判据错误

| 错误 | 表现 | 修正 |
| --- | --- | --- |
| 路由写死为二级路径 | 扫描到 0 张卡却输出 `PASS` | 改为从分类真相源派生 101 个三级路由，并对 0 卡页单独判失败 |
| 用元素盒而非文本字形 | 按钮、标签等自带内边距的控件被误报 | 改用 Range 取文本字形矩形 |
| 把 `.workspace` 写进排除面 | 示例页就渲染在 `.workspace` 内，阳性对照整页失效 | 删除该排除项，只保留表格、泳道、分页与交互控件 |
| 判据取四边最小值 | 顶部对齐会掩盖左右贴边 | 改为左右加底部三向分别判定 |
