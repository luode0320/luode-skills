# 组件边角方角缺口 Bug 主文档

结论：应用外壳左上、左下两个角上多出来的浅色小方角，是导航轨作为直角子元素把外框 10 像素深色描边盖掉造成的；影响：所有带外壳的页面（含全部 101 个组件示例页与业务页）都会在左上、左下角出现同一缺口；范围：一处本地样式覆盖与一条新守卫；非范围：组件造型、示例数据、上游冻结样式内容；变化：给导航轨补上与外框内弧一致的 28 像素圆角，外框描边恢复连续；完成标准：外壳四角描边连续、全量菜单页无同类遮挡、类型检查与单测与构建与还原度与污染扫描全部通过；术语说明：内弧指外框圆角内侧的弧线半径，等于外弧减去描边宽度；验证状态：已用像素剖面、全量运行时扫描与两条阳性对照验证通过。

## 1. 结论

用户截图圈出的「透明边角」不是透明度问题，而是**外框圆角内侧的深色描边被一个直角子元素盖住了**。

应用外壳由三层叠成：最外层是 10 像素宽、38 像素圆角的深色描边；往里是导航轨，它带一层半透明玻璃底；再往里是工作区。导航轨是矩形的，从内边距的左上角开始铺满，正好压在深色描边的内弧上。圆角处本来应该由描边画出一段弧线，被导航轨的直角盖掉后就断开了，露出底下浅色的舞台底色，看上去像多出来一块方角。

修复只需一步：把导航轨靠外框的那两个角补上圆角，半径取外框内弧的值（38 减 10 等于 28 像素）。描边恢复连续，方角消失。

## 2. 症状

- 应用外壳左上角、左下角各有一小块浅色方角，与深色外框的圆弧不连续。
- 该缺口在组件示例页、业务页、任何带外壳的页面都出现，位置固定。
- 组件本身看不出问题，只有套在深色外框里才暴露。

## 3. 复现步骤

1. 启动组件库后台：`cd frontend-design/component-library && npm run dev`，打开 `http://localhost:5173/`。
2. 用 `admin / admin123` 加页面显示的验证码登录。
3. 打开「外壳与系统 → 应用外壳」（`/gallery/shell/frame`）。
4. 放大观察第一张示例卡里深色外壳的左上角，可见圆弧中断、露出一块浅色方角。

稳定性：稳定复现，与数据、账号、缩放无关。

## 4. 诊断证据

| 证据 | 来源 | 结论 |
| --- | --- | --- |
| 外框声明 `border: 10px solid var(--frame)`、`border-radius: 38px`、`overflow: clip` | `src/styles/layout.css` `.app-frame` | 外弧 38、描边 10，内弧应为 28 |
| 导航轨 `.rail` 无圆角，且带 `.m-rail` 的 `rgba(250,251,250,.92)` 玻璃底 | `src/styles/layout.css` `.rail` + `src/styles/materials.css` `.m-rail` | 直角子元素从内边距左上角铺满，会盖住内弧 |
| 修复前逐行取色：y=304–307 四行**完全检测不到深色描边**，y=303 有、y=308 恢复 | 1920 宽视口截图，按外框色 `(23,25,29)±6` 逐像素判定 | 描边在角部真实断开，不是主观感受 |
| 两次独立截图在 y=304–307 均为空 | 重复截图对比 | 缺口稳定，非动画中间态 |
| 给 `.rail` 加 28px 圆角后，同四行恢复为 397/396/395/395 | 浏览器内临时改样式后复测 | 圆角补齐即恢复连续弧线 |
| 2 倍像素密度下 45 度剖面：舞台灰 -> 深色描边 -> 内部浅色，过渡连续无断口 | Playwright 元素截图 + 像素采样 | 修复后角部完整 |

## 5. 根因

**几何遮挡**：外框的圆角只作用于它自己绘制的描边与背景，不会自动裁剪子元素。导航轨是外框的第一个子元素，位置正好从描边内侧开始，自身又是直角，于是把圆角内侧那段本该由描边占据的区域盖成了自己的直角边缘。

`overflow: clip` 只裁到外框的外接矩形，不裁到圆角弧线，所以对子元素无效。

## 6. 修复

在本地样式覆盖层 `src/styles/overrides.css` 增加一条规则：在存在深色外框的宽度（≥821 像素）下，给 `.app-frame > .rail` 补 `28px` 的左上、左下圆角。

- 28 = 外弧 38 − 描边 10，与内弧严格相等，内外弧同心。
- ≤820 像素时上游把外框改成贴边全屏（描边 0、圆角 0），此时内弧也是 0，补圆角反而会切掉本应贴边的导航轨，所以加媒体查询限定。

上游 `src/styles/*.css` 逐字节冻结，修复只能落在本地覆盖层；覆盖层由 `main.ts` 的声明式缝隙行引入，`verify_fidelity.py` 剥离该行后要求与上游逐字节相等。

## 7. 全量排查

新增守卫 `frontend-design/scripts/check_corner_occlusion.py`，在真实浏览器里逐页扫描全部菜单页，按两条判据检查：

| 判据 | 含义 | 触发条件 |
| --- | --- | --- |
| `border-occluded` | 粗描边父级的内弧被直角子元素盖住 | 父级描边 ≥3px，子元素该角圆角 < 内弧 |
| `corner-mismatch` | 有背景的圆角父级下，方角子元素外露 | 父级不裁剪（`overflow` 非 hidden/clip），子元素该角圆角 < 父级外弧 |

父级自身 `overflow: hidden/clip` 时，子元素方角会被裁到圆角以内，不构成缺陷，判据主动跳过。这一条是必要的：初次全量扫描曾把 `.x-desc-body > .x-desc-item`、`.x-notify > .x-notify-bar`、`.org-canvas > .org-dots` 三组共 20 处报为缺陷，逐一核对后确认它们的父级都开启了裁切，方角不会外露，属误报。

全量结果：**112 个菜单页全部通过**，无第二处同类缺陷。
