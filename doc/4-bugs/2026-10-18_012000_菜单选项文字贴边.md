# 菜单选项文字贴边 Bug 主文档

结论：组件库 `Menu` / `MenuNode` 的选项块只设了左内边距，没有右内边距，横向模式下文字末尾直接贴到选中底色块的右边缘；影响：示例页 `/gallery/navigation/menu` 的横向菜单与浮层子菜单，以及所有复用 `MenuNode` 的页面；范围：`MenuNode.vue` 一条样式声明与内容留白守卫的判据升级；非范围：菜单的选中、展开、浮层定位等既有行为，上游冻结模板；变化：给选项块补 10 像素右内边距，与左内边距同值；完成标准：横向菜单选项左右留白均不小于 10 像素、全量 750 张示例卡扫描无同类贴边、阳性对照能精确复现、其余守卫全绿；术语说明：文本字形矩形指用 Range 测得的文字实际占据区域，区别于元素盒；验证状态：已用运行时几何、全量扫描、阳性对照与截图复验通过。

## 1. 结论

截图里「文字末尾几乎贴到选项边缘」不是文字溢出，而是**选项块缺了右内边距**。

`MenuNode` 的选项是一个 `button.x-menu-item`，左内边距由行内样式按层级缩进动态给出（`paddingLeft: 10 + depth * 14`），但样式块里从未声明 `padding-right`。纵向模式下按钮宽度撑满容器，右侧多出的空白把问题掩盖了；横向模式下按钮宽度贴合内容（`width: 100%` 在 flex 行内退化为内容宽），文字末尾就正好落在按钮右边缘，而按钮的选中态底色块与按钮同宽，于是视觉上文字贴到色块边缘。

修复只需给 `.x-menu-item` 补一条 `padding-right: 10px`，与左内边距的基础值同值。

## 2. 症状

- `/gallery/navigation/menu` 的 `Menu mode=horizontal` 卡片中，选中项「用户管理」的文字末尾与蓝色底色块右边缘距离为 0。
- 同一卡片的「角色管理」「监控中心」悬停时出现底色块，文字同样贴右边缘。
- `MenuNode` 浮层子菜单因按钮撑满 154 像素宽，问题不明显，但样式上同样缺右内边距。
- 纵向菜单看不出问题，是因为按钮撑满容器宽度，右侧剩余空间足够。

## 3. 复现步骤

1. 启动组件库：双击 `frontend-design/component-library/启动组件库.bat`，或执行 `npm run dev`。
2. 用任意账号密码登录（本地 mock 放行）。
3. 打开 `/gallery/navigation/menu`。
4. 观察第二张卡 `Menu mode=horizontal`：选中项的文字末尾与底色块右边缘距离为 0。

稳定性：稳定复现，与数据无关；横向模式必现，纵向模式因容器撑满而不可见。

## 4. 诊断证据

| 证据 | 来源 | 结论 |
| --- | --- | --- |
| 横向模式选项实测 `w=87`，文字字形距左 35 像素、距右 0 像素 | 浏览器运行时探针量取 `getBoundingClientRect` 与 Range 字形矩形 | 右内边距缺失 |
| 计算样式为 `padding: 10px / 0px` | 同一探针读取 `getComputedStyle` | 左有值、右为 0 |
| 纵向模式选项实测 `w=258`，右侧剩余 171 像素 | 同一探针 | 解释了「纵向看不出问题」的假象 |
| 模板只有 `:style="{ paddingLeft: indent }"`，样式块无 `padding-right` | `src/components/extend/MenuNode.vue` 第 78 行与第 111 至 122 行 | 右内边距从未声明 |
| 同目录 `TreeNode.vue` 与 `TreeSelect.vue` 均已有 `padding-right: 10px` | `grep -n padding-right` 命中两处 | 说明这是同一类缩进列表的既有写法，`MenuNode` 是遗漏 |

## 5. 根因

`MenuNode` 用行内 `paddingLeft` 承载层级缩进，把左右内边距拆成了两套来源：左侧由数据驱动、右侧依赖样式块。样式块里只写了高度、圆角、字号等，漏掉了 `padding-right`。纵向模式靠容器撑满掩盖了这个遗漏，横向模式把按钮收窄到内容宽度后立即暴露。

## 6. 修复

| 项 | 内容 |
| --- | --- |
| 落点 | `src/components/extend/MenuNode.vue` 的 `.x-menu-item` 样式块 |
| 规则 | 补 `padding-right: 10px`，与行内缩进的基础值 10 像素同值 |
| 为什么不改行内样式 | 行内样式只承载随层级变化的左缩进；右内边距是固定值，属于样式块职责，写进行内会让每次缩进计算都重复一次常量 |
| 是否触及冻结面 | 否，`extend/` 为本地扩展层，不在 139 个上游冻结文件内 |
| 回滚 | 删除该声明即可，无其他依赖 |

## 7. 全量排查

用户要求「检查所有组件是否还有这种问题」，因此把内容留白守卫 `frontend-design/scripts/check_content_padding.py` 的判据升级为覆盖控件内部：

- 候选容器新增 `button`、`menuitem`、`option`、`tab` 等交互控件，不再像旧版那样把交互控件整体豁免。
- 判据改为只取左右两向，阈值 4 像素。
- 新增三类语义豁免：无可见边界（无背景且无边框）的纯文字按钮与布局 div、圆形容器（头像）、自身可滚动的容器。

升级过程用阳性对照逐步校准，命中分布的变化记录在第 11 节。

## 9. 未覆盖说明

- 判据只覆盖左右两向：上下方向的 2 至 3 像素间距是标签、头像这类小控件靠行高与行内对齐居中的结果，纳入判据会把它们全部误报。
- 圆形容器豁免：圆形头像的字形受弧线约束，左右间距天然小于矩形块，贴边在视觉上被圆弧吃掉。
- 无可见边界的纯文字按钮豁免：文字贴到自身盒边是流式排版的既有结果，没有可见边界可供参照。
- 守卫依赖本地开发服务与 Python Playwright；CI 环境若未安装 Chromium，需先执行 `python -m playwright install chromium`。

## 10. 完成标准

本 Bug 以「截图中选项文字与底色块边缘拉开距离」且「全部组件页面无同类缺陷」为完成标准，逐项对照如下：

| 标准 | 判定方式 | 实际结果 |
| --- | --- | --- |
| 横向菜单选项文字不贴右边缘 | 运行时测量文字字形与按钮内边缘距离 | 距右 10 像素 |
| 浮层子菜单同样不贴边 | 同上 | 距右 53 像素 |
| 所有其他组件无同类缺陷 | 内容留白守卫扫描全部示例页 | 750 张卡全部 `PASS` |
| 守卫能真实抓到该缺陷 | 移除修复后必须转 `FAIL` | 精确报出 1 处，转 `FAIL` |
| 守卫不误报既定排版语义 | 全量扫描应无假阳性 | 校准判据后为 0 |
| 无上游漂移 | 还原度守卫剥离缝隙后逐字节相等 | `FIDELITY: PASS`（261 本地 / 139 上游） |
| 无测试污染 | 污染扫描 | `POLLUTION: PASS` |

## 11. 排查过程中修正的判据错误

| 错误 | 表现 | 修正 |
| --- | --- | --- |
| 旧版守卫整体豁免交互控件 | `MenuNode` 的选项文字贴边完全扫不到，缺陷被静默放过 | 候选容器纳入 `button` / `menuitem` / `option` / `tab` |
| 判据包含底部方向 | `Tag`（`b:3`）、`Avatar`（`b:6`）、`delta-pill`（`b:2`）等小控件被误报为缺陷 | 只判左右两向 |
| 未要求容器有可见边界 | `x-transfer-link`、`btn-text`、`rg-tools > BUTTON` 等纯文字按钮共命中 60 余处假阳性 | 无背景且无边框的容器不参与判定 |
| 未豁免圆形容器 | 头像首字母左右各 3 像素被判贴边 | 圆角达到半高即视为圆形，豁免 |
