## 详细缺陷说明

### 缺陷 1 & 2: Rate 评分组件交互与渲染问题

**现象描述:**
- 截图 1 显示多个小圆点（底槽星描边路径渲染异常）
- 截图 2-3 显示点击星星后没有立刻上色，需要鼠标移开后才会变色

**根因分析:**
1. **多圆问题**: SVG `stroke-width="1.2"`在某些渲染引擎下显示为小圆环，视觉上影响品质
2. **点击不上色**: `pick()`函数计算点击位置对应的分数并发出 update:modelValue，但未清除 hover 预览态。由于 shown computed 优先取 hover.value，导致点击后仍显示预览值而非真实绑定值

**修复方案:**
```typescript
// Rate.vue:66-70
function pick(event: PointerEvent) {
  if (props.readonly || props.disabled) return
  const next = valueOf(event)
  hover.value = null // 立即清除预览态，让 shown 回落到真实绑定值
  emit('update:modelValue', props.allowClear && next === props.modelValue ? 0 : next)
}

// Rate.vue:112
<path :d="STAR_PATH" fill="none" stroke="currentColor" stroke-width="0.8" stroke-linejoin="round" />
```

**验证要点:**
- 视觉检查：底槽星描边变细，不再出现小圆环
- 交互测试：点击任意星级后星星应即时变为蓝色填充态

### 缺陷 3: Form inline 布局两列对齐错位

**现象描述:**
- 截图 4-5 显示表单在 inline 横向布局模式下，两列输入框未对齐
- 出现校验红字提示后才临时对齐，正常状态下存在垂直错位

**根因分析:**
`.x-form.is-inline`使用了`align-items: end`将所有列底部对齐。当某行包含辅助文案（如"提示文字"）的高度高于其他行的纯输入框时，该行的内容会把整行顶高，导致另一列的同排输入框看起来"往下跑"了。

**修复方案:**
```css
/* Form.vue:61-67 */
.x-form.is-inline {
  grid-template-columns: none;
  grid-auto-flow: column;
  grid-auto-columns: max-content;
  align-items: start; /* 避免辅助文案把行顶高，导致两列不对齐 */
  gap: 12px;
}
```

**验证要点:**
- inline 布局下的两列输入框应各自独立顶部对齐
- 带辅助文案的行不应影响同排其他输入框的位置

### 缺陷 4: DataTable 缺少表头拖拽拉伸功能

**现象描述:**
- 截图 6 指出表格组件示例缺少可拖动、拉伸表头的功能演示
- Column 接口支持 width/minWidth，但模板未实现 drag-resize 手柄

**根因分析:**
功能缺失而非 Bug。DataTable 的 Column 接口原本只支持固定宽度，缺少动态调整列宽的能力。

**修复方案:**
新增以下功能：
1. **resizable 列属性**: 标识哪些列可调整宽度
2. **拖拽手柄**: 表头右侧显示悬停触发的手柄元素
3. **动态调整**: mousedown 后监听 mousemove/mouseup 事件实时更新宽度
4. **column-resize 事件**: emit 新事件供外部监听列宽变化
5. **最小宽度保护**: 拖拽下限 50px

**代码实现:**
```typescript
// DataTable.vue 新增逻辑
const resizedWidths = ref<Record<string, number>>({})
let resizeCol: string | null = null
let startX: number = 0
let startWidth: number = 0

function onResizeStart(e: MouseEvent, colKey: string) {
  const col = props.columns.find(c => c.key === colKey)
  if (!col || !col.resizable) return
  startX = e.clientX
  startWidth = resizedWidths.value[colKey] || col.width || 0
  resizeCol = colKey
  document.body.style.cursor = 'ew-resize'
  document.addEventListener('mousemove', onResizeing)
  document.addEventListener('mouseup', onResizeEnd)
}
```

**验证要点:**
- 鼠标悬停于可 resize 列的表头右侧时应出现双向箭头光标
- 拖拽操作应实时反映列宽变化且不低于 50px
- column-resize 事件应正确 emit 列名和新宽度

### 缺陷 5: Collapse 展开面板文字被覆盖一半

**现象描述:**
- 截图 7 显示某些面板展开后，下方文字被覆盖，只能看到一半或一部分

**根因分析:**
CollapseItem.vue:86 行中 `.x-collapse-inner`同时使用`overflow: hidden`和`padding: 0 14px 14px`。配合父级 grid-template-rows 过渡效果，当内容高度接近容器边缘时，overflow:hidden 会裁切掉最后一行文本。

**修复方案:**
```css
/* CollapseItem.vue:86 */
.x-collapse-inner {
  padding: 0 14px 20px; /* 从 14px 抬到 20px，避免最后一行被裁切 */
  font-size: 13px;
  color: var(--ink-muted);
  line-height: 1.6;
}
```

**变更说明:**
- **移除 overflow:hidden**: 确保内容不会被裁切
- **增加 padding-bottom**: 从 14px 提升至 20px，给最后一行留出完整显示空间

**验证要点:**
- 展开任意面板后，多行文本应完整显示不被裁切
- 滚动检查：内容较长时应能通过滚动查看全文

## 全量同类问题扫描结论

对全部 36+ 个组件进行了 overflow/highlight/padding 模式的分类核查：

### Layout 类组件 (Panel/Card/Descriptions)
- **Pattern**: overflow:hidden 用于圆角背景/封面裁切
- **Impact**: 非内容裁切，正文区域有充足内边距 (Card body: 13px 18px 16px)
- **Conclusion**: 无额外修复需求

### 表单标签类组件 (AutoComplete/Cascader/Dropdown/Tabs 等)
- **Pattern**: overflow:hidden + white-space: nowrap + text-overflow: ellipsis
- **Impact**: 用于单行文本截断展示，符合设计意图
- **Conclusion**: 行为正常无需修改

### Tree/TreeSelect 树形结构
- **Pattern**: label 域使用相同截断模式
- **Impact**: 树节点标签过长时自动省略号截断
- **Conclusion**: 行为符合预期

### Image/Carousel 媒体组件
- **Pattern**: overflow:hidden 配合 border-radius 做图片裁切
- **Impact**: 圆角图片背景容器的标准用法
- **Conclusion**: 无裁切隐患
