# Bug 主文档：任务投影跨宿主适配缺陷

> 稳定 ID：`BUG-TASK-PROJECTION-HOST-001`
> 发现日期：2026-08-23
> 状态：`root_cause_confirmed → 修复实施中`
> 关联 Skill：`task-plan-rehydration-rules`（唯一 Owner）

## 1. 结论

任务列表投影在 WorkBuddy Desktop 宿主下出现"UI 同步条件永远无法满足"的异常，由两层缺陷叠加导致：

1. **直接触发**：`ensure-start` 收到合成上下文时，代码实际读取的字段是 `trigger`（合法值 `start|continue|timeout`），本次输入缺失该字段，脚本按契约拒绝，且提示文案中的 `synthesis trigger` 被误读成不存在的字段名 `synthesis_trigger`。
2. **系统性根因**：任务投影协议围绕 Codex Desktop 的 `CODEX_THREAD_ID + update_plan` 设计，却被上层规则提升为所有宿主的执行硬闸门（`update_plan` 不可用 → `UI_SYNC_BLOCKED` → 禁止继续领域写入）。WorkBuddy 有任务列表能力但接口模型不同，当前环境也无 Codex 会话变量，因此出现"本地计划可执行、UI 同步条件永远无法满足"的错误阻断。

用户猜测"Codex 与 WorkBuddy 功能不同导致"**成立**，且这是主要系统性根因。

## 2. 症状

- 首次投影持久化被脚本契约拒绝，错误方向指向 `synthesis_trigger` 字段缺失。
- 恢复闸门发现项目状态文件中的活动投影属于其他历史会话；本环境未暴露可核验的当前会话标识（`CODEX_THREAD_ID` 未注入）。
- 按既有规则，`update_plan` 不可用即进入 `UI_SYNC_BLOCKED` 并禁止继续领域写入，导致已授权的本地实现被 UI 能力缺口阻断。

## 3. 复现环境

- 宿主：WorkBuddy Desktop（`CODEBUDDY_HOST=workbuddy-desktop`）。
- 会话变量：`CODEX_THREAD_ID` 未注入；`CODEBUDDY_MCP_CONFIG` 中未解析出唯一 `X-WorkBuddy-Session-Id`（探测结果 `absent`）。
- 调用入口：`ensure-start --input <synthesis_context.json>`，输入缺少 `trigger` 字段。

## 5. 根因分析

### 5.1 直接触发原因

`ensure-start` 走"合成上下文"分支时调用 `_normalize_context(input_value)`，`trigger` 缺失即拒绝（`task_plan_projection.py:1600`）。这是契约可用性问题：`ensure-start` 入口本身已表达"开始"语义，要求调用方重复填写 `trigger=start` 属于冗余且脆弱。

### 5.2 系统性根因

规则链把 Codex 专属能力当成跨平台必备能力：

```text
CODEX_THREAD_ID -> PROJECT_CURRENT 投影 -> update_plan（Codex Desktop 专属）
```

上层规则规定：`update_plan` 不可用 → `UI_SYNC_BLOCKED` → 禁止继续领域写入。对 WorkBuddy 而言：

- WorkBuddy 有任务列表能力（任务条目创建/更新/查询），但接口模型不是 Codex 的整份 `update_plan` 覆盖协议；
- 当前环境无 `CODEX_THREAD_ID`，也未暴露可核验的 WorkBuddy 会话 ID；
- 结果：UI 适配能力缺失被错误升级成了本地业务执行阻断。

## 6. 修复边界（已确认推荐方案）

| 层级 | 处理 |
| --- | --- |
| 投影核心层 | 保留计划事实、执行许可、可信会话隔离和原子持久化不变 |
| Codex 适配层 | 继续使用 `CODEX_THREAD_ID + update_plan` |
| WorkBuddy 适配层 | 会话解析支持 WorkBuddy 宿主元数据回退；UI 通道使用宿主任务列表工具（任务条目协议），与 Codex `update_plan` 互斥不双写 |
| 无任务 UI 宿主 | 只保留正式计划和磁盘状态，不伪造 UI 同步成功 |
| 阻断规则 | 仅持久化失败、会话归属冲突、执行状态不明才硬阻断；单纯 UI 不可用降级并继续本地执行 |
| 输入契约 | `ensure-start` 合成上下文缺 `trigger` 时默认补 `start`；直接调用 `synthesize` 保持严格必填 |
