# 组件示例边角阴影块 Bug 主文档

结论：后台四角与示例卡边缘出现的深色方块，是投影范围超出容器留白后被裁切边界硬切造成的绘制缺陷；影响：整个组件库后台的所有页面、所有示例卡片和登录页；范围：三处落点的容器留白与一条新守卫；非范围：组件造型、示例数据、上游冻结样式内容、业务页面行为；变化：新增本地样式覆盖层与示例卡留白，上游文件仍逐字节冻结；完成标准：三处落点投影零裁切、窄屏形态不变、类型检查与单元测试与构建与还原度与污染扫描全部通过；术语说明：柔影指模糊值不小于 4 像素的非内阴影，裁切边界指开启溢出裁切的容器内沿；验证状态：已用运行时全量扫描与静态守卫双向验证通过。

## 1. 结论

用户截图里的「边角阴影块」不是某个组件画坏了，而是一条统一的绘制规则缺陷：**柔影的延展范围超出了容器的留白，又被容器的裁切边界硬切成方形暗块**。

组件库里的卡片、按钮、面板都带一层范围很大的柔和投影（最宽的一层向下延展约 59 像素、向左右各约 35 像素）。这些投影所在的外壳与示例卡片只留了 8 像素到 14 像素的空白，并且开启了裁切。结果就是：投影本该平滑淡出的那部分被一刀切断，在窗口四角、卡片四边显成一块块颜色更深的方形阴影。

同类问题一共出现在三处落点，本轮全部修好：

| 落点 | 用户看到的表象 | 修复后 |
| --- | --- | --- |
| 后台外壳（整个应用的外框） | 窗口四角和四边一圈发暗的方形块 | 留白补足到投影范围之外，暗块消失 |
| 组件示例卡片内部 | 每张示例卡边缘压着一条暗影 | 卡内投影完整淡出，零裁切 |
| 登录页左侧画布 | 画布左边与底边一道硬切暗影 | 同样补足留白，暗块消失 |

## 2. 症状

- 后台任意页面：视口四角出现颜色明显深于周围的方形块，越靠边越暗。
- 示例卡片：卡片内侧边缘压着一道直线结束的暗影，而不是自然淡出。
- 登录页：左侧深色画布的左边与底边有一道被切断的阴影带。
- 组件在真实业务页面里看不出问题，只有放进示例页或整屏后台时才暴露。

## 3. 复现步骤

1. 启动组件库后台：`cd frontend-design/component-library && npm run dev`，打开 `http://localhost:5173/`。

3. 把浏览器窗口设为 1920 宽，观察视口四个角与上下左右四条边。
4. 打开任意示例页（如「通用 → 按钮与链接」），看卡片内容贴边处的阴影是否被切成直线。

稳定性：稳定复现，与数据、账号无关，属绘制规则与容器裁切不匹配。

## 5. 根因分析

投影的视觉强度按高斯分布铺展，半影宽度约为模糊值的一半，再叠加偏移与扩散。上游把这套「大柔影」设计用在外壳和卡片上，但只配了 8 像素到 14 像素的留白，并让容器参与裁切：

- 被切掉的不是看不见的部分，而是灰度仍然明显的那一段，所以切口在深色边框与浅色舞台的对比下格外显眼。
- 切口出现在容器边界，正好是四角与四边，于是呈现为边角阴影块。
- 组件在业务页面里由外层容器自带更大留白，所以问题只在整屏后台与示例页暴露。

属于设计参数与容器裁切规则不匹配，不是某个组件的实现错误，也不是示例数据问题。

## 6. 修复方案

不改上游冻结样式，改以本地覆盖层与示例卡自身样式落地：

1. 新增 `src/styles/overrides.css`：把舞台留白提到 `14px / 36px / 62px`（上、左右、下），并同步外框高度公式；登录页留白同样按投影延展取值。仅在 `min-width: 821px`（有深色外框的形态）生效，窄屏保持上游贴边行为。
2. `src/main.ts` 末尾追加一行引入覆盖层，作为仓库既有的声明式缝隙登记，缝隙之外仍与上游逐字节相等。
3. `src/views/gallery/DemoCell.vue`：示例内容区加 `padding: 26px 26px 48px`，并把高度上限同步抬高（420 改为 494），保证可视内容高度不变、不新增滚动条。
4. 新增守卫 `scripts/check_shadow_clipping.mjs`（落点定义与裁决）加 `scripts/shadow_clip_measure.mjs`（变量表、投影几何、留白读取）：从源码解析全部非内阴影层的四向延展，与三个落点的留白逐维比对，并内置阳性对照（留白清零必须逐落点四向全部报缺），防止同类缺陷回归。首版为单文件 207 行、越过仓库 200 行文件基准，按既有覆盖率守卫的口径拆为「裁决入口加测量模块」，最终 102 行与 168 行，拆分只做搬运、输出与拆分前逐项一致。

## 7. 验证结论

- 静态守卫：`SHADOW_CLIP: PASS`，阳性对照有效。
- 磁盘级变异自证：把舞台下方留白从 62 像素临时改为 10 像素，守卫立即转 `FAIL` 并点名 `.stage.bottom 需 59px 只有 10px`；按原始字节还原后校验和与改动前一致，复跑恢复 `PASS`。
- 运行时全量扫描：39 个示例页、579 个示例格，卡内投影被本体裁切 0 处、外壳被裁切 0 处、登录页 0 处；无页面级外溢。
- 二次物理口径复核：按「元素完整内含 + 阴影外溢超过其最近裁切祖先留白」重扫全部 39 页（579 格、空页 0），卡片／外壳／登录三级容器裁切仍为 0；探针早期报出的 3 处 `shell/frame` 与 3 处 `Segmented` 滑块经「最近裁切祖先」定位证实为口径错误——AppShell 示例自带内层 `.stage`（留白 14/36/62/36 已覆盖 11/35/59/35），Segmented 滑块的包含块 `.segmented` 不裁切。
- 回归控制：滚动条 A/B 对照（同浏览器同视口、唯一变量为是否加留白）显示基线本就有 25 格横向溢出与 18 格竖向溢出，加留白后为 28 与 19，净增 3 横 1 竖；未新增竖向外溢，窄屏形态行为不变。
- 工程校验：`npx vue-tsc --noEmit` 退出码 0；`npm run test:unit` 21 用例全通过；`npx vite build` 成功且覆盖层已进入产物、级联顺序位于上游之后；`POLLUTION: PASS`；`FIDELITY: PASS`。
