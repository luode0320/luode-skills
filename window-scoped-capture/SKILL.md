# 窗口级截图与窗口内受控交互

## Skill 作用与适用场景

- 需要「某个应用窗口现在长什么样」的视觉证据，且**不希望**截到桌面上其它应用；
- 需要在目标窗口里点某个坐标 / 按某个键来驱动界面，但**不希望**抢前台、移动真实光标、干扰用户正在用的其它程序；
- 目标窗口可能被其它窗口遮挡，仍需要拿到它自己的画面；
- 需要在 CI / 无人值守 / 多任务并行时重复做上述取证。

## 核心原理（为什么不能直接用全屏截图 + 全局鼠标）

三条独立红线，任何一条踩中都会污染取证结果：

| 做法 | 失败原因 |
|---|---|
| 全屏截图（`CopyFromScreen` / 系统截屏） | 会把桌面全部其它应用一起截进来；画面内容取决于当时谁在前台，不可重复 |
| 先 `SetForegroundWindow` 再截图 | 会抢用户前台焦点；用户正在输入时被抢走，属于破坏性副作用 |
| `SetCursorPos` + `mouse_event` 注入点击 | 注入到系统全局输入流，落在当时光标所在位置的真实窗口上，可能点到无关应用 |

正确做法是用两条**窗口定向**的 API：

1. **截图**用 `PrintWindow(hwnd, hdc, flags)`：把指定窗口的客户区渲染到你自己的位图，窗口被遮挡也能拿到自己的画面。`flags = 2`（`PW_CLIENTONLY`）只取客户区，不含标题栏。
2. **交互**用 `PostMessage(hwnd, ...)`：把 `WM_MOUSEMOVE` / `WM_LBUTTONDOWN` / `WM_LBUTTONUP` / `WM_KEYDOWN` / `WM_KEYUP` 直接投递到目标窗口消息队列，不经过系统输入队列，因此不动真实光标、不抢前台。

## 默认执行流程

1. 确认目标进程名或窗口句柄（`<PROCESS_NAME>`），并确认目标窗口当前可见且尺寸合理（过小的隐藏辅助窗口要过滤掉）。
2. 用窗口级截图脚本抓一张基线图，确认抓到的是**目标窗口自己的画面**（不是桌面，也不是全黑）。
3. 需要交互时，按**客户区比例坐标**投递点击（例如 `"0.5,0.51"` 表示客户区中心偏下一点），或投递按键；每次动作后重截一张，形成「动作 -> 画面变化」证据链。
4. 交互坐标只按客户区比例给，不要按屏幕绝对坐标给：窗口位置变了比例仍然有效。
5. 收口时关闭为取证启动的进程，并删除临时截图目录（除非截图本身是交付物）。

Windows 平台细节与踩坑见 [references/windows-notes.md](references/windows-notes.md)。

## 硬约束

- **脚本文件必须 ASCII-only**：Windows PowerShell 5.1 按 ANSI 读取 `.ps1`，脚本里出现 UTF-8 中文会破坏脚本**自身**的语法解析（报 `Missing closing '}'`、`string is missing the terminator` 这类与逻辑无关的怪错误）。注释和字符串都用英文。
- **默认只用窗口定向 API**：常规取证禁止 `CopyFromScreen`、禁止 `SetForegroundWindow`、禁止 `SetCursorPos` / `mouse_event`。
- **通道失效时才升级，并先证明落点**：若目标应用不响应 `PostMessage`（已知 Godot 4 导出程序如此），可升级为「前台 + 真实输入」，但必须先用 `WindowFromPoint` / `GetAncestor(GA_ROOT)` 确认点击坐标处最上层窗口就是目标窗口；不能确认用户当前无干扰时，退回应用自身的可编程通道。
- **一次只操作一个窗口**：选中窗口后先回读它的句柄、尺寸、标题，写进输出，避免「以为在 A 窗口其实在 B 窗口」。
- **先截图再动作**：每个交互动作都配一张动作后的截图，否则无法证明动作生效。
- **坐标用比例**：按客户区宽度 / 高度的比例给坐标，不要硬编码屏幕绝对像素。
- **结论必须有独立通道交叉验证**：`PrintWindow` 在 GPU 加速窗口上可能**静默返回陈旧帧**，会把「截图没变」误判成「功能失效」。凡依据截图得出「某操作无效」的结论，必须用应用日志 / 状态查询接口 / 自带调试协议独立复核。

## 权责边界与不负责事项

- 只负责「把取证范围锁定到单一窗口」的截图与输入投递机制；
- 不负责理解截图内容、不负责判断界面是否正确（那是具体业务 skill 的职责）；
- 不负责浏览器页面级自动化（DOM 查询、网络拦截、路由改写等）——浏览器有专门的 CDP / 自动化通道，本 skill 只在需要「窗口画面」或「非浏览器原生应用」时才用；
- 不负责替代应用自身提供的命令行 / API / 调试通道：如果目标程序自带可编程控制入口，优先用它，本 skill 是它的兜底。

## 执行通过 / 驳回标准

- **通过**：
  1. 截图内容确认来自目标窗口自身（遮挡下依然拿到自己的画面）；
  2. 交互全程未移动系统光标、未改变前台窗口、未影响其它应用；
  3. 坐标以客户区比例表达，动作后有对应截图证据；
  4. 脚本为 ASCII-only，可重复执行。
  5. 依据截图得出的任何「操作无效」结论，均有独立通道交叉验证。
- **驳回**：
  1. 用全屏截图或依赖前台窗口的截图方式取证；
  2. 用全局鼠标 / 键盘注入驱动界面，或抢走用户前台焦点；
  3. 直接把屏幕绝对坐标写进脚本；
  4. 脚本内含非 ASCII 文本导致自身解析失败。
  5. 单凭 `PrintWindow` 画面（可能为陈旧帧）就断言某功能失效。
