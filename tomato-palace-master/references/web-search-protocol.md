# 增强联网搜索协议 2026

> 知识截止：2026-09-11｜本文件定义本技能的**检索规范**，是所有"最新情报"可信度的保证。
> **核心立场：联网不是装饰，是防过期的免疫系统。所有判断必须带日期与信源等级。**

---

## 一、为什么要写"检索协议"

番茄平台的规则、阈值、榜单、活动**每月都在变**。典型月度变动量级：
- 福利档位与门槛（2026-09 全勤上限 2000→8000、星火门槛 500→1000、完读率考核节点提前 10 万字）；
- 征文活动（长风问道 8/6—9/30、落笔成笺 9/4 上线）；
- 赛道热度（月度标签流量榜）；
- 治理口径（AI 低质拒签数量月度公告）。

**结论：一个不联网的技能，最长保鲜期约 30 天。**

## 四、信源分级（每条结论必须标）

| 等级 | 定义 | 典型来源 | 使用方式 |
|---|---|---|---|
| **A 级【官方】** | 平台官方公告、作家专区、官方公众号 | fanqienovel.com 作家专区、番茄作家助手公告 | 直接采信，作为硬规则 |
| **B 级【实操】** | 作者社群、资深作者教程、有实测数据的经验帖 | 头条号/公众号实战文、写作社群 | 采信但标注"实操共识" |
| **C 级【分歧】** | 多来源口径不一致 | 不同教程给出不同阈值 | **并列保留，说明保守取法** |
| **D 级【推断】** | 基于公开数据的合理推断 | 由两个数据推导 | 明确标注"推断" |

**禁止**：把 D 级推断写成 A 级规则；把历史榜单说成实时数据。

## 五、时效标注规范（写进每份交付物）

**唯一允许的时间表述格式**：

| 场景 | 正确表述 | 错误表述 |
|---|---|---|
| 引用榜单 | 「截至 2026 年 8 月公开数据」 | 「目前榜单第一是……」 |
| 引用规则 | 「据 2026-09-04 平台公告」 | 「平台规定……」 |
| 引用经验 | 「据 2026 年作者社群实操共识」 | 「大家都这么做」 |
| 联网失败 | 「基于 2026-09 资源库，未联网校验」 | 省略不提 |
| 数据存疑 | 「两种口径并存，本方案取严」 | 只挑对自己有利的口径 |

## 六、冲突处理规则

当**资源库内容**与**联网最新结果**冲突时：

```
1. 以联网最新结果为准（时效优先）
2. 在交付物中标注变更点：「资源库记 X，最新核验为 Y，已在本次输出中采用 Y」
3. 把变更回流到对应 references 文件（带来源与日期）
4. 在 changelog.md 追加一条记录（只增不改）
```

当**联网来源之间**冲突时：

```
1. 按信源分级排序（官方 > 实操 > 推断）
2. 同级冲突 → 保留双方口径，施工取"更严"的一方
3. 在交付物中并列展示两组数字 + 保守取法说明
```

## 七、联网不可用时的降级方案

| 情况 | 处理 |
|---|---|
| 完全无网 | 用资源库完成，交付物开头标注「基于 2026-09 资源库，未联网校验」；提醒用户"平台规则可能已更新，建议验收后自核" |
| 部分可用 | 只跑波次三（红线）——合规优先于优化 |
| 搜索结果过时 | 显式标注"检索到的最新公开信息截至 X 月"，不用过期数据冒充实时 |
