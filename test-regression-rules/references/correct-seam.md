# 正确接缝（Correct Seam）与修复前回归测试

> 归属 owner：`test-regression-rules`。本文件吸收自 `mattpocock/skills` 的 `diagnose`（v1.0.0，2026-08-22 吸收）。负责在 Bug 修复阶段判断「回归测试该不该写、写在哪里、何时写」，避免浅接缝测试带来的虚假信心。

## 正确接缝定义

正确接缝（correct seam）是**在调用点复现真实 Bug 模式**的测试位置：

- 测试必须复现 Bug 在真实调用链上发生的模式，而不是只在单调用方里"看起来能过"。
- 接缝太浅（单调用方测试、无法复现触发链的单元测试）给出的回归测试是虚假信心：它锁不住真实场景，Bug 仍会在其他路径复发。

## 判断准则

- 该接缝是否复现了真实调用点上的 Bug 模式？
- 该测试能否在 Bug 复发时必然失败？
- 该接缝能否覆盖触发链（多个调用方 / 状态组合 / 上下游依赖），而不是只覆盖单个入口？

## 没有正确接缝本身就是发现

如果找不到正确接缝，**这本身就是定位结论的一部分**，不是"先不写测试"的借口：

1. 记录"找不到正确接缝"这一发现。
2. 指出是代码库架构阻碍了 Bug 被锁定（无良好测试接缝、调用方纠缠、隐藏耦合）。
3. 将该架构问题标记给下一阶段（修复建议 / 后续架构改进），修复完成后单独提出，不在修复前展开重构。

## 修复前回归测试流程

找到正确接缝后，按顺序执行：

1. 把最小化复现转成**失败测试**，落在正确接缝上。
2. 看它失败（确认测试真的在复现 Bug）。
3. 应用修复。
4. 看它通过。
5. **重跑原始（未最小化）场景**：用反馈回路 / 复现路径重验原 Bug 已消失——最小化场景通过不等于原始场景通过。

## 修复收尾清单

声明修复完成前必须逐项核对：

- [ ] 原始复现不再复现（重跑原始场景验证）
- [ ] 回归测试通过（或"无正确接缝"已记录并标记架构问题）
- [ ] 所有带唯一前缀标签的调试插桩已移除（`grep` 前缀确认零残留）
- [ ] 一次性原型 / 调试产物已删除（或移到明确标记的调试目录）
- [ ] 最终成立的根因假设写入 commit / PR message——让下一个调试者直接学到结论
