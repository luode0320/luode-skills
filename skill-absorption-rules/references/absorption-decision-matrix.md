# 吸收三态裁决矩阵

> 归属 owner：`skill-absorption-rules`。本文件是外部 skill 精华逐条裁决的唯一标准；不产生独立自动触发入口。

## 裁决三态

对每条外部精华（原子规则，一句话可独立判定）必须归入且仅归入一种裁决：

| 裁决 | 判定条件 | 动作 |
| --- | --- | --- |
| `保留本地` | 本地已有同义或更强规则（覆盖更全、更具体、已有真实场景验证） | 不吸收；在裁决表记录"本地更强"及对应本地文件 |
| `合并` | 本地缺失该规则，或本地版本明显更弱（只有原则没有细节） | 吸收为 reference 或补进现有 SKILL.md 正文，同步 References 引用 |
| `拒绝` | 与本地红线/工作流冲突、为吸收而吸收、一次性低频、外部专属形态（整套工作流、目录结构、`.codebuddy/specs/` 等） | 不吸收；在裁决表记录拒绝理由 |

## 判定顺序

1. 先判断是否冲突（拒绝候选）：违反本地红线（如"测试不可跳过""禁止猜测写成结论""不新增同类 skill 目录"）、或属于外部整套工作流的一部分、或外部专属目录形态 -> `拒绝`。
2. 再判断本地是否已有更强（保留候选）：本地 SKILL.md / references 里能找到同义或更具体的规则，且经过真实场景使用 -> `保留本地`。
3. 都不满足时才是 `合并`。

## 合并落点选择

- 优先落点：目标域 skill 的 `references/` 新增一个 reference（最小侵入、可追溯），或补进现有 reference 的相关小节。
- 次选落点：目标 SKILL.md 正文（仅当规则是高频核心动作、且正文已有同类条目）。
- 禁止落点：新建同类 skill 目录（除非职责边界稳定且现有 skill 明显承接不住，需与 `skill-evolution-rules` 的决策矩阵一致）。

## 反例（不得判为合并）

- 外部有"破冰寒暄"类交互（如问用户最喜欢的电影）而本地是工程化文档体系 -> `拒绝`，理由：风格不兼容、为吸收而吸收。
- 外部规则本地已有"一次一个问题"且更严格 -> `保留本地`，理由：本地更强。
- 外部"阶段问答链 / 子代理链 / 整套流程编排" -> `拒绝`，理由：本地四域 skill 已覆盖对应职责，不复制整套流程。

## 输出格式

裁决表必须可回指：

| 外部来源 | 外部精华 | 本地现状 | 裁决 | 落点 / 理由 |
| --- | --- | --- | --- | --- |

- 每条裁决都要有"本地现状"列的具体出处（文件/规则名），不能写"感觉已有"。
- `拒绝` 与 `保留本地` 都必须给理由，不能只写结论。
