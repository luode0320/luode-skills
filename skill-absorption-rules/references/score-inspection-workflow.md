# 体系 8 维评分巡检工作流（score-inspection-workflow）

> 归属 owner：`skill-absorption-rules`。是 `darwin-rubric.md` 8 维评分标准在「全仓库 skill 体系巡检」场景的执行流程，产出固定文件 `skill-8维评分报告.html`。
> 评分标准本身见 `darwin-rubric.md`（本文件不重复维度定义，只讲「怎么批量打分 + 怎么出报告 + 怎么识别短板」）。

## 触发信号

用户表达以下任一体系级评分诉求时命中本流程：

- "遍历所有 skill 打分 / 找短板 / 看看哪些 skill 是短板"
- "skill 质量检查 / 优化所有 skills / 给 skill 评分 / 8 维评分巡检"
- "吸收 skill 的打分规则，给所有 skill 打分"（用 darwin-rubric 做全量巡检）

## 前置（先做）

1. 读 `darwin-rubric.md`，确认 8 维标准、权重与计分公式。
2. 用 Glob / Bash 盘点当前 skill 总数与目录：`find . -maxdepth 2 -name SKILL.md`。

## 打分范围与四分类

- 范围：仓库内**全部含 SKILL.md 的 skill**（当前 157 个，含 `.system` 之外的所有目录）。
- 四分类（按目录名后缀判定，分类决定短板是否可迭代）：

| 分类 | 判定 | 短板处置 |
|---|---|---|
| `rules` | 目录名 `*-rules` 结尾 | 自有规则型，可迭代（短板有意义） |
| `skillhub` | 目录名 `*__skillhub` 结尾 | 第三方市场，短板**不可优化**，只能删除 / 重装 |
| `market` | 目录名 `skill_<数字>` | 市场编号安装，同上 |
| `other` | 其余（doc / pdf / write / imagegen / golang-patterns 等） | 自有工具 / 领域，可迭代 |

## 打分方式（静态 7 维 + 可选实测）

- **静态 7 维**：维度 1–7 各打 1–10 整数分；维度 8「实测表现」默认不评，统一标「未实测」。
- **总分公式**：`静态总分 = Σ(维度分 × 权重) / 10`，满分 75。
- 维度与权重（同 darwin-rubric 维度 1–7，权重合计 75）：

| # | 维度 | 权重 | 评分要点 |
|---|---|---|---|
| 1 | Frontmatter 质量 | 8 | name 规范、description 含「做什么+何时用+触发词」、≤1024 字符 |
| 2 | 工作流清晰度 | 15 | 步骤明确可执行、有序号、每步有输入/输出 |
| 3 | 边界条件覆盖 | 10 | 异常处理、fallback 路径、错误恢复 |
| 4 | 检查点设计 | 7 | 关键决策前用户确认、防止自主失控 |
| 5 | 指令具体性 | 15 | 不模糊、有具体参数/格式/示例、可直接执行 |
| 6 | 资源整合度 | 5 | references/scripts/assets 引用正确、路径可达 |
| 7 | 整体架构 | 15 | 结构层次清晰、不冗余不遗漏、与目录风格一致 |

- **独立评分（强制）**：派**并行子代理分批打分**，避免"自己改自己评"偏差。
  - 每批约 26 个，子代理用 general-purpose（需读文件 + 判断）。
  - 每个子代理 prompt 必须含：统一 7 维标准 + 权重 + 总分公式 + 该批 skill 清单（`D:\谷歌云盘\luode-skills\<名>\SKILL.md`）+ 固定输出格式。
  - 固定输出格式（每 skill 一行，半角竖线分隔 10 字段）：
    `<skill名>|<D1>|<D2>|<D3>|<D4>|<D5>|<D6>|<D7>|<静态总分>|<一句话短板或亮点>`
  - 要求子代理用 Read 读 SKILL.md 全文，用 Glob 检查 references/scripts 目录（维度 6 证据），D1–D7 必须 1–10 整数。
- **抽查实测（可选）**：对静态分最低的短板 skill 抽样跑 2–3 个真实 prompt 复核维度 8；全量实测成本过高，仅短板抽样。

## 短板识别

- 按静态总分升序取垫底 N 个（默认 Top 25）。
- **必须区分两类短板**，结论导向不同：
  - 第三方 `skillhub` / `market` 短板（缺 frontmatter / 缺触发词 / 无工作流 / 脚本断链）→ 建议**删除或重装**，不进入内部迭代。
  - 自有 `rules` / `other` 短板 → 进入 `skill-absorption-rules` 内部更新通道，按 `low-score-skill-optimization-sop.md`（低分 skill 优化 SOP：八步闭环 + 短板类型学 + 验证纪律）执行逐条迭代。
- 打分时同步算分类平均分（rules / other / skillhub / market），作为「短板集中在哪类」的判断依据。

## 报告产出（固定文件）

- **固定文件**：`<仓库根>/skill-8维评分报告.html`，覆盖更新，用 present_files 展示。
- **结构约定**：
  1. 统计卡片：总数 / 平均分 / 中位数 / 各分类平均分 / 最低分。
  2. 分类对比条形（rules / other / skillhub / market 平均分）。
  3. 短板 Top 25（分数 + 分类 + 一句短板说明）。
  4. 完整清单表：可筛选分类、可切换升/降序，每行含 7 维分数 + 总分 + 一句短板/亮点。
- **数据格式约定**：JS 数组 `const D=[["name",D1,D2,D3,D4,D5,D6,D7,"note","category"],...]`；总分由脚本按权重 `W=[8,15,10,7,15,5,15]` 现算，避免手算出错。
- 报告生成后建议用 Python 独立校验一遍总数、分类计数、平均分、最低/最高榜，与 JS 端一致。
