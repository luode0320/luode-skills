# darwin 8 维评分 Rubric（吸收自 darwin-skill）

> 归属 owner：`skill-absorption-rules`。本文件是吸收/优化后验证"改进是否真实成立"的评分标准，不产生独立自动触发入口。来源：`alchaincyf/darwin-skill`（GitHub），Rubric 结构、权重与棘轮规则直接吸收。

## 评分总览

总分 100。结构维度靠静态分析（60 分），效果维度必须实测（40 分）。**实测表现权重最高（25 分）：skill 写得再漂亮，跑出来效果不好就是零。**

| # | 维度 | 权重 | 评分标准（1-10 分打分） |
| --- | --- | --- | --- |
| 1 | Frontmatter 质量 | 8 | name 规范、description 包含做什么 + 何时用 + 触发词、≤1024 字符 |
| 2 | 工作流清晰度 | 15 | 步骤明确可执行、有序号、每步有明确输入/输出 |
| 3 | 边界条件覆盖 | 10 | 处理异常情况、有 fallback 路径、错误恢复 |
| 4 | 检查点设计 | 7 | 关键决策前有用户确认、防止自主失控 |
| 5 | 指令具体性 | 15 | 不模糊、有具体参数/格式/示例、可直接执行 |
| 6 | 资源整合度 | 5 | references/scripts/assets 引用正确、路径可达 |
| 7 | 整体架构 | 15 | 结构层次清晰、不冗余不遗漏、与项目目录风格一致 |
| 8 | 实测表现 | 25 | 用 2-3 个测试 prompt 跑一遍，输出质量是否符合 skill 宣称的能力 |

## 计分规则

- 维度 1-7：每个维度打 1-10 分，乘以权重得到该维度得分。
- 维度 8（实测表现）：跑 2-3 个真实测试 prompt，按输出质量打 1-10 分。
- 总分 = Σ(维度分 × 权重) / 10，满分 100。
- 改进后总分必须**严格高于**改进前才保留。

## 计分陷阱（强制，防再犯）

- **维度分必须 1-10 制**：任何维度得分都不得填 11/12/14 这类超界值，也不得直接填权重加权后的数；先打 1-10 分，再乘权重。
- 若算出的总分 > 100，说明存在超界维度分，必须回查修正（真实案例：首次评分误填 14 分导致总分 109，已修正为 1-10 制）。
- 打分要给出依据：每个维度 1 行理由（吸收了什么 / 本地现状 / 缺口），不写"感觉不错"。
- 评分前先明确打分人视角（独立子 agent / 间隔一轮第三方视角），写入评分记录。

## 棘轮机制（强制）

- 分数只能上升；每一轮要么改进 skill，要么干净地回滚（git revert / 恢复文件），不留局部退化。
- 回滚禁用 `git reset --hard`，使用 `git revert` 或恢复文件内容，保证历史可查。
- 单轮涨幅 < 1 分 -> 自动早停，避免凑分堆冗余；记录"该外部精华与本地位基本持平"。

## 短板优先策略

- 找加权短板最大的维度：`weighted_gap = weight × (10 − score) / 10`，避免低权重维度制造"进步幻觉"。
- 一轮只针对一个短板维度生成改进方案，不要一次改多个维度。

## 独立评分（强制）

- 评分用独立子 agent 执行，避免"自己改自己评"的偏差；下一轮换全新评委，避免锚定。
- 无法派子 agent 时，至少间隔一轮、以第三方视角重新打分，并在记录中注明评分方式。

## 人在回路（强制）

- 每个 skill 优化/吸收完成后暂停，展示 diff + 分数变化，等用户确认再进入下一个 skill 或下一轮。
- 涉及 shell 命令、git 操作、凭证、本地文件或发布流程的 skill，进入下一轮前必须审查 checkpoint 的 diff。

## 在吸收场景中的用法

- 吸收前：对目标 skill 按 8 维打分，得到基线分。
- 吸收后：同一维度标准重新打分 + 实测 prompt 验证。
- 新分 > 基线：保留吸收内容；新分 ≤ 基线：回滚并说明。
- 该评分也可用于吸收后整体 skill 体系的巡检（`优化所有skills` / `skill质量检查` 类请求）。
