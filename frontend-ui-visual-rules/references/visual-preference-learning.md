# 视觉偏好学习

> 用途：从用户的选择、反馈与反应中持续学习其个人视觉口味，沉淀为可复用的紧凑条目，让后续 UI、图形、视频、印刷等所有视觉输出自动贴合用户偏好。
> 本文件只承载「学习机制」；实际偏好条目沉淀到 `~/.workbuddy/visual-preferences.md`（用户级、跨项目长期）与项目设计文档（项目内），不写入本 skill 目录。

## 触发时机

- 视觉任务开始时：先查用户是否已沉淀偏好（`~/.workbuddy/visual-preferences.md` 与项目设计文档），有则作为风格方向的输入，避免从零猜测。
- 用户给出视觉反馈时：每次「喜欢 / 不喜欢 / 换一个 / 这个好」都是学习样本，按下方判定标准决定是否沉淀。

## 四分类记忆结构

| 分类 | 内容 | 示例 |
| --- | --- | --- |
| 总体审美 | 跨介质的整体口味 | `minimal, lots of white space` |
| 按介质 | 不同载体的差异口味 | `landing pages: hero-focused, bold CTAs` |
| 品牌项目 | 特定品牌/项目的独立风格 | `@ProductX: playful, rounded, bright` |
| 明确拒绝 | 用户明确排斥的视觉元素 | `no busy backgrounds` |

## 何时添加

**立即记（1 次明确表态）：**
- 用户明确说「我喜欢 X 风格 / 讨厌 Y」。
- 用户在 A/B 中明确选 A 并说明理由。
- 用户分享参考说「像这样」。
- 用户带具体反馈拒绝某个设计。

**确认后记（2+ 一致模式）：**
- 用户多次选择相近的审美方向。
- 用户过往作品呈现稳定模式。
- 同一风格选择被认可两次以上。

**不记：**
- 客户需求（不是用户个人口味）。
- 一次性实验。
- 用户在遵循既有品牌规范时的选择（那是规范要求，不是口味）。

## 检测维度

- **视觉风格**：极简 / 大胆 / 活泼 / 优雅 / 粗野，复杂程度，氛围，时代感。
- **颜色**：色板倾向（单色 / 鲜艳 / 柔和 / 低饱和）、偏好的具体色、明暗模式、对比度。
- **字体**：风格（无衬线 / 衬线 / 展示 / 等宽）、字重、层级处理。
- **布局**：密度、网格、留白、对齐。
- **UI**：组件形态（圆角 / 直角 / 阴影 / 扁平）、动效（克制 / 夸张 / 无）、交互模式。
- **图形**：照片 / 插画 / 图标风格、图像处理方式。
- **视频与动效**：节奏、转场、文字动画。
- **反馈模式**：什么让用户说「喜欢」，什么让用户说「不对」，用户分享的参考。

## 写入格式

- 超紧凑关键词，不用完整句子：`minimal, lots of white space`。
- 倾向性表述：用「tends toward」而非「always wants」；记录例外。
- 同义词合并：clean + minimal + simple → `minimal, clean`。
- 品味进化时更新旧条目，不累积冲突条目。
- 有价值的灵感来源可标注：`like Linear app`。

## 沉淀位置

- 用户级长期：`~/.workbuddy/visual-preferences.md`（四分类结构，跨项目生效）。
- 项目内：项目已有设计系统 / 主题文档时写入其中（见本 skill「执行结果归档要求」），不新建平行文档。
- 可回指：偏好条目必须能回指到来源反馈；来源不可考的条目不写。

## 与审美方向规则的关系

`aesthetic-direction-rules.md` 解决「这页怎么定方向」（方法论），本文件解决「用户口味是什么」（记忆）。定方向前先查偏好，两者串联使用。

## 在 frontend-design 工作流中的应用

### 第 1 步（理解需求）中的偏好查询

① 检查 `总体审美` 与 `明确拒绝` 分类，确保方向不与已有偏好冲突；
② 匹配当前媒介类型（如着陆页/移动端），加载 `按介质` 的对应偏好；
③ 若当前项目属于已记录的品牌项目，加载对应的风格约束；
④ 将偏好引用作为候选方向依据："基于你之前偏好的 X 风格，我们建议…"

### 第 2 步（选定审美方向）中的偏好应用

- 参考 `总体审美` 偏好缩小候选方向范围。
- 参考 `明确拒绝` 排除用户明确拒绝的风格。
- 当用户偏好清晰时，减少方向选项数量（从 3 个降为 1-2 个）。

### 交付后的偏好更新

- 用户确认的审美方向 → 更新 `总体审美` 或 `按介质`。
- 用户提出的修改意见 → 更新 `明确拒绝` 或反馈模式记录。
- 用户分享的参考案例 → 记录到反馈模式中。

## 反馈模式记录示例

记录以下反馈模式，帮助理解用户的设计直觉：

- `likes: Apple-style simplicity` — 喜欢简洁、精致的 Apple 风格
- `likes: Stripe's illustrations` — 喜欢 Stripe 的插画风格
- `dislikes: cluttered dashboards` — 不喜欢杂乱的仪表板
- `references: linear.app` — 用户主动引用的设计参考
