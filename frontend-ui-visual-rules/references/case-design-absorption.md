# Case Study：Design（skillhub）吸收

> 目的：记录本次「视觉偏好学习机制」吸收的全过程与关键决策，供后续吸收对照。

## 背景

外部 skill `design`（v1.0.0）是一个极简的视觉偏好自学习模板：SKILL.md 仅 33 行（四分类区块 + 自动学习规则），附 criteria.md（何时添加/何时不添加/写入格式）与 dimensions.md（检测维度）。

本地三个视觉类 skill 均无「记忆用户个人口味」能力：
- `frontend-ui-visual-rules`：规则型——教"怎么给页面定方向"。
- `frontend-design`：生成型——教"怎么做得有审美"。
- `web-design-guidelines`：在线审查型——拉取 vercel 规范逐条审查。

**模型判断**：外部 skill 的精华不是某条设计规则，而是「偏好学习元机制」（观察 → 确认 → 分类记忆 → 复用）。这类机制在本地是真空，与三个"设计能力型" skill 互补。

## 关键决策

### 1. 落点选择：复用既有先例，不新建 skill 目录

`seed-source-notes.md` 已记载 2026-03-28 吸收 ui-ux-pro-max-skill 时确定的规则："后续如继续吸收外部数据，优先补到当前 skill 内部，而不是重新造第二个前端视觉种子目录"。本次落点 `frontend-ui-visual-rules/references/visual-preference-learning.md` 直接命中既有先例。

### 2. 记忆与机制分离（本地化适配的核心）

外部模板设计是"把偏好写进 SKILL.md 区块"，但本地 skill 是 git 仓库资产（多人/多项目共享），把个人偏好写进 skill 文件会污染仓库。适配为：

- **机制**（如何观察/确认/分类/写入）→ skill 内 reference。
- **记忆**（实际偏好条目）→ `~/.workbuddy/visual-preferences.md`（用户级、跨项目）+ 项目设计文档（项目内）。

### 3. 跨介质语义保留

外部模板覆盖 UI/图形/视频/印刷。落盘时保留跨介质语义（触发时机、四分类、检测维度均不限前端），但实际触发入口在 frontend-ui-visual-rules（前端场景是偏好最常被表达的载体）。

## 棘轮与验证

- 独立子代理评分：吸收后 **87.5** vs 基线 **69.3**，涨幅 +18.2。
- 3 场景实测全通过：P1 极简偏好立即沉淀、P2 深色高对比 2+ 一致确认、P3 品牌规范不记。
- 子代理发现 1 处内部不一致（流程步骤 2 条件窄于读取规则），已在同闭环修复。

## 体积账（防臃肿证据）

| 项 | 字节 |
| --- | --- |
| 新增 visual-preference-learning.md | +3,488 |
| SKILL.md 修改（净 +2 行） | ≈ +300 |
| 删除 design__skillhub 全目录 | −7,499 |
| **体系级净变化** | **≈ −3.7KB（净减）** |

## 教训

1. **先查既有吸收先例再定落点**：`seed-source-notes.md` 一行"优先补到当前 skill 内部"直接消除了"新建 skill 目录"的选项争议。
2. **模板型外部 skill 的精华在机制不在形态**：33 行模板本身不值得复制，值得吸收的是它定义的"何时记/记什么/怎么记"判定逻辑。
3. **个人偏好 ≠ 仓库资产**：跨项目共享的 skill 仓库不适合存个人口味，记忆落用户级文件，机制留 skill——这个分离模式可推广到任何"个性化记忆"类吸收。
