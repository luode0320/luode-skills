# 11 互动叙事（分支 / 多结局 / 游戏脚本）

用户要的不是「一章接一章往下读」，而是「读者/玩家做选择，故事分叉」。本文件是这条支线的唯一入口。

> 来源：inkle/ink 的 knots/stitches 脚本结构与路径测试、klembot/twinejs 的节点表与分支爆炸控制、KoboldAI-Client 的冒险模式状态维护（三套公开方法合并去重）。归属记录见 `references/SOURCES.md`。

---

## 一、什么时候走这条支线

命中任一条即进入本文件，不再按线性长篇处理：

- 用户说「互动小说」「视觉小说」「文字冒险」「多结局」「让他选」「分支剧情」「跑团」「游戏叙事」「剧本杀」。
- 要交付的产物是节点表、选项表、变量表、状态表，而不是连续章节。
- 用户已经有正文，但要把它改成可选择的形态。

反过来，只要用户仍要「一条线读到尾」，即使题材是悬疑、言情、仙侠，也走 `03-大纲工程.md` + `04-正文技法.md`，不套本文件。

---

## 二、主干优先（先骨架，后分叉）

**先画一条能独立成立的主干**，再在主干上挂分支。一上手就铺网状结构，必然写不完——分支数量是乘法增长，不是加法。

```
主干节点 N1 → N2 → N3 → … → 终点
              ↓            ↑
        分支 A1 → A2 ──回收──┘
```

三条纪律：

1. **主干必须自己讲得通**：把所有分支删掉，主干仍是一个完整故事。做不到，说明分支在替主干承担主线功能。
2. **分支从主干上一个明确的岔口长出来**，不凭空插入。
3. **一层分支够了就回收**，不要分支再分支（除非分支本身就是卖点，且已算清总节点数）。

---

## 三、每个选择必须改变四样之一

判据（缺一即视为假选择，删掉或改写）：

| 维度 | 改变了什么 |
|---|---|
| 信息 | 玩家知道了别人不知道 / 仍不知道的事 |
| 关系 | 某两人之间的信任、亏欠、敌意发生变化 |
| 资源 | 物品、钱、时间、体力、筹码增减 |
| 结局概率 | 通往哪个结局的可达集合变了 |

**同义句不算选择。**「你要走左边还是右边」如果两边后续完全一样，就是假选择——这类选项会立刻摧毁玩家对分支的信任。

写法上，选项要体现**人物的策略**，不是三种语气：

```
差：A 我同意  /  B 我不同意  /  C 我不说话
好：A 先答应，把他稳住  /  B 当场戳穿，赌他不敢翻脸  /  C 拖到明天，先去查他说的人
```

## 四、节点表（交付物）

这是分支剧情唯一必须落盘的产物，写成 Markdown 表即可，不必上工具：

| 节点 | 标题 | 入口条件 | 本节点发生什么 | 选择 | 后果 |
|---|---|---|---|---|---|
| N1 | 雨夜到站 | 无（起始） | 主角下车，站台无人 | 等 / 走 / 打电话 | 分别进 N2 / N3 / N4 |
| N2 | 站台守夜 | 选「等」 | 遇到巡夜人 | 说实话 / 编身份 | 说实话→得线索；编身份→被记疑 |
| A1 | 巡夜人支线 | N2 选「说实话」且 信任≥1 | 巡夜人交出旧钥匙 | 收 / 拒 | 收→开 R1；拒→R1 永久关闭 |
| R1 | 回收：仓库门 | 命中 A1「收」或 N4「打电话」 | 两线汇入同一场景 | — | 进终点 |

字段纪律：

- **入口条件写可判定的形式**（「信任≥1」而不是「关系好」），否则自己都会算错。
- **后果写具体去向**（「→ N3」或「R1 永久关闭」），不写「剧情变化」。
- 回收节点单列一行，标注它汇入了哪几条线。

---

## 五、变量只记「会影响后续文本」的状态

变量表是最容易膨胀的地方。判据只有一条：**这个值会不会改变某一句话、某一个选项是否出现、或某个结局是否可达**。不会，就不建变量。

| 变量 | 类型 | 初值 | 影响点 | 谁改它 |
|---|---|---|---|---|
| 信任 | 整数 0–3 | 0 | N2 分支是否出现、结局 E2 是否可达 | N2 说实话 +1；A1 收钥匙 +1 |
| 知道真名 | 布尔 | false | N5 对白用「你」还是「<真名>」 | N4 打电话后 true |

同时写清**默认值与边界**：信任上限 3 写死，不要让它在不同路径里变成 5。

## 六、Ink 式脚本结构（要写脚本时用）

按 knot（场）+ stitch（缝）两级组织，不写「第几章第几节」：

```
=== knot_station ===          // 场：站台
= stitch_wait                  // 缝：等
巡夜人提灯走过来。
* [说实话] -> stitch_truth
* [编身份] -> stitch_lie

= stitch_truth
~ 信任 = 信任 + 1
他说：「这站三年没人下车了。」
-> knot_warehouse
```

- knot 是场景单位，stitch 是场景内的分叉单位。
- 跳转只有一个方向感：`->` 之后必须能走到底，不许悬空。
- 选项用 `*`，条件选项用 `{条件}` 包裹，条件本身要能机判。

写 Ink 草案时同时交付：脚本 + 变量表 + 路径测试清单，三件缺一不可。

## 七、路径测试（写完必须跑一遍）

纯人工走查即可，但要按清单逐项确认：

- [ ] 每个节点都可达（没有孤岛节点）。
- [ ] 每条路径都能走到某个终点，不存在死循环出口。
- [ ] 每条终点路径上，变量值不越界（信任没有变成 7）。
- [ ] 每个「永久关闭」的分支，确实有另一条路能补上它承担的信息，否则玩家会被饿死。
- [ ] 至少有一条路径能让玩家看到最核心的那场戏。
- [ ] 变量在两种冲突结局里没有互相矛盾（不能在 E1 里说钥匙丢了、E2 里说钥匙还在）。

发现孤岛或死循环，先修结构，不要靠加提示语遮盖。

## 八、跑团 / 冒险模式（连续互动，非一次性分支）

与静态分支的区别：故事在生成时还在生长，没有预写全部节点。

四条规则：

1. **开局定三样**：玩家身份、世界规则、可交互边界（能做什么、不能做什么）。边界不写清，后面每轮都要重新解释。
2. **每轮输出三件套**：场景（现在看到什么）+ 选择（2–4 个可行方向）+ 风险（每个方向的代价）。**不替玩家做决定**，不写「你决定走过去」。
3. **维护状态表**，每轮更新：物品 / 关系 / 线索 / 伤害 / 位置。这是唯一事实源，同 bible 的地位。
4. **分支回收要保留后果**：玩家之前的选择造成的损失、结下的仇、拿到的钥匙，回收时不能悄悄清零。硬重置等于宣布之前的选择无效。

状态表最小形态：

| 项 | 当前值 | 变动记录 |
|---|---|---|
| 位置 | 站台 | N1 起始 |
| 物品 | 旧钥匙、半包烟 | N2 得钥匙 |
| 关系 | 巡夜人：信任 1 | N2 说实话 |
| 线索 | 三年无人下车 | N2 |
| 伤害 | 左臂擦伤 | N3 摔下台阶 |

## 九、与主线的衔接

互动叙事不是另一个宇宙，分支产生的既成事实同样要回写 bible：

- 分支里确立的设定 → 写进 `world-bible.md`（否则后续分支会自相矛盾）。
- 分支里的死亡、失踪、关系变化 → 写进 `characters/*.md` 的「当前状态」，并按分支标注适用范围（如「结局 E2 线：已故」）。
- 分支回收 → 在 `plot-board.md` 用 `F` 编号登记，复用 C5 超期提醒。
- 时间点变化 → 写进 `timeline.md`，多结局项目按「线」分列。

多条线并存时，**每条线各自维护一套 bible 事实**，不要混在一份里——混了之后 C1–C11 会全线误报。

## 十、交付形态

| 用户要什么 | 交付什么 |
|---|---|
| 只想看结构 | 节点表 + 选择后果表（本文件第四节） |
| 要脚本 | Ink 草案 + 变量表 + 路径测试清单 |
| 要能点着玩的图文 | 节点表 + 每节点正文片段 + 回收关系图 |
| 跑团 / 连续互动 | 开局三样 + 状态表 + 每轮三件套 |

不主动推荐具体引擎或平台，用户问起再按需给对照。
