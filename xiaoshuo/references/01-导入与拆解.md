# 01 导入与拆解

两类任务的统一入口：把「别人的书」变成「自己的素材」。

- **导入**：已有正文、设定、大纲、角色资料 → 整理成可续写的标准项目。
- **拆解**：分析爆款作品的结构，提取可复用的方法论。

> 来源：story-import v4.0.0 的 4 步骨架 + MuMuAINovel `story-long-analyze` 的 6 阶段管道（后者明显更强，作为主力）。

---

## 一、导入已有项目

### 触发

用户手里已经有稿子：正文 txt/docx、零散设定、人物表、大纲片段，要求「整理」「继续写」「接着上次」。

### 执行流程

1. **盘点**：已有文件的类型、章节覆盖范围、完整性。
2. **提取**：角色、世界规则、时间线、剧情节点、未回收伏笔。
3. **建映射**：旧资料 → 标准项目结构（对应 `02a-bible-guide.md` 的 bible 四件套）。
4. **核对缺口**：生成待补材料清单，只追问会改变结果的关键缺口。

### 交付

- 资料清单与格式映射
- 人物、设定、大纲、章节索引
- 导入报告与待补材料清单

### 质量检查

- 原文与导入后项目可相互追溯
- **不自行补写缺失的关键设定**（缺就标缺）
- 章节、时间线、角色状态相互一致

### 材料不足时

先完成能确认的部分，再只追问关键缺口。不虚构用户未提供的事实。

## 二、拆解爆款作品

**核心信念：看懂别人的爆款，才能写出自己的爆款。**

### 两种模式

| 模式 | 触发 | 产物 |
|---|---|---|
| 快速拆解 | 默认；只给书名/平台 | 黄金三章逐章拆 + 整体结构 + 拆文报告 |
| 深度拆解 | 用户给文本文件路径，或说「深度/完整/系统拆解」 | 完整目录树（见下） |

### 快速拆解三阶段

1. **黄金三章**：逐章拆开篇——前 300 字钩子、第一章六步骨架、前三章是否让核心卖点完整运转一次。
2. **整体结构**：故事线分析、人物架构、节奏地图。
3. **拆文报告**：结构化输出，见下方模板。

### 深度拆解目录树

```
{小说标题}/
├── 概要.md
├── 章节/          第N章_深度拆解.md + 第N章_摘要.md
├── 角色/          {角色名}.md + 角色关系.md
├── 剧情/          {剧情标题}.md + 故事线.md + 散落情节.md
├── 设定/          世界观.md + 金手指.md
├── 拆文报告.md
└── _progress.md
```

### 六阶段管道

| 阶段 | 名称 | 输入 | 输出 | 完成标志 |
|---|---|---|---|---|
| 0 | 概要提取 | 原始文本 | 概要.md + 章节索引 | 章节结构识别完成 |
| 1 | 黄金三章 | 前 3 章原文 | 深度拆解 ×3 | 3 章拆解完成 |
| 2 | 逐章摘要 | 分块章节文本 | 章节摘要（含情节点+角色） | 全部章节处理完成 |
| 3 | 聚合分析 | 全部章节摘要 | 剧情/*.md + 故事线.md | 质量门控通过 |
| 4 | 设定+关系 | 阶段 3 合并后角色数据 | 设定/*.md + 角色/*.md | 设定与关系提取完成 |
| 5 | 汇总报告 | 全部输出 | 拆文报告.md | 报告生成完成 |

### 分块策略

| 篇幅 | 策略 |
|---|---|
| < 100 章 | 按阶段整体处理 |
| 100–500 章 | 按 5–8 章分块 |
| > 500 章 | 先按卷分组，卷内再按 5–8 章分块 |

块大小 6–8K token，章节边界对齐。每块完成后更新 `_progress.md`，支持断点恢复。

### 逐章摘要的三条纪律

1. **龙套不提取**：只提取有名字、有行动、有对话的角色。
2. **别名归类**：同一角色的不同称呼合并到主名。
3. **每章 10–15 个情节点**：太少抓不住推进，太多变成复述。

### 阶段 3 质量门控

三项指标必须过：**置信度**、**覆盖率**、**重叠率**。角色跨章节去重 + 别名归一 + 四级分级；孤立情节走 4 步兜底，不允许出现「提取了但没归入任何剧情线」的孤儿节点。

### 拆文报告模板

```markdown
# 《书名》拆文报告

## 一、基本信息
- 平台/分类/篇幅/更新状态
- 一句话故事核

## 二、黄金三章拆解
### 第 1 章
- 前 300 字钩子：（原文摘录 + 类型）
- 六步骨架：进入现场 → 出现偏差 → 明确目标 → 阻力升级 → 做出选择 → 产生后果
- 章末钩子类型：
- 身份反转/生死博弈是否命中：

### 第 2、3 章
- 承重点：
- 核心卖点第一次完整运转在哪：

## 三、整体结构
### 故事线
- 主线：
- 支线及汇入点：
### 人物架构
- 主角/对手/关键配角，各自要什么、怎么挡
### 节奏地图
- 大爽点分布（章号）
- 卷末翻什么

## 四、可复用结论
- 这本书最值得学的一点：
- 这本书不能学的地方（平台/时代/作者个人优势）：
```

## 三、拆完之后做什么

| 情况 | 下一步 |
|---|---|
| 想写自己的书 | 走 `03-大纲工程.md`，用拆解结论做卖点与节奏基线 |
| 想续写/同人 | 走 `05a-续写与同人-识别与锚定.md`，把拆解产物当 canon 源 |
| 想评估能不能拍短剧 | 走 `08-平台运营.md` 的改编评估 |
| 只是想改文笔 | 走 `06-去AI味.md` |
