# 历史小说深度一致性模板

## 为什么单列
历史小说的核心风险是「史实错置」：真实人物年代/官职/事件张冠李戴，或虚构主角与真实史事产生硬矛盾。这类问题**无法靠通用大模型稳定规避**（模型会编造看似合理但错误的史实），必须以「作者锚定 + 机器核对」解决。

## bible 字段约定（复用既有规则，不新增硬规则）
- `timeline.md`：把真实事件按年/朝代排好 → 供 **C2 时间线冲突** 核对年代。
- `world-bible.md` 的「世界规则」：把「禁止/不得」类史实约束写成可判定形式 → 供 **C4 设定违反** 核对。
- 建议新增「史实锚点」节（见 `templates/history-anchors.md`）统一登记真实人物/事件/制度，作为 C2/C4 的输入。

## 与 C4 的配合
把史实约束写成规则 Rn，正文出现违反即报 ERROR。例：
- 规则 R1：宋朝 之前 不得 出现活字印刷
- 规则 R2：诸葛亮 生于 181年、卒于 234年；正文称其参与 240年 之后战事 → 冲突

## 自查清单（软规则，需作者逐条确认）
1. 真实人物生卒/身份与锚点一致
2. 官职/称谓/器物符合朝代
3. 虚构主角不与真实史事产生史实性硬矛盾
4. 「戏说」边界明确，不把虚构当史实陈述

## 误报控制
- C2/C4 仅对 bible 中明确登记的锚点/规则生效；未登记不误报。
- 朝代年号换算（如「建隆三年」）建议作者在 timeline 统一写成公元年，避免模型换算偏差。

## 分诊触发
用户提到：历史小说 / 历史背景 / 史实 / 朝代 / 官职 / 考据 / 戏说 → 路由本模板 + `history-anchors.md`。
