# 书测套餐与断流急救手册 2026

> 知识截止：2026-09-11｜【实操】实战共识｜【分歧】多口径并列
> 本文件是「书测套餐生成器」与 Rescue 模式的底层依据。

---

## 一、书测是什么（一句话）

**书测 = 封面 + 书名 + 简介素材优化测试。** 系统同时投放多套"书名 + 封面 + 简介"组合，推送给全新一批潜在读者，7—10 天统计各组点击率，自动筛选出引流效果最好的一套，长期作为作品对外展示模板，**重新解锁推荐权重**。

**核心价值**：**正文剧情不用改，只优化流量门面，就能大幅提升点击，拉高整体数据，倒逼算法重新加大曝光。**
**数据支撑**：【实操】约 80% 首秀扑街的作品，通过规范书测能重新获得有效流量。

---

## 二、什么时候必须做书测

| 触发条件 | 说明 |
|---|---|
| 首秀流量持续低迷 | 点击率长期低于同赛道平均水平 |
| 7 天内完读率始终低于 8%，追更率低于 8% | 平台不会下架，但会停止主动推荐 |
| 验证流量低迷但单价可以 | 男频 10000:100 属正常，高于此比例都可尝试 |
| 数据好但到 45 万字 | 字数多单价高，此时书测收益更大 |

**时间建议**：
- **数据不好 → 20 万字立即书测**（平台开放书测功能的节点）；
- **数据好 → 到 45 万字再书测**；
- **20—35 万字**是多数快节奏网文的"甜点区间"。

**两轮书测节点**：
| 轮次 | 适配区间 | 重点 |
|---|---|---|
| 第一轮 | **20 万—50 万字** | 先做原书名封面测试 → 再多书名测试 → 最优书名出来后做一次新书名的封面测试 |
| 第二轮 | **100 万字以上** | 对应 100 万字流量加码前优化；微调封面、文案风格，避免中期审美疲劳 |

## 三、书测操作规范

| 项目 | 规范 |
|---|---|
| 准备材料 | **5 组不同风格的"书名 + 封面"**（可含简介变体） |
| 测试周期 | **7—10 天**（部分口径 3 天出结果） |
| 操作路径 | 后台「作品管理」→「书测申请」 |
| 结果处理 | 测试结束锁定数据最优素材，更换书名/封面 |
| 名额 | 作品 20—50 万字、100 万字**各有 1 次**测试机会 |

**三条绝对禁忌**：
1. **测试中途主动关闭 → 直接消耗本次测试名额，无法再次开启**；
2. **测试周期内不能大幅修改正文内容**，仅允许调整封面、书名、简介；
3. **首秀期不做书测**（首秀期严禁改封面/书名/简介，会被判异常降权）。

## 四、书名素材套餐生成法则（5 组怎么配）

**5 组素材的差异化原则：不是 5 个随机名字，是 5 种不同的"点击诱因"。**

| 组别 | 策略 | 命名方向 | 示例（古风宅斗） |
|---|---|---|---|
| A 组 | **热词直给型** | 直接命中平台大标签 | 《重生之嫡女当家》 |
| B 组 | **身份反差型** | 阶级/身份错位 | 《婢女她不想当皇后》 |
| C 组 | **冲突前置型** | 把最激烈的场面写进标题 | 《她把休书甩在了王爷脸上》 |
| D 组 | **悬念提问型** | 制造信息缺口 | 《退婚后，他们都跪着求我回去》 |
| E 组 | **情绪价值型** | 直接给情绪承诺 | 《这一世，我只想护住我的女儿》 |

**封面与书名的匹配规则**：
- A 组封面：人物特写，风格主流，识别度高；
- B 组封面：身份符号突出（服饰/道具对比）；
- C 组封面：动作场面，动态感强；
- D 组封面：留白 + 悬念要素（背影、背影 + 关键道具）；
- E 组封面：情绪化构图（暖色调、亲密关系）。

**高点击标签池（可嵌入书名）**：穿书 / 系统 / 重生 / 退婚 / 开局 / 我 / 她 / 重生八零 / 空间 / 系统 / 签到 / 无敌 / 从……开始 / 谁懂啊 / 我靠…… / 她死后 / 都跪了

> 【分歧】"重生之××""开局××"或长标题，可能帮助类型识别，但不能替代内容差异。**不要为了点击使用与正文不符的热门标签**（书名简介错配是低留存第 11 类死因）。

## 五、简介素材套餐（三句话结构）

| 位置 | 任务 | 句式模板 |
|---|---|---|
| 第 1 句 | 人物 + 处境 + 反常事件 | 「结婚三年，她在丈夫手机里发现了自己的死亡证明。」 |
| 第 2 句 | 核心冲突 + 代价 | 「她必须在下一次家宴前找出真相，否则她会失去女儿的抚养权。」 |
| 第 3 句 | 悬念 + 期待 | 「于是她决定，先让全家人……好好吃一顿饭。」 |

**简介四不要**：
- 不要先解释完整世界观；
- 不要只写人物履历；
- 不要堆三个以上反问；
- 不要提"新人""慢热""文笔差"。

## 六、断流急救（Rescue 模式全流程）

### 6.1 断流症状与根因速查

| 症状 | 大概率根因 | 急救优先级 |
|---|---|---|
| 首秀后流量断崖 | 断更 ≥3 天 / 首秀期改过正文封面简介 / 点击率先天不足 | 1 |
| 验证期数据暴跌 | 断更、发 <1000 字章、开了"书荒测试" | 1 |
| 一直没流量（8 万字前） | 点击率不足（书名/封面/简介） | 2 |
| 完读率持续走低 | 中段注水、主线不立、章末无钩子 | 3 |
| 追更率不足 | 更新不稳定、钩子同质化、情绪回报不足 | 3 |
| 评论恶评增多 | 人设崩、逻辑漏洞、承诺与正文不符 | 4 |

### 6.2 七天急救动作清单

```
Day 1  停止一切修改动作（首秀期/验证期尤其）
       ├─ 若断更 → 立刻恢复日更，再也不断
       ├─ 更新时段统一到 08:00—20:00 之间（避开 22:00—24:00）
       └─ 单章字数稳定在 2000—3000 字，不发 <1000 字的章

Day 2—3  复盘数据，定位病灶
       ├─ 点击率低 → 门面问题 → 排书测
       ├─ 完读率低 → 内容问题 → 跑 quality-rubric 体检
       └─ 追更低 → 节奏问题 → 跑 hook 密度扫描

Day 4—7  执行修复
       ├─ 门面问题 → 准备 5 组书名+封面素材
       ├─ 内容问题 → 从"最近 10 章"开始改（不改已发布章节结构）
       └─ 节奏问题 → 未来 10 章细纲重排，补钩子

Day 8+   启动书测（若已到 20 万字）或继续稳定输出
```

### 6.3 三条死命令（急救期间）

1. **已发布章节不做结构性大改**——修改已发布章节会导致历史数据归零、系统重新评估；
2. **验证期/首秀期不改封面书名简介**——会被判异常降权；
3. **不断更**——断更三天以上流量会断崖式下跌，断更一天即可能终止验证。

## 七、切书决策模型

**不要短期数据低迷就冲动删文。** 一本书至少连载至 30 万字走完首秀周期，再客观评判。

| 情形 | 判断 | 动作 |
|---|---|---|
| 8 万字验证期失败一次，还有 2 次机会 | **不切** | 保持日更，准备第二次评估 |
| 3 次评估机会全败 | **可考虑切** | 复盘根因（是选题错还是执行错） |
| 首秀数据垫底但结算单价正常 | **不切** | 20 万字书测翻盘 |
| 20 万字书测失败 + 单价极差 | **可切** | 用原大纲换新开篇重做 |
| 写到 50 万字数据仍差但评分 ≥8.0 | **考虑完本** | 走完本线福利（起笔扬帆/品质成就/星燃） |

**切书的隐性成本**：**频繁弃书会让账号权重持续走低，后续新书冷启动曝光量大幅缩减。**

**账户健康红线**：
- 频繁切书 → 降权；
- 抄袭 → 封书 + 追回稿费；
- 擦边 → 进小黑屋（可恢复但**失去搜索流量**）；
- 敏感内容 → 隐藏章节，严重影响推荐。

## 八、书测套餐生成输出格式（交付物模板）

```
## 书测素材套餐（5 组）

- 作品名（现用）：________
- 当前字数：____ 字  → 书测轮次：第____轮（20—50 万 / 100 万+）
- 建议测试时间窗口：____（7—10 天）
- 当前点击率水平：____（低于同赛道均值 → 建议立即书测）

| 组 | 策略类型 | 书名 | 封面方向 | 简介变体要点 |
|---|---|---|---|---|
| A | 热词直给型 | 《____》 | 人物特写 | ____ |
| B | 身份反差型 | 《____》 | 身份符号对比 | ____ |
| C | 冲突前置型 | 《____》 | 动作场面 | ____ |
| D | 悬念提问型 | 《____》 | 留白 + 悬念要素 | ____ |
| E | 情绪价值型 | 《____》 | 情绪化构图 | ____ |

**统一点评**：
- 5 组是否构成 5 种不同的点击诱因？□ 是  □ 部分重叠（需重做第__组）
- 是否有任一组使用了与正文不符的标签？□ 无  □ 有（第__组）
- 是否都保留了作品的核心承诺？□ 是

**操作提醒**：
⚠️ 测试中途关闭 = 消耗名额，不可重开
⚠️ 测试期不得大幅修改正文
⚠️ 测试结束立即锁定最优素材并更换

**测试期同步动作**：日更保持稳定（4000—6000 字），时段避开 22:00—24:00
```
