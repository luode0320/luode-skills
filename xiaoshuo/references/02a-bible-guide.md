# 世界观圣经指南（bible-guide）

bible 是**单一事实源**。所有写作与校验都从这里取数。先跑 `build_bible.py` 生成骨架，再填写。

```
python scripts/build_bible.py --project ./my-novel
# 生成 my-novel/bible/{world-bible.md, characters/, timeline.md, plot-board.md}
```

## 一、world-bible.md 字段规范

```markdown
# 世界观圣经：<书名>

## 1. 基础设定
- 类型：仙侠 / 科幻 / 都市 / 言情 / 悬疑 …
- 时代背景：
- 核心冲突：

## 2. 世界规则（确定性校验的「设定」来源）
- 规则 R1：<一句可判定规则，如「灵力耗尽者 12 时辰内无法再施法」>
- 规则 R2：<…>
> 规则要写「可机器核对」的形式（明确主体+条件+结果），别写形容词。

## 3. 力量/能力体系（如有）
- 层级：练气→筑基→金丹→…（明确每层的可观测标志）
- 禁忌：<明确禁止项>

## 4. 地理/机构
- 地名 A：定位 + 关键属性
- 机构 B：职能 + 关键人物

## 5. 结构规划（来自 planning-guide）
- 卷/章预算表（链接或内联）
```

## 二、characters/<name>.md 人物卡字段

```markdown
# 人物：<姓名（规范拼写）>
- 别名/曾用名：<无则写「无」>
- 性别/年龄：
- 外貌关键特征：<用于一致性核对，如「左手六指」「左脸疤」>
- 性格：
- 当前状态：在世 / 已故(死于第X卷) / 失踪(第X–X卷) / 流放…
- 关系网：<与谁敌/友/恋/师徒>
- 弧光：<起点→终点>
- 在场时间线：<出现卷章范围>
```

> **关键**：`姓名` 是规范拼写，consistency_audit 会据此抓名字变体；`当前状态`/`在场时间线` 供「在场性」规则核对。

## 三、timeline.md 时间线字段

```markdown
# 时间线
- T1：<绝对或相对时点> — 事件：<xxx>（出处：第X卷第Y章）
- T2：…
```
> 绝对日期用 `YYYY-MM-DD` 或 `纪元X年`；相对时间用「开篇后第N天」。供「时间线冲突」规则核对。

## 四、plot-board.md 剧情板字段

```markdown
# 剧情板
## 伏笔
- F1：<伏笔描述> — 埋于：第X卷 — 状态：待回收 / 已回收(第Y卷)
## 线头
- L1：<未结案线> — 状态：进行中 / 已收
```
> `状态` 字段供「伏笔未回收」规则核对；写作层每回收一处就改状态。

## 五、维护纪律
- 改了 manuscript 里的设定，**同步回 bible**（单向事实源）。
- 校验发现的真矛盾，先修 manuscript 再回写 bible。
- 不把 bible 当草稿本，只存「已确定事实」。

## 六、记忆分层：硬事实 / 软倾向 / 临时计划

bible 是事实源，但「什么该进 bible、什么不该进」还需要一条判据。把记忆分三层，各层用途不同：

| 层 | 内容 | 落点 | 每章前怎么用 | 每章后怎么写 |
|---|---|---|---|---|
| **硬事实** | 已发生的事、已确立的规则、人物状态与在场时段、关系标签 | `bible/` 四件套 | **必读**，本章一切以它为准 | 只补新增事实，改状态字段 |
| **软倾向** | 文风偏好、语气基调、节奏手感、读者的期待 | `PROJECT_STYLE` 类笔记 / 风格锚定卡 | 只影响**语气**，不影响事实判定 | 不写。风格每章记一遍就是废料 |
| **临时计划** | 下一章打算怎么写、想试的桥段、待验证的伏笔方案 | 章纲草稿区 | 按需读 | 只保留仍有效的；兑现或废弃后立即清理 |

三条硬纪律：

1. **每章前只读「硬事实 + 本章目标」**，不要把全部历史正文塞进上下文——长文写歪往往不是想太少，而是被无关旧文本拖走。
2. **每章后只写新事实**，不写「这一章我用了什么修辞手法」这类风格废话。风格废话会让 bible 膨胀到无法检索。
3. **定期合并**：同一事实在多处出现（人物卡、时间线、剧情板各写一遍）就收敛成一处 + 其余改指针；已废弃的临时计划删掉，不留「曾经想过」的残骸。

> 判据：一条信息如果三个月后你不会去查，它就不该进硬事实层。
