# 02 设定与一致性

长篇崩盘的根源只有一个：**设定没有单一事实源**。本文件解决这件事。

> 来源：novel-writing-assistant v1.7.2 的 bible 四件套 + C1–C11 确定性校验，是 7 个源里唯一提供**可机检**能力的一套。

---

## 一、bible 四件套（单一事实源）

所有写作与校验从这里取数。用脚本初始化骨架：

```bash
python scripts/build_bible.py --project ./my-novel
# 生成 my-novel/bible/{world-bible.md, characters/, timeline.md, plot-board.md}
```

| 文件 | 存什么 | 谁依赖它 |
|---|---|---|
| `world-bible.md` | 类型、时代、核心冲突、世界规则、力量体系、关键物品状态 | C4 设定违反、C6 境界倒退、C7 物证链、C10 系统面板 |
| `characters/*.md` | 每人一张卡：规范名、别名、当前状态、当前境界/等级、在场时间线 | C1 名字、C3 在场性、C6、C10 |
| `timeline.md` | 事件时点表 | C2 时间线冲突 |
| `plot-board.md` | 伏笔台账：埋于/回收卷/状态 | C5 伏笔未回收 |

字段规范详见 `references/02a-bible-guide.md`，这里只给三条硬要求：

1. **规则必须可机判**。写「灵力耗尽者 12 时辰内无法再施法」，不写「灵力体系很严谨」。形容词式规则脚本无法校验，等于没写。
2. **人物状态必须显式**。「已故 / 失踪 / 不在场时段」要写在卡里，否则 C3 抓不到漂移。
3. **伏笔必须登记埋点与预期回收卷**。不登记就永远不会被提醒回收。

## 二、C1–C11 一致性校验

```bash
python scripts/consistency_audit.py --bible bible/ --ms manuscript/ [--json report.json]
```

| 编号 | 规则 | 级别 | 关键误报边界 |
|---|---|---|---|
| C1 | 名字一致性（形近/音近变体） | WARN | 译名/昵称/代号需白名单 |
| C2 | 时间线冲突 | WARN | 多视角时间差、倒叙不报 |
| C3 | 在场性漂移（已故者正常出场） | **ERROR** | 回忆/幻觉/复活设定需排除 |
| C4 | 设定违反（违反世界规则） | **ERROR** | 模糊规则跳过并提示改写 |
| C5 | 伏笔未回收（超期） | WARN | 长线伏笔按设定卷数判 |
| C6 | 仙侠境界倒退 | **ERROR** | 散功/自废/兵解/重修/封印自动豁免 |
| C7 | 物证状态链（已毁物品再运转） | WARN | 修复/重铸/复制豁免；未登记则跳过 |
| C8 | 关系称谓冲突（ex 却称 spouse） | WARN | 回忆/倒叙/传闻豁免 |
| C9 | 线索状态链（已销毁线索再现） | WARN | 伪造/调包/新发现豁免 |
| C10 | 游戏系统面板（等级倒退/未学技能） | ERROR/WARN | 自废/封印/重生/转生/试炼豁免 |
| C11 | 首版 AI 味信号 | WARN | 仅信号清单，非判定 |

**判据细节与完整误报边界**见 `references/02b-consistency-rules.md`。改任何一条规则时必须同步更新那份文档，否则下次会误伤。

### 校验节奏

| 时机 | 跑什么 |
|---|---|
| 每写完 1 章 | C1–C4（快） |
| 每写完 1 卷 | 全量 C1–C11 |
| 定稿前 | 全量 + C11 清零 |

### ERROR 与 WARN 的处理差别

- **ERROR 必须修**：设定被违反、死者复活、境界倒退、等级倒退——这些读者一眼能看出来。
- **WARN 需人工确认**：可能是豁免情节，也可能是真问题。不要机械全改。

## 三、类型深度模板

不同题材的一致性维度不一样，别用一套模板套所有书：

| 题材 | 参考 | 专属模板 | 专属校验 |
|---|---|---|---|
| 仙侠 | `genres/genre-deep-xianxia.md` | `templates/cultivation-system.md` | C6 境界倒退 |
| 科幻 | `genres/genre-deep-kehuan.md` | `templates/tech-system.md` | C7 物证状态链 |
| 言情 | `genres/genre-deep-yanqing.md` | `templates/relationship-map.md` | C8 关系称谓 |
| 都市/悬疑 | `genres/genre-deep-urban-suspense.md` | `templates/clue-board.md` | C9 线索状态链 |
| 历史 | `genres/genre-deep-history.md` | `templates/history-anchors.md` | 软自查 |
| 奇幻 | `genres/genre-deep-fantasy.md` | `templates/fantasy-magic.md` | C4 + 软自查 |
| 游戏异界 | `genres/genre-deep-game.md` | `templates/game-system.md` | C10 系统面板 |

通用题材画像见 `genres/genre-profiles.md`。

## 四、伏笔台账维护

每完成一批（3 章）更新一次 `plot-board.md`：

1. 记录本批新埋的伏笔（埋于第几章、预期第几卷回收）。
2. 更新已有伏笔状态（已回收 / 待回收 / 已放弃）。
3. 检查待回收伏笔是否已超期。

**超期 20 章未回收 = 读者流失点**，必须当轮处理：要么提前回收，要么显式标记放弃。

## 五、写正文前必读的四件事

1. 本章所处时间线节点（`timeline.md`）。
2. 本章应在场 / 不在场人物（`characters/*.md`）。
3. 本章涉及的已定规则（`world-bible.md`）。
4. 本章要推进 / 回收的伏笔（`plot-board.md`）。

**这四件事没读就动笔，等于闭眼开车。**
