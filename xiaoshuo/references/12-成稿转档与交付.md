# 12 成稿转档与交付（EPUB / PDF / 样章）

正文写完不等于能交。本文件处理「已定稿 → 可交付文件」这一段：清理、转档、验收。

> 来源：Sigil（EPUB 结构校验）、pandoc（Markdown 转多格式中间层）、typst（PDF 排版）三套公开工具的通用出版流程，合并为与本技能脚本链衔接的交付清单。归属记录见 `references/SOURCES.md`。

---

## 一、什么时候走这一节

- 用户要「导出」「打包」「做成电子书」「给编辑的稿子」「印成 PDF」「样章」「宣传册」。
- 稿件要交出去（投稿、上架、自印、送审），需要一份对外体面的文件。
- 平台要求上传 docx / pdf，而手上只有一堆 md。

只需要发个 txt 或直接贴到平台后台的，不用走这一节。

---

## 二、清理：转档前必须先做（顺序不可颠倒）

转档工具会把格式问题原样放大。**先清稿，再转档**，不要指望工具兜底。

| # | 检查项 | 判据 | 修法 |
|---|---|---|---|
| 1 | 章节标题层级 | 卷用 `#`、章用 `##`、节用 `###`，全稿只有一套 | 统一后重扫，混级会让目录错乱 |
| 2 | 空行 | 段间恰好一个空行；无连续两个以上空行 | 批量规整 |
| 3 | 标点 | 全角引号「」/“”全稿统一；省略号统一 `……`；不用连续多个感叹号 | 逐类替换 |
| 4 | 专名 | 人名、地名、功法名与 `bible/` 完全一致 | 先跑 `consistency_audit.py`，C1 清零 |
| 5 | 数字与单位 | 同一概念全稿写法一致（不要一处「三丈」一处「3丈」） | 统一规则后替换 |
| 6 | 目录层级 | 章标题里不含序号冗余（## 第3章 第3章 xxx） | 去重 |
| 7 | 正文残留 | 无「（待补充）」「TODO」「[优化]」等编辑痕迹 | 搜关键词 |
| 8 | 断章 | 每章结尾是完整句；章末不留半句 | 逐章看最后一段 |
| 9 | 重复段 | 无整段重复（复制粘贴事故） | 按段落首句去重扫描 |
| 10 | 错字 | 常见易错字表过一遍 | 人工过 + 关键词替换 |

前三项和第九项可以先跑一遍现成脚本筛：

```bash
# 一致性：--bible 与 --ms 都吃目录，ERROR 必须清零
python scripts/consistency_audit.py --bible bible/ --ms manuscript/

# 稿件体检：吃文件或目录，AI 味 / 钩子 / 一致性
python scripts/tomato_audit.py manuscript/

# 活人感硬禁令：只吃单个文件（或用 - 从标准输入读），逐文件跑
for f in manuscript/*.md; do python scripts/check_prose.py "$f"; done
```

## 三、先出整合稿（本技能自带，纯标准库）

转档工具都吃单文件，先把分章稿合并：

```bash
# 合并为整合稿 + 保留分章稿 + 生成交付说明骨架与目录索引
python scripts/export_markdown.py --input ./chapters --out ./交付 --title <作品名> --split
```

产物：`<作品名>_整合稿_<YYYYMMDD>.md`（主文件）+ `分章/` + 目录索引 + 统计信息。

**这一步是转档的唯一输入**。后面的 EPUB / PDF 都从这里出发，不要拿分章目录直接喂工具。

## 四、转档路线（Markdown → 中间格式 → 目标格式）

### 4.1 电子书（EPUB）

```bash
# 1) Markdown → EPUB（pandoc 直接产出，带目录与元数据）
pandoc <作品名>_整合稿_<YYYYMMDD>.md \
  -o <作品名>.epub \
  --toc --toc-depth=2 \
  --metadata title="<书名>" \
  --metadata author="<作者名>" \
  --metadata lang=zh-CN \
  --css <样式文件>.css

# 2) 结构校验（Sigil 打开逐项核对，见第五节）
```

必要条件：

- 用了 `--toc` 就必须保证标题层级干净（第二节第 1、6 项），否则目录会串。
- 封面单独给：`--epub-cover-image=<封面>.jpg`。
- CSS 只用最基础的段落/标题/首行缩进规则，不要依赖平台字体。

### 4.2 PDF（排版稿）

```bash
# 走 typst：先 pandoc 转 typst，再由 typst 编译为 PDF
pandoc <作品名>_整合稿_<YYYYMMDD>.md -o <作品名>.typ
typst compile <作品名>.typ <作品名>.pdf
```

或直接由 pandoc 走 PDF 引擎（需要本机有 LaTeX 或 wkhtmltopdf 等引擎）：

```bash
pandoc <作品名>_整合稿_<YYYYMMDD>.md -o <作品名>.pdf --pdf-engine=<引擎>
```

中文 PDF 必须显式指定中文字体，否则整篇方块：

```
# typst 侧在模板里设
#set text(font: ("<中文字体名>", "Noto Sans CJK SC"))
```

### 4.3 样章 / 宣传册

只取前 3 章 + 简介 + 作者简介，走同一条链，另存文件名区分：

```bash
python scripts/export_markdown.py --input ./chapters/1-3 --out ./交付 --title <作品名>-样章
```

## 五、交付前检查表

### 5.1 结构

- [ ] 目录能自动生成，且层级与正文标题一致（点进去能到对应位置）
- [ ] 封面存在、比例正常、不拉伸（EPUB 封面建议 1600×2400 竖版）
- [ ] 元数据齐全：书名、作者、语言（`zh-CN`）、出版方/标识（有则填）
- [ ] 章节顺序与 `bible/plot-board.md`、`timeline.md` 一致
- [ ] 无空章、无重复章、无孤立的分隔页

### 5.2 排版

- [ ] 段落首行缩进统一（中文正文惯例两字）
- [ ] 段间留白不过大（缩进与空行二者取一，不要同时用）
- [ ] 标题不与正文同字号；章标题另起页
- [ ] 引文、书信、系统面板等特殊段落有区分样式（不要和正文一样）
- [ ] 破折号、省略号在窄屏不折行错位

### 5.3 移动端 / 阅读器实测

- [ ] 手机竖屏读 3 页：字号、行距、缩进舒服，不需要双指缩放
- [ ] 夜间模式（深底浅字）下正文可读，没有硬编码黑色文字
- [ ] 翻页/滚动到底部，最后一章完整，没有被截断
- [ ] 跳章、返回目录、进度条位置正确
- [ ] 至少在两个阅读器里各开一次（不同引擎对 CSS 支持差异很大）

### 5.4 内容终检

- [ ] 搜「（待补充」「TODO」「[优化]」「xxx」等编辑痕迹：0 命中
- [ ] 首章前 300 字仍是钩子（转档不改变文本，但排版可能把钩子推到第二屏）
- [ ] 末章结尾没有编辑器残留、没有多余分隔线
- [ ] 全稿错字复核过一遍
- [ ] 与 `bible/` 的专名一致性最后再跑一次 `consistency_audit.py`

## 六、文件命名与目录结构

交付目录建议长这样，交付时整目录打包：

```
交付/
├── <作品名>_整合稿_<YYYYMMDD>.md      # 主稿，可再编辑
├── <作品名>.epub                       # 电子书
├── <作品名>.pdf                        # 排版稿
├── <作品名>-样章.md                    # 样章（可选）
├── 分章/                               # 分章稿（可选，投稿按章上传时用）
├── 封面.jpg
└── 交付说明.md                          # 版本、字数、章节数、已知未完成项
```

命名纪律：

- 日期用 `YYYYMMDD`，不用「最终版」「最终版2」「真的最终版」。
- 作品名不做删减或缩写，与书名一致。
- 交付说明里必须写清：总字数、章数、完成度（全本/前 N 章）、已知未处理的问题。

## 七、环境依赖

| 工具 | 用途 | 缺失时 |
|---|---|---|
| `export_markdown.py` | 合并整合稿（纯标准库） | 必需，随技能自带 |
| `pandoc` | Markdown → EPUB / 中间格式 | 缺失时只能交付 Markdown 整合稿 + 转档命令清单 |
| `typst` | 排版 PDF | 缺失时可改用 pandoc 的其他 PDF 引擎；都缺失则交付 Markdown |
| `Sigil` | EPUB 结构可视化校验 | 缺失时按第五节清单人工核对文件内部结构 |

**转档工具全部是可选的。** 本技能的核心交付物始终是 Markdown 整合稿；EPUB / PDF 是加值产物。工具缺失不阻断交稿，只降级交付形态，并在交付说明里写明「未转档，附转档命令」。
