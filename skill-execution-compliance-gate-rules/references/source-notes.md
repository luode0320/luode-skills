# skill-execution-compliance-gate-rules 来源记录

## 2026-09-12

- 内部调整：`skill-execution-compliance-gate-rules`，调整诉求「在收口前增加一次以真实变更集为输入、以独立读者视角进行的交付残留自查，解决任务收口后仍能被复查找出残留新问题」。
- 触发来源：用户会话——需求 / Bug / 计划任务执行完成后再次复查，仍能发现该任务残留的新问题；用户要求分析现有 skill 流程薄弱环节，并评估是否增加收口前自动自查环节、明确其检查维度 / 触发时机 / 收口标准。用户当轮裁决「落成共享 reference」且「6 维全部为必须项」。
- 诊断结论（六处结构性薄弱环节，均有本仓库实证）：
  1. 收口链为**消费型 / 信任型**：gate 只校验下游 owner 的 PASS/FAIL 与「是否执行」，不做独立复核，能防「漏执行」但防不住「执行得不够」。
  2. 触发依赖首条 `闸门预告` 预测后正向对账，缺「收口时从真实变更集反向推导应有 gate 清单」的第二机制；预测漏一项，收口即少一个对照项。
  3. `6-review` 被制度性限定为只查风格、不判断业务正确性与需求覆盖，而仓库已不再自动触发业务审查与最终验收，导致「本次改动是否真的完成了用户要的事」在收口链上无责任方。
  4. 检查单位是「单 gate 单维度」，无「变更集 → 影响面 / 消费方」的横切扫描。
  5. `SUMMARY-GATE-PMW-002` 只查计划内显式登记项（宿主任务列表 / 投影 registry），查不到计划外残留（临时脚本、debug 代码、失效引用、未用导入）。
  6. 验证粒度停留在「验证对象本身」，缺「把本轮全部产物当作整体重读」，等于把独立复查这项工作外包给用户。
- 实证来源：`doc/6-review/2026-09-11_172500_来源映射加载纳入6-review流水线_6-review.md`（问题三：来源映射 v1→v2 升级后监督侧读取方按旧形态解析，静默降级为 P1，且监督侧测试自带旧形态夹具，缺陷对测试套件不可见）；`doc/6-review/2026-09-12_103431_行尾归一与既有测试失败修复_6-review.md`（问题二：行尾判定使用会退化的测量写法，标注「本轮自查发现并纠正」）；`PROJECT_CURRENT.md` 登记的连带失配类既有失败（夹具引用已删文档、模板注册表 `template_count` 22 与实际 21 不符、`bootstrap_agents.sh` 把 `/c/...` 喂给原生 Python 被误解析）。
- 落点：新建 `references/delivery-residue-self-check.md`（6 维契约——需求覆盖对账 / 影响面与消费方对账 / 残留物清扫 / 文档与引用一致性 / 口径一致性 / 验证有效性反审；含三档触发时机、收口标准、防退化约束、与既有 owner 的边界）；`SKILL.md` 增加承载条目、「进入后先做什么」`2.1`、默认执行流程第 2 步、阻断级判定、references 读取规则、通过 / 驳回标准；`code-change-finalization-gate-rules/SKILL.md` 增加消费条目（维度 2 / 3 / 6）、「进入后先做什么」第 9 条、阻断级、驳回标准、references 读取规则；`skill-hit-check-rules/references/deferred-gate-registry.md` 增加强制 gate 行（收口前 + 中段改码）。
- 形态裁决：**不做独立新 skill**。理由——仓库已有 5 个收口 gate，新增同构 gate 会造成层叠（`skill-split-preserve-rules` 与 `skill-audit-rules` 已警示 gate 层叠风险），且无法改变「自我声明式 PASS」的失效模式；因此落为被既有 gate 消费的横切 reference，符合仓库「单一权威 + 消费不复制」架构。
- 与 `applicability-and-gap-check.md` 的边界：后者从「已命中 skill 声明」**正向**抽取规则缺口；本文件从「磁盘真实变更集」**反向**推导残留；输入方向相反、判定对象不同，互补不重复。
- 诚实局限（已写入交付说明，非本文件承诺）：本环节**不能消灭残留，只能把「用户复查发现」前移为「agent 收口发现」**；残留绝对数量取决于任务复杂度，真实可达目标是前移发现时机。
