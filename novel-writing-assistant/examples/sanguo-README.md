# 示例：穰县醒（「建库 → 写 → 审计」最小可运行范例）

本目录是 novel-writing-assistant 的**官方可运行示例**。它完整演示了稳定写作的核心闭环：

```
建库（bible 四件套）  →  写作（manuscript）  →  审计（consistency_audit.py）  →  修订（回写 bible）
```

复制整个 `sanguo-demo/` 目录到你的项目，即可一键跑通一致性校验。

---

## 1. 目录结构

```
sanguo-demo/
├── bible/
│   ├── world-bible.md      # 世界规则（R1 火药独有 / R2 九月前抵许昌）→ C4 来源
│   ├── timeline.md         # 时间线（建安五年，无空格日期）→ C2 来源
│   ├── plot-board.md       # 伏笔 F1/F2/F3 + 线头 L1 → C5 来源
│   └── characters/
│       ├── 陈默.md          # 规范名 + 别名「陈恪」（干净字段）
│       ├── 陈实.md          # 陈默之父（独立注册，避免被误判为变体）
│       └── 荀彧.md          # 史实人物
├── manuscript/
│   └── 第一卷/
│       ├── 第1章_穰县醒.md   # 魂穿设定 + 埋 F1/F2/F3
│       ├── 第2章_智退追兵.md  # 演示 R1：火攻退敌，绝不用火药
│       └── 第3章_北望许昌.md  # 演示 R2：建安五年八月抵许昌见荀彧
├── de-ai-demo/             # 二遍去味可运行对照实例（见下 §6）
│   ├── bible/              # 最小 bible，隔离 C1–C10，报告只显示 C11
│   ├── before/第1章_首版.md  # 故意堆 AI 味的首版
│   ├── after/第1章_定稿.md   # 二遍去味后的定稿
│   └── README.md          # 命中→清零 的跑法与对照表
└── README.md
```

---

## 2. 一键审计

在技能根目录执行：

```bash
python scripts/consistency_audit.py \
  --bible examples/sanguo-demo/bible \
  --ms    examples/sanguo-demo/manuscript
```

**期望输出**：`ERROR 0 / WARN 3`
- 3 条 WARN 全部是 `C5 伏笔未回收`：F1（残页秘藏）、F2（死因未解）、F3（幕后黑手未明）——这是给作者追线的提醒，**不是逻辑错误**。
- 其余 C1（名字变体）/ C2（时间线）/ C3（在场性）/ C4（设定违反）均为 0，证明本章逻辑自洽。

要导出 JSON 报告，加 `--json report.json`。

## 3. 如何把它变成你自己的项目

1. 复制 `sanguo-demo/` 为你项目的 `my-novel/`（或直接用 `scripts/build_bible.py --project my-novel` 生成骨架后，参考本例填内容）。
2. 改 `world-bible.md`：把 R1/R2 换成你的世界规则（**必须写成「主体 + 条件 + 结果」可判定形式**，否则 C4 抓不到）。
3. 改 `timeline.md`：填你的关键时点（**日期不要加空格**：`建安五年` / `公元715年`）。
4. 改 `characters/`：每人一张卡，**`# 人物：干净姓名`**（不要带括号），别名写纯名。
5. 改 `plot-board.md`：伏笔严格写成 `— 埋于：第X卷 — 状态：待回收`。
6. 写 `manuscript/` 章节，每写完一批（建议每卷或每 10 章）跑一次审计。
7. 审计发现真矛盾 → 改 manuscript **并同步回 bible**（保持单一事实源）。

## 4. 格式红线（踩过坑后固化的硬约束）

| 位置 | 错误写法 | 正确写法 | 后果 |
|---|---|---|---|
| plot-board 伏笔 | `— 埋于：第1卷第3章 — 状态：待回收` | `— 埋于：第1卷 — 状态：待回收` | 加章号 → C5 解析失败，伏笔漏报 |
| plot-board 状态 | `状态：部分回收` | `状态：待回收` 或 `已回收` | 不在枚举 → C5 不触发 |
| timeline 日期 | `公元 715 年` | `公元715年` / `建安五年` | 空格 → C2 日期匹配失败 |
| 人物卡标题 | `# 人物：陈默（规范名）` | `# 人物：陈默` | 括号 → 规范名解析错误，C1 互标风暴 |
| 人物卡别名 | `别名/曾用名：陈恪（前世本名…）` | `别名/曾用名：陈恪` | 长串 → 别名无效，变体误报 |
| 缺人物卡 | 文中有「陈实」但无 `characters/陈实.md` | 补卡 | 无卡 → 被误判为「陈默」变体 WARN |

> 这些红线已同步固化进 `templates/` 对应模板的注释中，复制模板即可规避。

## 5. 验证示例本身（自证可跑）

本示例已通过 `consistency_audit.py` 实测：ERROR 0 / WARN 3。负向对照（往副本注入 C1/C2/C3/C4 违例）可确认审计器灵敏、0 非假阴性。

## 6. 去 AI 味二遍（首版去机械感）

若你觉得首版"有机器痕迹"（破折号滥用、仿佛/似乎搭桥、段尾强行升华、无人称感受句等），用 **C11** 信号 + `references/de-ai-flavor.md` 改写范式做二遍去味：

```bash
python scripts/consistency_audit.py --bible examples/sanguo-demo/bible --ms examples/sanguo-demo/manuscript
# 看 [C11/WARN] 行 → 章节 × 信号类型 × 次数
```

然后照 `de-ai-flavor.md` 第 2 节八类 before/after 范式逐章改写，改完重跑审计确认 C11 清零。
**优先级**：先修 C1–C10 逻辑硬伤，再处理 C11 文风信号；二遍改写后务必重跑全量审计，确保一致性未回退。

**📁 想直接看「命中 → 清零」的可运行对照？** 进 `de-ai-demo/` 目录，照其 `README.md` 跑两条命令：首版触发 7 类 C11 WARN（破折号/比喻连接词/情绪直给/说教收尾/信息交代开头/无人称句/突发转场），定稿一键清零到 WARN 0。before/after 两个文件逐句对应八类改写范式，照着改自己章节最快。
