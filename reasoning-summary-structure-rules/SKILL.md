# 推理总结结构闸门规则

只在「本轮准备输出最终总结」时使用。目标是按任务性质分档输出高密度总结，消除小节堆叠与跨节复述。

## Plan Mode 负向退出

- 当前上下文处于 `Plan Mode` 时，本 skill 必须判定为 `NOT_APPLICABLE`：不命中、不读模板、不生成总结型 `final_answer`、不参与计划出口。正式、受限和阻断计划一律由 `implementation-planning-rules` 独占。
- `Plan Mode` 下不得输出 `# 📋 本轮总结`、`summary` 或其它总结容器。

## 档位判定（强制）

先判定任务性质：

- **决策研判与建议任务**（字段是否拆分、架构选型、表设计裁定、口径确认）：走下面的「决策收敛结构」，禁止套用工程执行的多节模板。
- **工程执行任务**（代码编写、文件修改、Bug 修复、文档变更）：按 T0 / T1 / T2 分档。

### T2 完整档（命中任一硬条件）

存在真实 `blocked` / `manual_handoff`；命中 `code-change-finalization-gate-rules`；存在适合图形表达的流程、依赖、状态迁移或量化对照；跨模块 / 跨服务改动；用户明确要求完整结构或详细报告。

### T0 极简档（全部满足）

单点任务之一（单文件文字修正、简单保存、纯问答、单命令说明）；改动文件数 ≤ 1；实质动作 ≤ 1 步；无独立验证（或仅读回确认）；未命中任何 T2 硬条件；无需求理解偏差。

### T1 标准档

不满足 T0 全部条件且未命中 T2 任一硬条件时一律判 T1：普通多步任务（2–5 个实质动作），改动集中同一主题。

## 决策收敛结构

- **简单建议**：`---` + `# 📋 决策结论` + `> 建议：<拆 / 不拆 / 方案 A>` + `> 核心理由：<1 句>`，全文 ≤ 3 行，零铺垫。
- **复杂建议**：`---` + `# 📋 决策建议` + 三段「1. 待判断字段/决策点 → 2. 作用与跨成员影响 → 3. 明确建议与倾向（加粗倾向 + 1-2 句依据 + 选项 A/B）」，一屏以内，不插执行证据。
- 待裁定事项四要素闭环：裁定点与影响 + 加粗推荐建议与理由 + 选项 A/B + 未裁定时的默认最安全兜底。禁止只抛问题不给建议。
- 三反铁律细节见 `references/writing-style.md`。

## T2 固定顺序

1. 一句话结论（必须，紧接主标题的引用块）
2. 图形化总览（适用时；位于一句话结论之后、执行证据之前）
3. 执行证据（必须；1-3 条关键动作与证据，不写流水账）
4. 当前要解决的问题（必须，1-2 行；存在 ⚠️ 需求理解偏差时附一行）
5. 解决方案与问题根因（只写方案与根因，不复述执行证据）
6. 验证结果（只写验证了什么、结果、是否通过、残留风险）
7. 结果与结论（必须；只写结论行未覆盖的增量信息，1-2 句最多 3 句）
8. 后台异步任务（本轮启动异步任务时必须，位于结果与结论之后）
9. 本次改动点（有改动时）
10. 知识引用（`knowledge-flow` 的引用台账非空时必须）
11. 任务阻断收口（仅真实 `blocked` 或 `manual_handoff`，作为总结最后的最终状态区）

后续内容（条件节）：仅非阻断状态下存在原执行计划内未完成必需项，或用户明确要求后续建议时出现，插在第 8 项之后、第 9 项之前。

### T1 / T0 结构

- **T1**（主节 ≤ 4 个）：容器开场 → 一句话结论 → `## 🛠 执行证据` → `## 🔧 方案与结果`（方案 / 根因 / 结果各一句，含偏差行与待裁定闭环），之后接条件尾节。不输出图形化总览，不单列问题与验证小节。
- **T0**：容器开场（`---` + `# 📋 本轮总结`）→ 一句话结论（含验证状态）→ 条件尾节。省略执行证据、问题、方案与根因、结果结论、图形化总览。

### 通用尾部顺序（所有档位共用）

一句话结论之后依次：`🖼 生成产物`（本轮生成图片 / 视频时）→ `🔄 后台异步任务`（启动时）→ 后续内容（仅合法）→ `📦 本次改动点` → `📚 知识引用` → `⛔ 任务阻断收口`（真实阻断时永远最后）。

- 无真实阻断时按台账分流收尾：台账非空时「知识引用」放在所有内容节点的最后、「本次改动点」紧邻其前；台账为空时「本次改动点」放在最后。
- 真实阻断时改动点与知识引用（如有）必须置于其前。
- 未命中的条件尾节整节省略，不输出空表或占位行。
- 生成的媒体必须内联可渲染本体，不得只用路径或普通链接冒充已展示；宿主无渲染能力时明确写出限制。
- 知识库检索与沉淀统一由「知识引用」小节承载，不在本节写摘要行；该小节只列台账条目，不得输出笔记正文、不得摘录笔记片段。
- 具体字段、模板与正反例见 `references/conditional-sections-rules.md` 与 `references/summary-structure-template.md`。

## 发送前自检（硬闸）

发出前逐条核对，任一不满足即判定 `FAIL` 并改写后再发送：

- 是否以 `---` + `# 📋 本轮总结` 开场；是否覆盖当前档位全部必填小节且顺序未错乱；T1 主节是否 ≤ 4 个。
- 一句话结论是否承载结果 + 关键数字/文件 + 验证状态；结果区是否只写增量、不跨节复述同一事实。
- **引用台账是否非空**：非空时是否输出「知识引用」且每行能回指本轮一次成功返回的文件读/写调用；**台账为空时是否已整节省略**。
- 通过标准：台账非空时知识引用位于总结最后；驳回标准：引用台账非空却缺少「知识引用」小节，或台账为空却输出该小节或空表。
- 待裁定事项是否补齐四要素闭环；决策研判是否守住三反铁律。
- T2 图形适用性是否已判定，适用时先图后文且图内术语与证据一致。
- 启动后台异步任务时是否输出分流小节并写明任务标识、轮询节奏、结果回流渠道、等待语义与宿主任务列表映射。
- 解释性自然语言是否为简体中文（技术片段除外）。

### `SUMMARY-GATE-PMW-001`（总结闸门硬失败条件）

存在任何未决 `request_user_input` / `WAITING_DECISION`（含空答案、缺失答案或宿主隐式超时未解决）时，不得输出冻结集合内任何可见内容：`commentary`、`limited_plan`、`pending_summary`、`proposed_plan`、`final`、`summary`、`final_answer`、`task_complete`、`result_and_conclusion`。必须回到同一选择框重发循环。

收口前任务状态检查同为硬条件：宿主任务列表仍有 pending / in_progress 任务，且既未继续执行也未输出显式中断点（已完成清单 + 剩余清单 + 下一动作 + 重入入口）时，禁止输出「已完成」式总结。

通过 / 驳回标准、驳回细则与自检清单全文见 `references/acceptance-checklist.md`。

## 权责边界

- 只负责最终总结的结构与篇幅，不替代业务执行、需求澄清、Bug 分析、编码实现或测试执行。
- 不要求虚构字段；不存在的条件字段明确「本轮不适用」或按规则省略。
