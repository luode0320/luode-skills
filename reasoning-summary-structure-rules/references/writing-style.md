# 反重复铁律与文字风格约束（强制）

### 决策研判三反铁律（反铺垫、反探查流水账、反重复论证，强制）

针对字段判断、架构选型、表拆分与设计建议等场景，强制执行三反铁律，任何一条违反应判定 `FAIL` 阻断：

1. **反铺垫（零废话开场）**：
   - 严禁出现“经过深入分析”、“针对您提出的关于某某的问题”、“为了保证高可用与扩展性”等仪式性前戏；
   - 第一行直接定调：简单场景直奔“建议：拆/不拆”，复杂场景第一段直接列出“待判断字段/决策点”。
2. **反探查流水账（严禁 Proof of Work 倒苦水）**：
   - 严禁在总结中叙述排查代码、SQL查询、文件翻找的过程（如“查看了某某代码第几行发现”、“查了数据表有这几个列”、“起初考虑了方案A后来排除了”等自言自语式排查记录）；
   - 工具探索与排查过程只留在工具调用和思考中，面向用户的总结**只留系统现状、跨成员影响与确定性建议**。
3. **反重复论证（一次讲透）**：
   - 决策依据有且仅在第 3 段“明确建议与倾向”中表达一次（1-2句硬核理由点透本质，如读写热度不均、行膨胀、反序列化损耗）；
   - 严禁在第 1 段铺垫一遍原因、第 2 段解释一遍理由、第 3 段又复述一遍论据的车轱辘话。
4. **决策弹性（简单极简断言，复杂选项抉择）**：
   - 简单场景（二选一/确定性/用户要求直说）：直接极简断言（如“**建议：拆**。理由：...”），篇幅 ≤ 3 行，零模板包袱；
   - 复杂场景（多表关系/多方案）：严格执行三段式，并给出明确倾向（推荐方案加粗），同时清晰罗列方案 A/B 供用户定夺，绝不模棱两可。

### 待裁定事项处理铁律（建议、选项与默认最安全兜底闭环，强制）

无论是工程执行任务收口、周期/阶段边界、任务中断点，还是独立结论区，凡列出“需用户裁定的事 / 待决策项 / 阻断决策”，**严禁“只抛问题、不给建议”的传声筒行为**。Agent 作为具备专业判断力的工作搭档，必须体现主见（带着答案回来，而不是带着问题回来）。

每项待裁定事项必须严格落实**四要素闭环**：

1. **裁定点与影响**：一句话精准锚定决策争议点，明确为什么必须现在定夺（阻塞什么后续动作、有什么业务/技术波及）；
2. **明确建议与理由（加粗倾向）**：Agent 必须亮出鲜明判断（加粗标注，如“**建议：改为包级单例共享**”或“**建议：立即重启服务触发 AutoMigrate**”），并用 1 句话讲透硬核技术/业务依据，绝不模棱两可；
3. **选项选择（清晰 A/B 方案）**：必须提供简洁、互斥的方案选项供用户选择，并明确标注推荐项：
   - **选项 A（推荐）**：<方案描述> —— *<核心收益与操作>*
   - **选项 B（备选）**：<替代方案描述> —— *<代价与适用条件>*
   （若是操作确认类，如重建表或服务重启：`选项 A（推荐）：重启服务完成自动迁移；选项 B：手动执行 DDL 脚本`）。
4. **默认最安全兜底方案（防死锁与盲目冒进）**：必须明确声明“**若未做裁定（如直接回复‘继续’或未选选项），默认按【选项 X / 保守安全方案】推进**”，并说明其安全性保证（原则：**防限流、防击穿、防破坏性误删、改动影响最小、保持系统安全稳定**）。

用户只需直接回复“选 A”、“按推荐”或直接回复“继续”，系统都能有明确且安全的方向推进，既把决策权交给用户，又彻底避免因未裁定导致的停滞死锁或无序冒进。

### 反重复铁律

- 任何事实（文件路径、命令、数字、结论、验证状态、改动点）在总结中最多出现一次；首次出现处为权威位置（通常是一句话结论或执行证据），其余小节只引用其含义，不复述原文。
- T2 的「方案与根因」「结果与结论」不得复述一句话结论或执行证据已记录的同一事实；T1 的「方案与结果」只写增量；T0 除结论行与条件尾节外无其他复述机会。
- 例外：「知识引用」小节的登记行按台账口径重复笔记名属于登记需要，不算重复；异步小节的任务标识属于字段要求，同样豁免。
- 关键事实不得因反重复而丢失：验证状态必须出现在一句话结论或执行证据中，改动文件必须出现在一句话结论或改动点中，二者择一即可，不要求双写。

### 结论为主

- 一句话结论是信息密度主行，格式 = 结果 + 关键数字/文件 + 验证状态（如“已修复 `auth.go:42` 空指针，3 个单测通过 ✅”），不是单纯的口号句。
- 用户只读一行时，结论行就能给出核心结果；其余小节是审计证据，不是结论的展开重复。

### 文字风格（去 AI 味）

- 砍填充词与空话连接词：删除“此外”“总体而言”“值得注意的是”“显而易见”“在此基础上”等，不损失信息量。
- 用具体名词和数字替代空泛形容：“p99 从 320ms 降至 90ms”而不是“性能大幅提升”；“迁移 6 个测试文件”而不是“完善了测试体系”。
- 禁止 AI 套话：禁止排比式总结（“不仅…而且…更…”连用）、禁止小节末尾加意义升华句、禁止用感叹号堆情绪。
- 结论先行：任何小节的第一句是该小节的重点句，细节后置。
