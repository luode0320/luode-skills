# Markdown 编写规则

> 通用 Markdown 语法陷阱与可移植性规则，适用于所有需要编写 `.md` 文档的场景（需求、计划、Bug、实施计划、会话总结、交付文档等）。本文件不重复 `summary-structure-template.md` 的总结排版规则，也不重复 `artifact-storage-rules` 的图片资产路径规则。

## 空白行

- 列表、代码围栏、引用块**前必须空行**，否则很多解析器会将其视为前一段落的延续。
- 嵌套列表使用 **4 空格缩进**（CommonMark / GitHub），2 空格在严格解析器中会破坏层级。
- 纯空格行仍会断段落，编写时**清理行尾空白**。

## 链接与图片

- URL 中的括号必须用 `%28` / `%29` 转义，或使用尖括号包裹：`[text](<url with (parens)>)`。
- URL 中的空格用 `%20` 或尖括号包裹。
- 引用式链接 `[text][ref]` 必须验证 `[ref]: url` 存在，否则**静默失败**（不显示链接也不报错）。

## 代码栅栏

- 代码块内部出现三重反引号时，外层栅栏使用 **4 个以上反引号**。
- 行内反引号内包含反引号字符时，包裹层使用**双反引号**并内衬空格：`` `` `code` `` ``。
- 代码栅栏的语言提示影响语法高亮，只有纯文本才能省略语言标记。

## 表格

- 对齐冒号放在分隔行：`:---` 左对齐，`:---:` 居中，`---:` 右对齐。
- 单元格内的管道符 `|` 需用反斜杠转义：`\|`。
- 表格前**不能有空行**，某些解析器会失败。
- 空单元格至少需要一个空格，否则破坏渲染。

## 转义

- 普通文本中需要转义的字符：`\*`、`\_`、`\[`、`\]`、`\#`、`\>`、`\``、`\\`。
- 代码块和行内代码中**不需要**转义，内容按原样显示。
- `&` 符号只在可能形成 HTML 实体时需要转义为 `&amp;`；否则保持原样。

## 可移植性

- HTML 标签在 GitHub 上可用，但许多渲染器（CLI 端、纯文本端）会**剥离不渲染**。优先使用纯 Markdown 语法。
- 扩展语法（脚注 `[^1]`、任务列表 `- [x]`、emoji 简码 `:smile:`）在不同解析器间不通用——输出前确认目标解析器是否支持。
- YAML frontmatter 使用 `---` 围栏且只能放在文件开头；某些解析器会将其渲染为可见文本。
